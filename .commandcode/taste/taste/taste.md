# Taste
- Writes in Chinese and expects replies in Chinese. Confidence: 0.9
- Frames problems by contrasting current behavior with "正常人的预期" (what a normal user would expect), i.e. wants the implementation to follow the user's mental model rather than internal implementation convenience. Confidence: 0.75
- When reporting one bug in a subsystem, expects the agent to also holistically review that subsystem for other related problems ("你也整体 review 一下 X 是否还有其他问题") instead of only fixing the reported symptom. Confidence: 0.7
- Expects the agent to critically self-review its own diff before declaring work done ("自己 review 一遍 diff"), reporting a verdict, any bugs it found in its own changes (and fixing them), and explicitly flagging known limitations it deliberately left unfixed — rather than just summarizing what it changed. Confidence: 0.7
- Expects batch operations to undo/redo as a single grouped step — e.g. multi-select delete should be undone in one ⌘Z, not item-by-item. Confidence: 0.75
- Prefers surfaces to blend into their parent background rather than carrying their own outer background/border — e.g. panel headers share the content area's background, and the composer/input strip has no outer background (floating, Codex-style transparent area with only the inner rounded input card). Confidence: 0.7
- Prioritizes fixing the already-identified bugs over jumping to a bigger architectural change — explicitly defers large new strategies (e.g. "先不要到 atlas，先修复你说的各种 bug") until the cheap/known fixes are landed. Confidence: 0.7
- Measurement-driven optimization order: prefers landing low-risk fixes (e.g. release builds), then re-profiling the real workload before committing to a larger rewrite, rather than starting with the big strategy. Confidence: 0.65
- Challenges the causal premise of a proposed fix and expects it verified before implementation (e.g. "拖拽完全不应该影响缓存？只是位置变了而已？") — wants the agent to reason about whether the diagnosis actually holds, not just act on it. Confidence: 0.65
- Prefers a clear split between primary and secondary header actions: primary actions (e.g. 新建/new conversation, 历史/history) stay as separate visible icon buttons, while secondary/diagnostic actions (e.g. debug copy, terminal/CLI stream) are tucked into a single trailing "更多" (more) overflow menu. Confidence: 0.7
- Dislikes overuse of the primary/accent color in UI, calling heavy primary usage "AI 味儿太重" (looks too AI-generated); wants a restrained palette where the role/accent color is reserved for functional elements (the single primary CTA per screen, focus rings, progress/switch indicators) and decorative uses (eyebrow labels, badges, icons, tags, banners, hover borders, breadcrumbs, active tabs) fall back to neutral muted/secondary/foreground tones. Confidence: 0.85
- Prefers dark surfaces to be neutral near-black (zero chroma, e.g. `lab(... 0 0)` / #0A0A0A) rather than carrying a color cast — flagged a dark canvas as still "偏绿色" (green-tinted) and chose to zero out the chroma while keeping the same lightness. Confidence: 0.55
- Prefers to consolidate UI controls rather than keep redundant affordances for the same state — e.g. removed a panel's left/right docking toggle (replacing it with a collapse-to-small-icon entry) and also removed the Header info button since the new collapse affordance already serves as that entry. Confidence: 0.6
- Defines visual/color targets by pointing at an existing UI surface for consistency (e.g. "我要的是颜色和左侧的 agent chat 背景颜色一致") and expects the agent to find and match that exact rendered reference, rather than inventing or re-deriving a new standalone value. Confidence: 0.6
- Specifies colors by naming the design-system CSS token to use rather than describing a shade (e.g. `--background` / `bg-background` in place of an ad-hoc `bg-muted/30`), expecting the code to reference the semantic variable/token instead of a hardcoded or opacity-modified value. Confidence: 0.6
- Prefers status/error states (e.g. a "生成失败"/generation-failed indicator) to be visually subtle and low-key — calls loud treatments "太抢眼了" (too eye-catching) and asks to "降低存在感" (reduce its presence); wants failure/status affordances understated rather than highlighted. Confidence: 0.7
- Prefers card/tile geometry in grids to be square (`aspect-square`) rather than carrying arbitrary aspect ratios (e.g. "卡片尺寸直接用正方形") — except video/film thumbnails, which should use 16:9 to read as "video". Confidence: 0.6
- Expects navigation between views to be seamless (client-side) rather than triggering a full page refresh/reload — flags cases where opening a page from another entry point "刷新页面进入". Confidence: 0.55
- Expects available data to render promptly and dislikes long blank/empty loading states, especially when data is already available locally ("都是基于 local 环境拿数据，不应该这么慢"). Confidence: 0.55
- Wants long-running/pending ("生成中") states to be bounded and self-resolving rather than shown indefinitely: a stuck generation past a maximum age (e.g. 3 hours) should automatically become a failed/retryable state, and the timeout rule should be applied consistently across every status surface (grid, detail preview, canvas, streamed/SSE cache) instead of patched in one place. Confidence: 0.6
- Wants loading states to be explicit and informative rather than a bare/ambiguous spinner — asks to "把 Loading 状态提示更明确一些" (make the loading indicator clearer), e.g. naming what is being loaded and showing progress/bytes so the user knows something is happening and how far along it is. Confidence: 0.65
- Prefers progressive rendering / paint-first: render what is available immediately (shapes, cards, links, grid) and fill in the expensive/deferred parts (e.g. text once fonts arrive) rather than blocking first paint on a slow resource; is pragmatic about cost, accepting the optimization be skipped only if implementing it is genuinely expensive ("如果成本高可以先不做"). Confidence: 0.65
- Expects static/heavy assets (e.g. multi-MB fonts) to be cached in the browser so repeat visits are fast — accepts a slow first load ("第一次加载这么慢都行") but considers re-downloading every time unacceptable ("不能每次都这样"); favors explicit client-side caching (e.g. Cache Storage) over relying on HTTP cache revalidation. Confidence: 0.65
- Prefers marketing/landing pages to tell one focused core story rather than enumerating features — "先得把一个核心故事讲好，然后再来逐渐放出这些功能"; explicitly says not to pitch extensibility or a laundry list of capabilities, and wants the page cut down to the minimum sections that carry that narrative (e.g. two sections + footer). Confidence: 0.6
