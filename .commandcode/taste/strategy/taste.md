# Strategy
- 全程用中文对话；若中途切到英文会明确提醒（"记得用中文和我对话"）。Confidence: 0.95
- 判断以"正常人的预期 / 用户心智模型"为准，而不是实现上的方便。Confidence: 0.75
- UI 文案措辞较真：如「添加应用」而非「新建应用」，并要求用独立 i18n key。Confidence: 0.55
- 变更说明必须讲清"逻辑/性能到底是多少"：能量化就给 before/after 数字，不能就明说"未测量"；只报"已修复"会被退回。Confidence: 0.65
- 文档与改动说明用"人话"写，非技术读者也能看懂，讲清判断逻辑。Confidence: 0.7
- 策略/营销/GTM 文档要的是"深度思考后的精炼判断"，不要技术堆砌；策略以 Marketing 导向反推产品/网站/运营。Confidence: 0.75
- RFC 按仓库 rfc/ 规范写"完整"（状态/摘要/调研/目标/决策记录 D1…/数据模型/契约/迁移/验收/边界）并登记进 rfc/README.md；讨论出的结论就地回写现有 RFC（保持交叉引用一致），不另开新文档。Confidence: 0.6
- 讨论中的判断必须真正落进文档（口头结论要升格为决策 + 独立章节），会审计遗漏。Confidence: 0.6
- 抽象设计要用具体真实样例（如真实 script 实体）逐层走一遍，便于检验。Confidence: 0.55
- 一次性分析要沉淀为可复用产物：docs/ 下的说明文档 + 可运行脚本，方便下次继续。Confidence: 0.6
- 先修已确认的 bug / 落低成本修复，再谈大改造；优化按测量驱动（先低风险修复 → 重 profile 真实负载 → 再决定大改）。Confidence: 0.7
- 根因一次修到底：前后端/平台层一起改，不接受只做一侧 workaround，或把平台层"单独立项"推迟。Confidence: 0.65
- 严守已定范围，判定为 overdesign 的里程碑直接砍掉，并把砍掉的决定记进文档。Confidence: 0.65
- 计划/RFC 定下后直接完整实现，不中途请示；计划/设计就在正常对话里内联确认，不切 plan mode。Confidence: 0.55
- 面对开放的设计/文案/产品问题（含「要跑通这些场景还缺什么」这类全局 gap 分析），先自己思考形成报告再谈落地：诊断 + 建议 + 落地顺序 + 需拍板的未决项，方向确认前不动代码。Confidence: 0.7
- 授权 agent 自行判断严重程度并直接修严重问题；认可其小改动方案并允许顺手修小问题，不必为小事反复请示。Confidence: 0.55
- 按落地成本评估方案：把必做核心与可选改进分开，小改动不要写成大工程。Confidence: 0.6
- 验证可批量（等 agent 改完一起验）；长驻 dev service 的重启由用户自己来，agent 只诊断并把步骤交回。Confidence: 0.55
- 同仓库多会话并行时，本会话要复审合并后的工作树（确认自己的改动还在、修别人引入的问题）；不要替用户清理可能还会用到的共享/云端资源。Confidence: 0.55
- 声明完成前先自己 review 一遍 diff：给结论、报告并修掉自己引入的 bug、明确标出故意留下的限制；报一个 bug 时顺带整体 review 该子系统。Confidence: 0.8
- 要真正跑通并端到端验证自己的改动，不能以"本机跑不了"为由把真实测试丢给用户；为验证可以批准真实、计费的云端/GPU 运行。Confidence: 0.8
- 验证要系统性：用仓库既有入口（如 make check）分层（lint/单测/真实 MCP 端到端/漂移检查），每项有明确通过标准并可追溯到自动化测试。Confidence: 0.55
- 实现前先质疑并验证修复的因果前提；调质量/行为差距先排除基础前提（模型/checkpoint 是否正确）再做 A/B。Confidence: 0.65
- 修完重跑原始复现，若同样失败即说明诊断（而非仅代码）错了，要放弃旧理论重新根因；需求已明确时别再纠结重现，把正确行为当规格直接改代码。Confidence: 0.6
- 诊断/重设计必须基于真实产物（实际打开并度量那段 JSON：各段大小、条目数、字段字节构成）；非平凡缺陷先"review 现有设计 → 给重设计方案与理由"，方向达成一致前不动代码。Confidence: 0.6
- 用可观测现象定位缺陷（形成假设 → 用 file:line/日志/产物验证或推翻），不轻信用户口述的因果，也不轻信自己"明显是…"的自信判断。Confidence: 0.6
- 以实际安装/部署的运行时确认真实配置（探测容器/读已安装包），不要假设 main 分支即真相。Confidence: 0.55
- 以官方/上游效果（文档、demo）为质量基准；我们结果偏离时优先怀疑本地累积的"优化"，回退到官方默认配置。Confidence: 0.6
- 不确定的外部硬指标要 agent 自己从官方/权威来源查证并给出来源；研究外部产品要真实驱动页面（playwright / agent-browser），不靠静态内容或二手描述。Confidence: 0.55
- 用户的第一手陈述即为事实，不接受预设了用户没做过的动作的解释；回到真实日志/产物对齐说法。Confidence: 0.65
- 新功能对齐用户点名的行业标准产品（如 figma）的既有交互模型，不另造一套。Confidence: 0.6
- 新能力的设计先做外部现状/前沿调研（社区实践 + 上游最新最优方案），把结论作为证据写进 RFC，不被现有实现局限。Confidence: 0.6
- 质量/表达格式不对就改产生它的 skill prompt 模板，而不是单独修那一条结果；skill 指南要用具体前后对比（❌/✅）+ 真实示范，且一条规则在所有相关通路上都要一视同仁地强调。Confidence: 0.6
- 高频/最常见用例要标准化成 skill 里的固定 recipe（如"作品 = 容器实体 + 子实体"）。Confidence: 0.6
- 架构简洁是首要评估标准：宁可删掉冗余子系统、收敛到单一真源，也不加补偿性机制（限流/并发上限）。Confidence: 0.7
- 优先复用现成的而非自造（自造要处理大量边界 bug）；通用/可配置机制优先于硬编码特例清单。Confidence: 0.8
- 配置分层：平台级共享默认 + 各单元自己的覆盖，避免各单元漏配。Confidence: 0.6
- 不需要且有 bug 的能力整体删除（连开关、阈值常量、文档/日志字段一并清）；低价值的派生/状态字段也从读模型删掉，并同步清理所有相关面。Confidence: 0.6
- 概念重叠就删一个、留语义更准的那个，而不是写文档划边界；优先移除"自我设限"这个根因，而不是绕开它加新机制。Confidence: 0.6
- 回归/兜底实现宁可删掉并明确提示"不支持"（如无 WebGPU 就直说），不做降级路径。Confidence: 0.7
- 新 app/模块沿用成熟兄弟 app 的既有模式（设计系统、能力接线）；新实现要与既有兄弟同级、同一契约（如新 provider 满足同样的契约维度），能力缺口不能挂成后续 milestone。Confidence: 0.6
- 能力注册在平台层（capability/provider registry）且声明式去中心化（各单元自己的配置，available 时自动注册）；第三方/agent 集成自动接入（启动自动发现并注入 mcp），不要手工每用户配置。Confidence: 0.6
- Agent 工程量是硬约束：改动不能给 Agent 加步骤，要让既有调用形态直接正确、工作流更短。Confidence: 0.8
- Agent 面向的失败优先在机制层修（改服务逻辑/schema 让失败路径不可能发生），文案/文档只作补充——"机械修复比提示更可靠"。Confidence: 0.7
- Agent 工具面要自描述：tool 描述与 input schema 直接携带语义（字段用途、可选值、并发约束），不依赖只在激活后加载的 skill 文档。Confidence: 0.6
- 新增 tool/API 先问"价值密度"，泛化操作已覆盖的薄封装视为冗余；不要给 Agent 加流程阶段（如 plan→apply），把能力折进既有原语让 Agent 一次调用完成——"工具多没什么，多流程才复杂"。Confidence: 0.7
- 草稿态只用于昂贵生成的成本闸门，不泛化成通用生命周期；结构/画布操作直接以最终态创建。Confidence: 0.65
- 危险/不可逆操作（如永久删除 World）不暴露给 AI，只留人工 UI/HTTP 面；持续精简 Agent 工具面（薄读折进入口、删掉步骤/状态已不存在的 tool）。Confidence: 0.6
- 分叉/兜底逻辑留在后端单个 generate 函数里，不扩散到前端各面；调用方已明确指定模型时就照做，不再重新路由。Confidence: 0.7
- 按用途拆分模型配置（如图像"生成"vs"编辑"）但调用方接口不变，由服务按输入参数动态路由。Confidence: 0.65
- 用户手动提交的值是权威，不被配置默认值悄悄补齐/覆盖（默认值只作用于 agent/平台路由的调用）。Confidence: 0.6
- 不破坏现有 API 是硬约束，迁移成本要计入双源/兼容层；落定便宜方案前先算一遍完整架构的成本，把"多买到什么 vs 多出什么风险"讲清楚。不沿用上游 `(default)` 决定我们的默认，默认要有意选择并跨服务/前端一致。Confidence: 0.55
- 产品面按"用户需求层"组织（做什么、给谁），不按底层能力；新功能做成可扩展模块（每个 item 一个自包含文件 + 单一 index 聚合，可选覆盖宿主默认渲染）。Confidence: 0.55
- 文档/偏好清单要精炼去冗：宁可激进合并同类项成一条高层结论、按主题分组，也不要保留全部细粒度条目；重复与断句残缺的条目直接删掉，不迁就现状。Confidence: 0.6
- 用户确认/花钱这类门槛（如视频确认）是刻意留给人操作的设计，不该交给 AI 代做，也不该被当成待补的能力缺口提出来。Confidence: 0.7
- 报"缺什么"之前先在代码/能力注册表里核实该能力是否真的不存在（如 music 能力 atlas/wavespeed 本就有），把已有能力误报为缺口会被直接纠正。Confidence: 0.65
- 不为已被现有对象覆盖的场景另造抽象：作品 work 就够承载一条内容，无需引入 series/栏目/episode 这类新概念；跨场景共享的概念（如资产 assetId 各处共用）按"本就全局共享"理解，不另建专用集合。Confidence: 0.6
- 判断产品真正缺什么时，倾向把缺口落在提示词/skill 引导层（教 AI workflow 与各种工具怎么用），而不是靠新增平台能力补。Confidence: 0.55
- 跨场景共用的概念/纪律直接放进平台核心 skill 层（单一真源、可版本化），场景侧只写自己的差异（意图/走哪条链/产物）——最终提示词 = 共享前言 + 场景差异，不把共享纪律复制进每一段提示词。Confidence: 0.7
- 平台字段（GitHub About / topics 等）的文案常要"给文本我手动替换"，而不是让 agent 直接改文件：直接交可复制的成稿，并按用途附不同长度（含被截断的短版）与中英版本备选。Confidence: 0.55
- 平台的核心宗旨/使命（"为什么需要作品/栏目/账号/IP"这类根因）要放进最顶层的 agent core 引导、且置于规则之前，让 AI 先理解"为什么"再遵循规则；文档分层：宗旨（为什么）→ 复用优先（怎么复用）→ 技能路由（用哪些能力）→ 场景提示词（这次做什么）。Confidence: 0.6
- 内容/账号策略偏"系列化 IP"：固定角色/世界观 + 固定选题域 + 可复制的每集结构，参考已被验证的爆款账号形态，而不是追单条爆款。Confidence: 0.6
- 用户给的参考案例（既有爆款/样例）是"机制样本"而非"选题清单"：要抽象出可迁移的机制（如 非常规讲述者 × 高价值领域 × 能无限生成选题的世界规则 × 清晰变现），再用它去占还没被占的格子；直接把用户的例子搬成方案＝照抄题材，会被退回重做。Confidence: 0.75
- 市场推进按地区排序、先做国内场景（抖音/小红书/视频号），海外另起一篇。Confidence: 0.5
- 愿意给出本人账号/cookie 或允许有头登录，以换取平台一手研究数据（研究渠道可直接用其登录态）。Confidence: 0.5
- 抽象 RFC 之后要接着推进到"具体可启动"的层面（具体栏目/账号方向、组合与上线顺序），不停留在抽象人群描述。Confidence: 0.55
- 为 AI 设计的「记忆（memory）」是一等持久层：读工具每次自动内联返回（AI 无需额外单独读一次），Agent 在用户给出反馈 / 纠正 / 偏好时**主动**写入记忆，避免用户下次重复交代。Confidence: 0.6
- AI 可写的自由文本（如记忆）要提供细粒度编辑模式（末尾追加 / 替换某行 / 整体重写）并设尺寸预算：让最省的编辑达成目标，超预算时引导 AI 自行压缩（去重、合并、删过时），而非允许超限硬塞。Confidence: 0.55
