# RFC: 视频 GTM 用户聚焦 —— 专注「IP 账号的媒体平台系列内容」

- 状态：提议
- 作者：Recut
- 日期：2026-10-10
- 决策范围：唯一聚焦场景（IP 账号系列内容）与定位表达、场景画像与痛点、两类 IP 的推进顺序、获客楔子、能力闸门、首批 5 案例选题、三条内容线、90 天验证计划、度量口径、明确不打的场景
- 关联：`rfc/2026-08-16-marketing-content-plan.md`、`rfc/2026-10-03-world-case-genre-selection.md`、`README.md`、各 App 落地页（audio-studio / timeline-editor / recut-clone / recut-reference / recut-motion-graphic / World）

## 1. 背景与结论（TL;DR）

Higgsfield 最值得学的不是它做了哪些 AI 视频功能，而是它**把复杂生成能力包装成用户一眼就懂、马上想试的具体结果**，并把「单次效果」和「持续生产」分成两层：**用病毒式视觉效果获客，用可重复的商业工作流变现**。

Recut 不应在早期直接对标 Higgsfield 做「面向所有人的 AI 视频生成平台」。更值得做的是：**先选择一种需要持续生产视频的创作者或小团队，把某类视频的制作过程变成可重复运行的自动化工作流。**

结论——**不做「面向所有人的 AI 视频生成平台」，只把一件事做到最好：运营一个 IP 账号、在媒体平台持续产出系列内容。**

- **场景（唯一聚焦）**：**IP 账号的媒体平台系列内容**——一个人/小团队运营一个有角色、世界观或固定人设的账号（=IP），在抖音/视频号/B站/小红书/YouTube/TikTok 等平台**持续更新系列内容**。
- **贯穿一切的线**：**把一个可积累的角色/世界/格式，变成可重复更新的系列内容**——即「一个世界观，无限条视频」。这也是它与「随手做一条视频」的根本区别。
- **两类 IP（同一场景的两段，不是两个场景）**：
  - **真人/口播型 IP**：有素材、靠人设与栏目一致性取胜。低生成风险、今天可交付，用来跑通「持续出系列」的循环。
  - **虚拟/AI 原生 IP**：无素材、全生成、跨集一致。高上限、强差异化、World 展示，是品牌与注意力来源。
- **楔子（获客）**：**「丢进一条参考视频，复刻成你自己的版本」**——门槛最低、demo 最强、天然导向系列。

一句话：**只服务「做 IP 账号的人」，先跑通「持续出系列」的循环，再用全生成虚拟 IP 拉高上限。**

## 2. Higgsfield 拆解（可迁移参考）

### 2.1 五类用户场景与其价值

把它的产品布局拆成用户愿意付费的**具体任务**，共五类；它们分属两种驱动：

| 场景 | 用户 | 想要的结果 | 关键卖点 | 驱动 |
|---|---|---|---|---|
| 电商与品牌广告 | 电商品牌/独立站/效果营销/代理商 | 不找模特不拍摄就能持续做可测试的商品广告 | 「我的商品能快速变成广告」 | 持续生产 |
| 社交爆款与视觉特效 | TikTok/Reels/Shorts 创作者、个人 | 做出惊艳、易分享、让人问「怎么做的」的视频 | 先看到效果，再点击复刻——**产品本身就是营销内容** | 单次效果 |
| AI 网红与虚拟人物 | 虚拟 IP/数字人/AI 模特运营者 | 不依赖真人也能持续产出人物内容，同一角色反复出现 | 「建立一个可持续运营的虚拟创作者」 | 持续生产 |
| AI 短片与电影级 | AI 视频创作者/独立导演/短片工作室 | 一个人/小团队做出原本需要大团队的视觉表达 | 更高视觉上限 + 更强导演控制 + 更低门槛 | 单次效果 |
| 自动化内容与无脸频道 | YouTube 知识/科普/资讯/批量多号 | 给一个主题就能得到含脚本/配音/动画/字幕/音乐的完整视频 | 「从主题到成片，而非自己串联五六个工具」 | 持续生产 |

**关键区分**：产品布局覆盖的场景 ≠ 公司增长最依赖的场景。官网只证明它在展示什么，不能推断各线的收入/留存/获客成本。所以要问的不是「哪个最热」，而是**每个场景为什么容易卖、容易展示、容易形成持续使用**。

**价值公式**：电商广告＝更低单条成本 × 更多测试；视觉特效＝惊艳效果 × 低门槛复刻；AI 网红＝角色资产 × 持续产出；AI 电影＝创意表现力 × 专业控制力；自动化频道＝每条人工投入下降 × 更新频率提升。

**两种驱动**：**单次效果驱动**（视觉特效、电影感镜头）靠惊艳作品吸引用户、传播潜力大，但可能生成一次就走；**持续生产驱动**（电商广告、虚拟人物、无脸频道）靠重复业务任务带来持续需求，更适合建稳定工作流。Higgsfield 同时覆盖两类，**Recut 不必一开始就同时覆盖**。

### 2.2 它把能力包装成任务的四层

1. **用一个明确结果代替技术介绍**：`Drop a product link. Get a video ad.` / `Turn your idea into a cinematic scene.`——不要求用户先懂扩散模型、镜头参数、工作流编排。**Recut 首页第一句该说用户能得到什么，而不是 Recut 由什么技术组成。**
2. **把抽象能力变成可点击的模板**：Marketing Studio 强调 1500+ 模板、六个类别，先选模板再给素材，不必从空白提示词开始。区别：空白输入框要求用户先理解工具；模板让用户先理解自己要做什么；真实案例让用户先相信结果可实现；一键复刻让用户从观看者变成使用者。**Recut 的无限画布/创作世界是底层工作方式，不应要求新用户先理解实体关系图才知道能帮他做什么。**
3. **让一个案例同时承担展示、教学与获客**：每个教程都是一个完整获客路径——看到感兴趣成片 → 知道它怎么做出来 → 用自己的素材复刻 → 继续做自己的作品。**Recut 的每个营销案例应同时具备：成片、制作过程、可复用创作资产、用户自己的下一步操作。**
4. **从单条视频升级为持续生产系统**：把商品链接、品牌、角色、模板、模型、生成任务放进统一流程，UGC/Faceless Content Factory 进一步封装成多步工作流。升级路径天然：第一次「我想生成一条」→ 第二次「用相同商品/角色再生成一条」→ 后续「持续更新、测试版本、形成稳定生产流程」。**这正是 Recut 的 Agent 与创作世界能建立差异化的地方。但模板化生成 ≠ 完整自动运营系统**——Recut 若要打「自动化」，必须用案例证明它能处理选题、素材复用、脚本、镜头组织、配音、字幕、成片输出，而非只把生成调用串起来。

### 2.3 横向对比：不同产品以什么用户任务为入口

| 产品 | 市场入口（用户任务） | 适合参考 | 不宜照搬 |
|---|---|---|---|
| Higgsfield | 用视觉效果与可复刻模板获客 | 案例展示、特效预设、教程、从单条到商业工作流的升级 | 同时服务所有创作者的宽泛定位 |
| Creatify | 围绕「商品广告」这一具体任务 | 商品网址输入、广告生成、批量创意与电商案例 | 若 Recut 没有商品广告核心工作流，别靠换广告模板竞争 |
| OpusClip | 把「长视频→短视频」压缩成一句话 | 清晰的输入输出、前后对比、可量化的省时价值 | Recut 若主打原创生产，核心定位不应变成纯切片工具 |
| InVideo | 从创意/脚本到完整视频 | 完整成片（而非单镜头）的价值表达、围绕主题/脚本/配音/素材的流程 | 泛化的「一句话生成任何视频」难以说明为何必须选 Recut |

**抽象规律：更容易被理解与传播的 AI 视频产品，不是从「我有多少模型」开始，而是从「我替你省掉哪一种完整工作」开始。**（上表为产品定位/工作流对比，非营收/份额排名。）

### 2.4 Recut 的对应定位

| Higgsfield | Recut 对应位 |
|---|---|
| 一次出片快、要量 | 真时间线、可迭代、结果可审阅修改撤销 |
| 云端、按量计费 | 本地优先、开源、不按条计费、可自部署 |
| Soul ID 局部一致性 | World：角色/风格/场景/规则沉淀，一个世界观无限条视频 |
| 聚合模型拼控制层 | 参考理解（recut-reference）+ 克隆重建（recut-clone）拼「读懂并重建」 |
| 生成端大词 | 「生成之后」：字幕/去口癖/B-roll/封面/多轨剪辑 |

## 3. 决策框架：用五个维度选人群

不只比市场规模，同时看：**需求强度**（是否经常要做）、**展示效果**（能否一条视频讲清价值）、**自动化空间**（多少重复步骤可交给 Agent）、**差异化空间**（能否发挥创作世界/资产关系/工作流优势）、**获客可行性**（能否低成本找到用户并持续产案例）。

| 用户方向 | 需求频率 | 案例传播性 | 自动化空间 | Recut 差异化 |
|---|---|---|---|---|
| 电商商品广告 | 高 | 高 | 高 | 中 |
| AI 视觉特效创作者 | 中 | 极高 | 中 | 低至中 |
| AI 短片 / 电影 | 中 | 极高 | 中 | 中 |
| 无脸知识 / 资讯频道 | 高 | 高 | 极高 | 高 |
| 固定角色的系列短视频 | 高 | 高 | 极高 | 极高 |

（分数为战略评估，非市场调查数据。最后一行——**固定角色系列短视频**——是本 RFC 重点验证的细分方向，不代表它已被证明比电商广告市场更大。）

## 4. 目标模型：只做「IP 账号的媒体平台系列内容」

### 4.1 场景定义

**运营一个 IP 账号、在媒体平台持续产出系列内容的人/小团队。**

四要素（缺一不可）：
- **IP**：账号有稳定的角色 / 世界观 / 固定人设与栏目格式——可积累的资产，也是与「随手做一条」的根本区别。
- **账号**：以「经营一个账号」为目的（涨粉、变现、品牌），不是一次性项目。
- **系列**：持续更新、成季成集，集与集之间要保持一致。
- **媒体平台**：内容发在抖音/视频号/B站/小红书/YouTube/TikTok 等，天然要面对画幅、时长、多语言、切片分发。

一句话复述 Recut 在这个场景里的承诺：**给定你的 IP（世界），帮你稳定、低成本地持续产出与之一致的下一集。**

### 4.2 用户画像与痛点

| 维度 | 内容 |
|---|---|
| 是谁 | 个人/小团队 IP 账号运营者、IP 工作室、想用 AI 起一个 IP 号的创作者 |
| 已有 | 明确的 IP（角色/人设/世界观/格式）、选题来源、发布平台 |
| 缺什么 | 一致性（跨集不掉链子）、更新频率、单位成本、跨平台派生 |
| 痛点 | 每集都要重新组织角色/视觉/脚本、难一致；出片慢成本高、频率上不去；多平台/多语言重复劳动 |
| 成功的样子 | 「这个 IP 我一直在更新，越做越省，一致性还在」 |

### 4.3 两类 IP，共用一套 World/Agent

| 类型 | 驱动 | 交付形态 | 风险 | 角色 |
|---|---|---|---|---|
| **真人/口播型 IP** | 素材驱动 | 人设/栏目场景 + 素材 → 系列切片 + 字幕 + B-roll + 封面 | 低（有素材，加工确定） | 跑通「持续出系列」的循环 |
| **虚拟/AI 原生 IP** | 生成驱动 | 世界/角色 → 全生成系列（跨集一致） | 高（依赖模型可靠性，竞品拥挤） | 品牌、注意力、World 差异化 |

**关键**：它们不是两个场景，是同一场景（IP 账号系列内容）的两段。两者都把「角色/世界/格式」当资产积累、都要求跨集一致——这正是 Recut 的 World 与 Higgsfield Soul ID（只做人物一致性）拉开差距的地方。

### 4.4 楔子（获客）——保留「复刻爆款」

| 维度 | 说明 |
|---|---|
| 是什么 | 丢进一条参考视频，读懂它的钩子/故事/分镜/节奏/字幕/声音/视觉语言，重建成你自己的版本 |
| 为什么是它 | 门槛最低、好奇驱动、demo 极强、可截图可传播；**天然导向系列**（复刻一条 → 建立自己的 IP → 系列化） |
| 承接 | recut-reference + recut-clone + timeline-editor + audio-studio |
| 关键洞察 | Higgsfield 的**拉量靠单次效果（VFX 病毒内容），不是持续生产**；持续生产的 demo 天然不够 viral。所以获客楔子必须是「单次效果型」，而复刻是最能接住 Recut 能力的单次效果 |

### 4.5 入门 IP 类型（待拍板）

同一场景下，第一验证走哪类 IP：

- **真人/口播型 IP 先行**（推荐）：低风险、今天可交付，能干净验证「用户愿不愿把持续出系列交给 Recut」；缺点是差异化偏弱。
- **虚拟/AI 原生 IP 先行**：最亮、最差异化、最贴 World；但**必须过能力闸门**，否则旗舰案例会露怯。

推荐：以「IP 账号系列内容」为唯一对外身份，第一验证挑**已有素材、靠一致性取胜的 IP 号**跑通循环，同时用少量全生成虚拟 IP 案例做「结果展示」。

### 4.6 能力闸门（前置条件）

在 Recut 通过内部**「从 IP 世界 + 选题到可发布成片」的可靠性门槛**之前，对外**不承诺全自动**，只展示诚实的人机协作。对外话术必须与真实交付能力对齐——这是虚拟/AI 原生 IP 案例能不能站住的前提。

## 5. 首批 5 个案例选题（全部围绕「IP 账号系列内容」）

| # | 选题 | 类型 | 承接 App / 能力 | 演示要点（hook） | 形态 | 优先级 |
|---|---|---|---|---|---|---|
| 1 | **复刻一条爆款，起一个 IP 号** | 楔子 | recut-reference + recut-clone + timeline-editor + audio-studio | 同一条参考、换成我的角色/品牌/语言，直接变成第一集 | 对比 + 工作流 | P0 |

## 6. 营销系统：三条内容线

| 内容线 | 负责 | 选题示例 | 核心要求 |
|---|---|---|---|
| **结果展示** | 吸引注意力 | 一个 AI 新闻主题 → 完整短视频；同一角色连演五条；一段文字 → 脚本/配音/画面/字幕全成片 | 前几秒就展示最终效果，**不要先介绍软件** |
| **制作过程** | 建立产品认知 | 主题→脚本→画面→成片；为什么同一角色能跨视频一致；AI 如何复用素材而非重生成 | 展示 Recut 具体替用户完成了哪些步，哪些仍需人工判断 |
| **可复用创作资产** | 让用户开始使用 | 一个可复用的技术解说世界；含角色/场景/视觉规范的动画世界；可继续修改的系列制作流程 | 案例不能是看完就结束的视频，而应成为用户开始创作的起点 |

- **内容线 1 的「结果」= 复刻 + 系列成片两类**，不只放「主题→解说」。
- **内容线 3 是 Recut 独有、最该重仓**：Higgsfield 的 1500 个模板 ≠ 可积累的世界；这是唯一能把「抽卡工具」与「经营世界」区分开的内容线，也最该承接 World。
- **增长循环**：案例吸引用户 → 复刻案例 → 创建自己的世界 → 持续制作视频。
- 三线对应获客/理解/激活；每篇产 zh+en（对齐 marketing-content-plan §4）。
- **一手实测是差异化**：自测截图/基准表/真实工作流，压过大媒体新闻稿式内容。

## 7. 90 天验证计划

**第 1–2 周 · 验证定位**：只选一个主要内容类型，做三条有说服力的案例。建议先确定固定画面风格、长度、配音、字幕、输出标准。观察：用户能否几秒内理解价值？是否愿意用自己的主题试做？

**第 3–6 周 · 验证激活**：围绕一个用户任务做 10–20 个不同案例，每个采用统一结构（最终视频 + 制作过程 + 复用资产 + 用户下一步）。在目标创作者社交平台发布，邀小批真实用户用自己主题试做，记录他们在哪一步失败或放弃。

**第 7–12 周 · 验证留存**：让用户从「做一条」转向「持续做一个系列」——复用角色/视觉/素材/工作流，观察是否回来做第二、三条。若只有生成一次的兴趣、不愿继续用，应**重新审视细分场景的真实需求，而非增加更多模型**。

## 8. 度量

| 指标 | 要回答的问题 |
|---|---|
| 案例内容带来的访问与注册 | 场景是否能吸引目标用户？ |
| 首次成功导出率 | 用户能否得到想要的结果？ |
| 从开始到成片的时间 | Recut 是否真的减少了制作负担？ |
| 7 天内再次制作的比例 | 是否存在持续需求？ |
| 每条成片的人工干预与成本 | 自动化是否能规模化？ |

**不用播放量/点赞决定方向**：某个视觉特效容易获得大量观看，但不一定带来持续使用；反过来，一个不那么炫酷的工作流，可能更容易吸引真正有需求的创作者。北极星是「用户把一个持续更新的系列建立在 Recut 上」。

## 9. 定位表达

- **品牌层（长期，不变）**：`From idea to viral video, automatically.` / 从灵感到爆款视频，AI 全自动完成。有吸引力，但几乎任何 AI 视频产品都能这样承诺，不足以独立承担早期获客。
- **市场入口层（早期，具体）**：**`Turn one idea into a series of videos.` / 从一个主题，持续制作一个系列。**（用 AI Agent 组织脚本、角色、视觉素材和剪辑流程，不必每次从零开始。）
  - 优点：① 直接描述用户结果，不需先理解无限画布或实体关系图；② 把 Recut 与单纯生成器区分开——重点不只是生成画面，而是组织持续生产所需的素材与流程；③ 给创作世界留空间：用户可能先只想做一条，随后才发现角色/场景/工作流可以积累。

## 10. 边界与未决

- **非目标**：不早期对标做「面向所有人的 AI 视频生成平台」；不正面硬刚「文生视频」大词；不与 Higgsfield 拼出片速度与量；不做付费投放/外链采购。
- **未决 A**：A 腿与 B 腿谁先正式对外主打——本 RFC 主张先用 B 腿结果展示获客、用 A 腿验证留存；若生成可靠性很快达标，可提前主推 B 腿全自动。
- **未决 B**：本地优先/开源对 2-5 人小团队是卖点还是门槛（自部署成本）——先以个人创作者验证，再定是否含团队。
- **未决 C**：B 腿旗舰案例走「国风志怪单元剧」（见 `2026-10-03-world-case-genre-selection.md`）还是更轻的 faceless 人格号——先做后者降低解释成本，前者作为 P1 纵深。
- **风险**：B 腿演示依赖生成可靠性，未过能力闸门（§4.4）前不得承诺全自动；「主题→全生成」赛道竞品拥挤，需以 World/一致性/本地优先做差异化而非模板数量。
