# RFC: 视频 GTM —— 面向「持续更新的系列创作者」的营销目标设计

- 状态：提议
- 作者：Recut
- 日期：2026-10-10
- 决策范围：目标人群从「IP 账号」放宽为「持续更新的系列短视频创作者」；三类账号（科技/AI 资讯、原创 IP、知识科普）的角色与推进顺序；营销主线（对外承诺、核心 demo、证据）；由营销倒推的产品 / 官网 / 运营调整；开源优势的使用边界；系列留存度量口径；明确不打的场景
- 关联：`rfc/2026-10-10-video-gtm-user-focus.md`（前身，本 RFC 放宽其人群边界）、`rfc/2026-08-16-marketing-content-plan.md`、`rfc/2026-08-28-world-onboarding.md`、`README.md`

## 1. 判断（TL;DR）

把人群收窄到「IP 账号」是错的——**IP 太窄**。它把「可复用资产」等同于「角色 / 世界观」，于是把大量同样在持续更新、每条都要重新组织脚本 / 画面 / 配音 / 剪辑的创作者排除在外。AI 资讯号、科普号往往没有虚构角色，但他们有**固定的栏目格式、视觉模板和素材库**，复用价值一样高。

放宽后的判断：

> **我们真正要服务的人，不是「做一条视频」的人，而是「以系列为单位重复生产」的人。**
> 他们已有明确的选题与更新频率，每条内容不同，但制作流程高度重复。

对外承诺从「一个世界观，无限条视频」放宽为：**「一个栏目，持续出片」——把你的账号变成一条可复用的生产线。**

三条精炼判断：

1. **分段的轴不是题材，是生产重复度。** 科技资讯、原创 IP、知识科普是同一件事的三张脸：固定选题域 + 固定格式 + 持续更新。
2. **可复用的单位从「角色 / 世界」泛化为「账号的生产规范」。** 角色（若有）+ 视觉模板 + 素材库 + 脚本结构 + 剪辑流程都可复用；IP 只是其中一种（有角色的）形态，不是入场门槛。
3. **差异化不在「生成一条」，在「第 N 条比第 1 条更快」。** 竞品都能生成；只有把资产积累起来、让系列越做越省，才是别人抄不走的。

## 2. 三类账号：同一个抽象，三种角色

**纳入判据（四要素，缺一不可）**：① 有明确内容主题；② 以账号 / 系列为单位持续更新；③ 每条内容不同但流程重复；④ 有可沉淀的格式 / 视觉 / 素材。

| 人群 | 更新频率 | 复用资产 | 演示性 | 差异化上限 | 竞争 | 在本计划中的角色 |
|---|---|---|---|---|---|---|
| **A 科技 / AI / 资讯解说** | 极高（近日更） | 格式 + 素材库 + 视觉模板 | 极强 | 中 | 极高 | **先验证**：跑通「主题→成片」与跨条复用，产出内容量 |
| **B 原创 IP / 固定角色** | 高 | 角色 + 世界 + 视觉 | 强 | 极高 | 中 | **品牌与愿景**：展示积累与跨集一致性，代表产品天花板 |
| **C 知识 / 历史 / 科普** | 中 | 选题库 + 资料素材 + 镜头结构 | 中 | 高 | 中低 | **第二阶段**：素材管理与可展示案例库，商业化纵深 |

判断：

- **A 先打，但不当品牌主张。** 它更新最勤、流程最规整、最容易演示「给一个主题得到成片」，是验证产线的最佳样本；但 AI 资讯号是人人都能做的红海，靠效果拼不赢，只能靠「更快、更省」的证明。
- **B 是旗子，不是第一批客户。** 它最能兑现「经营一个世界」的愿景，但依赖跨集一致性能力，客户也更难规模获取。用它建品牌与注意力，用 A 验证留存。
- **C 是放大器。** 选题 / 脚本 / 旁白 / 资料图像 / 镜头结构天然模块化，也适合用素材库管理参考资料；但涉及历史影像、版权与素材溯源，早期不宜主打。

## 3. 营销主线：说什么、拿什么证明

**核心承诺（对外一句话）**：

> **给出一个主题，得到一条可发布的成片；做第 10 条，比第 1 条快得多。**

**核心 demo（唯一必须打磨的演示）：「同一栏目，换主题」**

- 用同一个栏目的格式 / 视觉 / 素材，连续做 2–3 条不同主题的视频；
- 前几秒直接放成片——观众先看到结果，而不是先看到软件；
- 展示第 1 条 vs 第 N 条的差异，**要证明的不是「它生成了什么」，而是「它记住了什么、省掉了什么」**。
- 这一支 demo 同时兑现两件事：**主题→成片**（A 的刚需）与**跨条复用**（我们的护城河），比「复刻爆款」更贴近这三类人的日常。

**辅助钩子**：复刻一条参考视频（好奇驱动、易传播），用于拉量；但转化必须落到「起一个自己的栏目」。

**证据（缺一不可）**：成片本身 / 制作过程 / 可复用的栏目资产（模板或世界）/ 用户自己的下一步。案例不能是「看完就结束」，要能一键变成用户自己的起点。

## 4. 倒推产品

| 调整 | 为什么（由营销倒推） |
|---|---|
| **给「栏目 / 系列」一个一等入口** | 对外卖的是「持续出片」，产品里却只有单项目 / 单世界，用户第一反应会是「那我每条都要重建一遍」。 |
| **把「复用」做成默认，而非进阶功能** | 第 N 条要能从已有栏目一键开新集（继承格式 / 角色 / 素材 / 模板），而不是从空白开始。 |
| **首成片路径要短** | A 类用户日更，若第一条就要先学画布 / 世界 / 实体关系，劝退率极高；首条要在「给主题」后尽快落地成片。 |
| **一致性要可见** | 跨集一致（角色 / 风格 / 格式）是三类人的共同刚需；要让一致性成为可检查、可复用的东西，而不是碰运气。 |
| **付费 / 不可逆步骤停在确认点** | 面向「把账号当饭碗」的人，一次翻车就是信任崩塌；宁可少自动一点，也要可控、可审阅、可撤销。 |
| **补齐三类引导蓝图** | 已有「IP 账号」世界蓝图；需补「资讯解说」「知识科普」两条更轻的起点，降低非 IP 用户的理解成本。 |

一句话：**产品要从「生成一条视频的工具箱」，变成「经营一个栏目的工作台」。**

## 5. 倒推官网

官网现状讲的是「Recut 是什么 / 有什么能力」，而这三类人关心的是「能不能替我持续出片」。

- **首页改为场景入口**：三条门——科技资讯 / 原创 IP / 知识科普，或先统一为「系列创作者」再分场景。让人一眼对号入座，而不是先读功能。
- **每个场景页给同一套证据**：一支成片 + 「同一栏目换主题」的制作过程 + 可复用的栏目资产 + 第 N 条的成本 / 耗时对比。
- **把栏目资产做成可下载的起点**：可复用的世界 / 模板（配合应用商店与社区），让「看案例」直接变成「用案例」——这是最该重仓、也最区别于「模板数量竞赛」的一层。
- **开源与本地优先放在「为什么放心」，不放开头**：它是信任层与差异层（资产不被锁定、不按条计费、可自部署），不是非技术创作者的入口。
- **换掉一句话**：从「从灵感到爆款视频，AI 全自动完成」（人人都能说）换成「**把一个栏目，变成一条持续产出的生产线**」。

## 6. 倒推运营

**两条并行运营线：面向创作者的「价值展示」，面向建造者的「开源社区」。**

创作者侧：

- **自有样片账号**：自己运营至少一个 A 类（资讯 / 科普）账号，用 Recut 日更，把工具能力变成公开、可追更的证据——**第 10 条那条视频本身就是最重要的营销**。
- **内容三线**（承接前身 RFC）：结果展示（先放成片）/ 制作过程（哪些步被替掉、哪些仍需人工）/ 可复用资产（看完能拿来用）。
- **案例管线按人群排期**：先 A 打样跑通，再上 B 的旗舰案例做品牌，C 作为扩展批次。
- **节奏**：少量高打磨案例 > 大量低质演示；每条尽量带「第 1 条 vs 第 N 条」的对比。

建造者侧（开源杠杆）：

- **GitHub / 社区不是终端用户的入口，是「会写 App / World 的人」的入口**：让社区替我们长出三个垂直场景的 App、世界与模板。
- 用「栏目资产 / 世界」的可分享、可安装，把社区贡献直接变成创作者侧可用的案例与模板——形成「社区造资产 → 创作者用资产 → 案例反哺社区」的循环。

## 7. 开源优势怎么用（分清两件事）

- **对创作者（信任与差异）**：开源 + 本地优先 = 你的栏目资产（世界 / 素材 / 模板 / 流程）不被单一平台锁定，可迁移、可自部署、不按条计费。对「把账号当事业」的人是真实承诺；对「只想试一下」的人不是卖点。
- **对建造者（分发与杠杆）**：开源是把产品做成「可扩展底座」的能力来源。它不直接带来创作者流量，但能让生态以我们做不过来的速度覆盖垂直场景。
- **不能做的**：不要把「开源」当成面向大众创作者的营销钩子，也不要指望 GitHub 热度自动转化为非技术用户。它是护城河与杠杆，不是话术。

## 8. 度量：从「单条激活」换成「系列留存」

北极星：**用户把一个持续更新的账号建立在 Recut 上。**

| 指标 | 要回答的问题 |
|---|---|
| 第二次 / 第三次产出率 | 用户是在「做一个系列」，还是只做了一条？ |
| 第 N 条 vs 第 1 条的耗时与人工干预 | 复用是否真的发生、资产是否在积累？ |
| 跨集一致性达成度 | 用户是否敢把「账号一致性」交给 Recut？ |
| 从主题到成片的时间 | 是否真的减少了制作负担？ |
| 栏目资产（世界 / 模板）的复用次数 | 产品与开源生态是否在沉淀？ |

**不要用播放量 / 点赞决定方向**：一条炫技视频容易爆，但不代表能形成持续使用；反过来，一条朴素的「日更流水线」可能才是真需求。

## 9. 边界与风险

- **非目标**：不早期对标「面向所有人的 AI 视频生成平台」；不与 Higgsfield 拼出片速度与量；不硬刚「文生视频」大词；不做付费投放。
- **风险 A（红海）**：A 类赛道拥挤，若无「更快更省」的硬证据会淹没——所有案例必须带成本 / 耗时对比，而不是只拼效果。
- **风险 B（能力闸门）**：B 类依赖跨集一致性。未过内部「从栏目到可发布成片」的可靠性门槛前，对外不承诺全自动，只展示诚实的人机协作。
- **风险 C（信任一次性）**：面向「靠账号吃饭」的人，交付不稳会一次性击穿信任。宁可少自动化，也要可控、可审阅、可撤销。
- **未决**：三类是否在首页同时露出，还是先只露 A 与 B、C 后置；「栏目」这一新概念与既有「World」如何统一对外表达（避免用户先学两个词）。
