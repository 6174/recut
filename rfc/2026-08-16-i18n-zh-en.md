# RFC: 全站多语言（zh / en）——官网、工作台、Service 与 App 的 i18n 整体方案

- 状态：提议
- 作者：Recut
- 日期：2026-08-16
- 决策范围：语言枚举与默认、两种语言真相（URL 驱动 vs 偏好驱动）、官网多路由结构、工作台语言偏好持久化、Service 的 Accept-Language 传递与 manifest 本地化契约、background.js `ctx.locale`、App UI iframe 语言注入与宿主桥、Agent guide/MCP 语言一致化、内容模型与 sitemap/hreflang/canonical 逐语言收敛
- 关联：`web/worker.ts`（Host 分流与多路由重写）、`web/wrangler.toml`、`web/app/layout.tsx`（html lang）、`web/app/marketing|docs|blog|marketing/apps`（官网路由）、`web/components/marketing-site.tsx`（官网展示文案）、`web/lib/marketing-posts|marketing-home|marketing-apps.ts`（内容数据源）、`web/lib/workspace-store.ts`（工作台状态）、`web/lib/service-endpoint.ts`（API 连接）、`service/server.go`（App UI / API / catalog / onboarding 服务）、`service/mcp.go`（MCP 工具描述）、`service/prompts/core-agents.md.tmpl`（Agent guide）、`service/runtime.go`（Goja `ctx` 注入）、`apps/*/manifest.json` 与 `apps/*/background.js`、`apps/*/ui`（App 契约）
- 实施进展：提案，未实施

## 1. 背景与病灶

对现状逐层盘点，Recut 全部界面与内容都是硬编码中文，任何一层都不具备语言感知，也没有语言真相：

1. **官网硬编码中文**。`components/marketing-site.tsx`（Header/Footer/Hero/各 section 文案）、`marketing-apps.tsx`、`lib/marketing-posts.ts`、`lib/marketing-home.ts`、`lib/marketing-apps.ts` 的标题、描述、FAQ、文章正文全部是中文；`app/marketing/page.tsx`、`app/docs/page.tsx`、`app/blog` 的 `metadata` 也是中文，`og:locale` 固定 `zh_CN`。没有英文路线，海外用户与英文 SEO 完全不可达。
2. **官网无多路由**。`recut.video`、`/docs`、`/blog(/slug)`、`/apps(/appID)` 各自只有一套中文 URL，`worker.ts` 直接把这些路径 fetch 给静态壳；没有 `/zh/` 中文前缀，没有 `/` 之外的英文面，没有 hreflang，没有 per-locale canonical 与 sitemap 条目。
3. **工作台核心硬编码中文**。`web/app` 全部 Tab（Studio/Worlds/Projects/Assets/Apps）、`components/*`（设置面板、Agent 面板、弹框、错误文案）逐字硬编码中文；`app/layout.tsx` 的 `<html lang="zh">` 与 metadata 固定。约百处文案，无字典、无 key、无语言切换入口。
4. **Service 单语言**。`manifest.json` 的 `name`/`description`/`onboarding` 是单语言中文；`service/appstore/apps.json`、`catalog.go`、`onboarding.go` 原样透出；`mcp.go` 的 `recut.*` 工具描述与 `recut.context` 快照是中文；`service/prompts/core-agents.md.tmpl`（Agent guide）与 `bridge.go` 组装是中文——guide 语言决定 Agent 的工作与回复语言，无法按用户切换。
5. **App 的 UI 与 background 无语言感知**。每个 App 的 `ui/` 是独立构建的 iframe（vox-broll `index.html` 固定 `<html lang="zh">`），`background.js` 的 operation 描述、错误信息、生成的资源标题都是中文；平台没有任何机制告诉 App 当前用户语言，App 无法感知宿主语言，宿主也无法感知 App 语言。
6. **无语言偏好持久化**。没有用户语言设置、没有探测（`navigator.language` / `Accept-Language` 均未使用），也没有任何一处向 service 传递语言。

**目标**：一套在「官网、工作台核心、Service、每个 App 的 UI 与 background」之间传递同一语言的架构——每个消费方都能感知当前语言，也能被统一语言真相收敛；官网以独立 URL 服务每个语言并保持 SEO 正确；工作台/Service/App 以偏好驱动单 URL 即时切换。

**边界**：本期只做 `zh` 与 `en` 两种语言；不引入付费翻译服务或第三方聚合；不强制外部 App submodule 必须迁移（平台提供契约与 SDK 约定，App 逐个采纳）；不改动工作台与 App 的功能逻辑，只做语言层；不引入 SSR middleware 或运行时依赖（保持 `output: export` 静态导出）。

## 2. 决策记录

| # | 决策 |
|---|---|
| D1 | **语言枚举与默认**：`Locale = "zh" \| "en"`，`defaultLocale = "en"`——无语言前缀的 `/` 恒为英文（SEO canonical 稳定）；中文固定 `/zh/` 前缀。默认语言是配置常量，可整仓切换 |
| D2 | **两种语言真相**：官网是 **URL 驱动**（每个语言有独立 canonical 路径，供 SEO/hreflang/分享），工作台/Service/App 是 **偏好驱动**（单一 URL，语言为持久化的用户偏好，切换全局生效）。这是全方案的分水岭 |
| D3 | **官网多路由结构**：所有官网内容收敛到 `app/marketing/[locale]/...`（`generateStaticParams` 枚举 `["zh", "en"]`），`en` 经 Worker 映射为无前缀 `/`，`zh` 固定 `/zh/`；旧 `app/docs`、`app/blog` 迁入并删除 |
| D4 | **逐语言 metadata / hreflang / sitemap / canonical**：`generateMetadata` 以 locale 参数取本地化 title/description；`alternates.languages` 输出 `{ en: …, zh: …, "x-default": … }`；canonical 按「default 无前缀 / 非 default 带 `/zh/`」收敛；`og:locale` = `en_US`/`zh_CN` 并输出 `og:locale:alternate`；`sitemap.ts` 遍历语言产出全部 URL；JSON-LD `inLanguage` 逐语言 |
| D5 | **内容模型 locale-keyed**：`marketing-posts.ts` / `marketing-home.ts` / `marketing-apps.ts` 改为 `Record<Locale, …>`；blog 同 slug 双语言正文；某语言缺失时该语言 URL 返回 404 且不出现在 sitemap/hreflang（安全降级，不混语言渲染） |
| D6 | **轻量类型化字典，不引入 next-intl**：新增 `web/lib/i18n/`（`locales.ts`、`dictionary.ts`、`t(locale, path)` 纯函数 + `useI18n()` client hook，基于现有 zustand）；理由：`output: export` 静态导出、无 middleware、类型安全、零依赖；next-intl 记为替代方案不采纳 |
| D7 | **工作台语言偏好真相**：新增 `GET/PUT /v1/preferences`（`workspace.sqlite` 的 `user_settings` 表，key=`locale`），`workspace-store` 增加 `locale` 状态并以 localStorage 兜底即时生效；首次运行按 `navigator.language` 探测映射 |
| D8 | **Service 语言传递**：工作台统一 fetch 包装为所有 `/v1` 请求附加 `Accept-Language: <locale>`；service 解析该头并用于 manifest 本地化、catalog/appstore、onboarding、MCP 描述、Agent guide 渲染、App UI 注入与 `ctx.locale` |
| D9 | **manifest 本地化契约**：manifest 支持可选 `localized: { [locale]: { name?, description?, onboarding? } }`，平台按语言取用、缺失回退顶层字段（顶层视为 default locale）；向后兼容，不要求既有 App 改动 |
| D10 | **`ctx.locale` 注入 background.js**：Goja runtime 依 App API 请求头注入 `ctx.locale`，App background 可产出本地化结果与错误 |
| D11 | **App UI 语言注入**：工作台 iframe src 带 `?locale=`；宿主桥 `page.context` 消息携带 `locale`；App UI 以「`navigator.language` + host 消息」为准；SDK 提供 `useRecutLocale()` 约定 |
| D12 | **Agent 语言一致化**：Agent guide（`core-agents.md.tmpl`）按用户 locale 渲染（模板加 `{{.Locale}}` 与条件块）；MCP 工具描述按 service 当前偏好 locale 本地化（MCP 无 locale 概念，用用户偏好） |
| D13 | **错误文案本地化策略**：/v1 返回结构化 error code，工作台在客户端经 `useI18n()` 本地化展示；服务端只对 MCP/非 UI 消费者本地化，避免双重维护 |
| D14 | **html lang 动态化**：官网 `[locale]` 布局静态输出正确 `lang`；工作台壳默认 `lang="en"`，客户端按偏好设置 `document.documentElement.lang` |
| D15 | **浏览器语言自动识别与跳转**：Marketing Host 无前缀路径先看 `recut_locale` cookie（语言切换器写入），无 cookie 时按 `Accept-Language` 判断：中文浏览器 302 到 `/zh/<同路径>/`，其余浏览器留在 `/`（英文）；跳转用 302 而非 301，避免改变爬虫对 canonical 的理解 |

## 3. 架构：语言真相与传递

```text
                    ┌─────────────────────────────────────────────────────────┐
                    │             语言真相（Language Truth）                  │
                    │  官网 = URL 驱动         工作台/Service/App = 偏好驱动    │
                    └───────────────┬─────────────────────────────────────────┘
                                    │
   URL 驱动                          │ 偏好驱动（persisted）
   ┌──────────────┐                 │  ┌──────────────────────────────────┐
   │ recut.video  │  / 默认英文      │  │ workspace-store (zustand)         │
   │ recut.video/ │  /zh/ 中文       │  │   ├─ navigator.language 首启探测    │
   │ zh/docs …    │  hreflang/canon │  │   ├─ GET/PUT /v1/preferences       │
   └──────┬───────┘  sitemap×2      │  │   └─ localStorage 兜底             │
          │ 静态导出 generateStaticParams │  └──────────────┬───────────────┘
          ▼                            │                     │
   app/marketing/[locale]/…            │  ┌──────────────────┼────────────────────┐
          │                            │  │                  ▼                    │
   worker.ts 重写 + 浏览器语言 302     │  │  工作台 UI  <── useI18n() 字典          │
   / → /marketing/en/               │  │   iframe App <── ?locale= + page.context.locale
   /zh/ → /marketing/zh/            │  │        │           └─> background.js ctx.locale
                                       │  │   service API <── Accept-Language 头
                                       │  │        ├── manifest/catalog/onboarding 本地化
                                       │  │        ├── MCP 描述 / Agent guide 本地化
                                       │  │        └── App UI 服务（携带 locale）
                                       │  └──────────────────────────────────────────┘
```

关键原则：

- **一个真相、多点感知**：`zh`/`en` 是唯一枚举；官网从 URL 读，其余从偏好读；两者都收敛为同一个 `Locale` 类型，跨层用 `Accept-Language` / `?locale=` / `page.context.locale` / `ctx.locale` 传递，不存在各自为政的第二个语言系统。
- **官网与工作台同仓同构**：`lib/i18n` 字典同时服务服务端组件（`t()` 纯函数，静态导出安全）与客户端组件（`useI18n()`），文案 key 一处定义、多处引用。
- **App 不被强推**：平台只负责「注入语言 + 提供契约 + 文档指南」，App 是否本地化由 App 自己决定；未本地化 App 的语言信息仍然被宿主与服务感知，只是其自身文案保持原样。

## 4. 官网多路由 i18n（D1/D2/D3/D4/D5）

### 4.1 路由收敛

现有官网内容迁移为 locale 目录：

```text
web/app/marketing/
  [locale]/                       # generateStaticParams = ["zh", "en"]
    layout.tsx                    # <html lang>、逐语言 metadata 默认值
    page.tsx                      # Landing
    apps/page.tsx                 # 应用市场
    apps/[appID]/page.tsx         # App SEO 落地页
    docs/page.tsx                 # Docs
    blog/page.tsx                 # Blog 列表
    blog/[slug]/page.tsx          # Blog 详情
```

删除或收敛旧的 `web/app/docs`、`web/app/blog` 顶级路由（其内容迁入 `[locale]` 下）；`app/marketing` 原无前缀壳退役，改由 Worker 重写。静态导出产物为 `/marketing/zh/…` 与 `/marketing/en/…`。

### 4.2 Worker 重写映射与语言跳转（`web/worker.ts`，Marketing Host，D15）

Worker 对 Marketing Host 的无前缀路径先做语言判定，再做静态壳重写：

```text
判定顺序：
1. 路径显式带 /zh/ 前缀        → 直接服务中文壳，不跳转
2. 无前缀路径读 recut_locale  cookie → en → 服务英文壳；zh → 302 到 /zh/<同路径>/
3. 无 cookie 读 Accept-Language   → 首项 zh* → 302 到 /zh/<同路径>/；否则服务英文壳
```

| 请求路径 | 处理 |
|---|---|
| `/`、`/docs`、`/blog`、`/blog/<slug>`、`/apps`、`/apps/<id>` | 默认英文壳 `/marketing/en/<同路径>/`（无前缀，canonical 收敛点）；中文浏览器 302 → `/zh/<同路径>/` |
| `/zh/`、`/zh/docs`、`/zh/blog/<slug>`、`/zh/apps/<id>` | 中文壳 `/marketing/zh/<同路径>/` |
| `/zh`（无尾斜杠） | 301 → `/zh/` |
| `/en`、`/en/`（可选别名） | 301 → `/`（en 是 default，前缀收敛到无前缀） |
| `/marketing/...` | 404（内部壳不可达，保持现状） |

`server.cjs`（本地开发 Host 分流）同步同一映射与跳转逻辑。Worker 的 App Host 分支不变（工作台单 URL，语言偏好驱动，不出现语言前缀）。语言切换器经 `document.cookie = "recut_locale=<locale>; max-age=31536000"` 写 cookie 后再导航，避免中文浏览器用户切到英文后立刻被 `Accept-Language` 弹回 `/zh`。

### 4.3 逐语言 metadata 与 SEO（D4）

`[locale]/layout.tsx` 提供默认值，各页面 `generateMetadata({ params })` 按 `locale` 取字典：

```ts
export async function generateMetadata({ params }: { params: Promise<{ locale: Locale }> }): Promise<Metadata> {
  const { locale } = await params;
  const t = dictionary[locale].landing;
  return {
    title: t.title,
    description: t.description,
    robots: { index: true, follow: true },
    alternates: {
      canonical: localizeURL("/", locale),                 // default(en) → https://recut.video/，zh → /zh/
      languages: { en: "https://recut.video/", zh: "https://recut.video/zh/", "x-default": "https://recut.video/" },
    },
    openGraph: {
      url: localizeURL("/", locale), locale: locale === "en" ? "en_US" : "zh_CN",
      alternates: { locale: locale === "en" ? ["zh_CN"] : ["en_US"] },
      // …
    },
  };
}
```

- `lib/i18n/url.ts` 提供 `localizeURL(path, locale)`：default(`en`) 无前缀、`zh` 加 `/zh/` 前缀——canonical、og:url、分享链接、内部 Link 全部经它派生，杜绝两套 URL 拼写。
- `app/sitemap.ts` 遍历 `locales`，default 与 zh 各产出 Landing/Docs/Apps/应用详情/Blog/文章条目；文章若缺某语言则只列入存在的语言。
- `app/robots.ts` 不变；JSON-LD 组件 `marketing-jsonld.tsx` 接收 `locale`，`inLanguage` 逐语言，其余结构共享。
- 官网 Header 增加语言切换（`/` ↔ `/zh/`，当前语言高亮），切换器先写 `recut_locale` cookie 再导航；`MarketingShell` 从 props/context 读取 `locale`，全部文案切到字典。

### 4.4 内容模型（D5）

```ts
export type Locale = "zh" | "en";
export const locales: Locale[] = ["zh", "en"];
export const defaultLocale: Locale = "en";

// lib/marketing-posts.ts
export type MarketingPost = {
  slug: string;                    // 双语言同 slug，URL 稳定
  date: string;
  content: Record<Locale, string>; // 每语言唯一 markdown 正文
  title: Record<Locale, string>;
  description: Record<Locale, string>;
};

// lib/marketing-home.ts / lib/marketing-apps.ts
export type MarketingApp = { …; name: Record<Locale, string>; tagline: Record<Locale, string>; overview: Record<Locale, string[]>; … };
```

**缺失降级规则**：某语言无内容时，该语言路由 404（不混语言渲染、不污染 canonical/hreflang）。`en` 是 default 无前缀面，必须恒有内容；迁移期允许 `zh` 条目为空（`/zh/…` 404 且不出 sitemap/hreflang），不阻塞机制上线。新增文章默认要求双语言正文，审核流程保证一致。

## 5. 工作台核心 i18n（D6/D7/D14）

### 5.1 字典与 hooks（D6）

```text
web/lib/i18n/
  locales.ts        # Locale 类型、locales、defaultLocale、探测映射（navigator.language → Locale）
  url.ts            # localizeURL(path, locale)：官网 URL 派生
  dictionary.ts     # 类型化字典：Record<Locale, MarketingDict & WorkspaceDict>；WorkspaceDict 含 settings/apps/projects/media/agent/common 等命名空间
  index.ts          # t(locale, "workspace.settings.title") 纯函数（服务端/静态）；useI18n() client hook（读 zustand locale）
```

- `t()` 是纯函数，可在 `generateMetadata`（服务端组件）与事件回调里使用；`useI18n()` 返回 `{ locale, setLocale, t }`，`setLocale` 写 `workspace-store`。
- key 按「页面/组件/字段」命名，扁平化便于检索；缺 key 时 TS 编译报错，杜绝漏译。

### 5.2 偏好真相与探测（D7）

- `workspace-store`（zustand）新增 `locale` 与 `setLocale`：`setLocale` 写 `GET/PUT /v1/preferences`（失败不阻塞，localStorage 兜底）并更新 `<html lang>`。
- 首启探测：无本地偏好时读 `navigator.language`，`zh*` → `zh`，其余 → `en`（与官网 D15 同一探测口径）。
- 设置面板新增「语言 / Language」下拉，选择即时全工作台生效。
- `lib/service-endpoint.ts` 增加统一 `fetchJSON` 包装：所有 `/v1` 请求自动附加 `Accept-Language: <currentLocale>`（D8 的服务端入口）。

### 5.3 html lang（D14）

工作台壳 `<html lang="en">` 保留为默认，客户端在 `setLocale` 与首启探测后写 `document.documentElement.lang`；官网由 `[locale]/layout.tsx` 静态输出正确 `lang`。

## 6. Service 层 i18n（D8/D12/D13）

### 6.1 语言解析

新增 `service/locale.go`：解析 `Accept-Language`（取首个匹配 `zh`/`zh*`/`en*`，回退 `en`），导出 `type Locale string` 与 `DetectLocale(r) Locale`。工作台每次 `/v1` 请求都携带该头，服务侧据此响应。

### 6.2 本地化的服务面

| 面 | 现状 | 方案 |
|---|---|---|
| `GET /v1/apps`、catalog、appstore | 原样透出 manifest `name`/`description` | 按请求头取 `manifest.localized[locale]`，缺失回退顶层字段 |
| onboarding（`onboarding.go`） | 原样透出 manifest `onboarding[].title/description/prompt` | 同上；platform 兜底引导也入字典 |
| MCP 工具描述（`mcp.go`） | 硬编码中文 | 按 service 持久化偏好 locale（见 6.3）选择描述；`recut.context` 快照同 |
| Agent guide（`prompts/core-agents.md.tmpl`、`bridge.go`） | 硬编码中文 | 模板加 `{{.Locale}}` 与条件块；`bridge.go` 从会话/偏好取 locale 渲染，guide 语言决定 Agent 工作语言 |
| App UI 服务（`server.go appUI`） | 直接 ServeFile | 不修改 HTML；locale 由工作台 iframe `?locale=` 传递，不经服务注入 |
| `/v1` 错误 | 中文 error string | 返回结构化 `code`，工作台客户端本地化（D13）；MCP 路径由服务按偏好本地化 |

### 6.3 服务端偏好持久化

`workspace.sqlite` 新增 `user_settings` 表（key/value），`GET/PUT /v1/preferences` 读写 `locale`；service 自身的 MCP/guide 渲染读取该偏好（无请求头时的兜底）。与工作台 localStorage 同源同值，以 service 为准。

## 7. App 的 UI 与 background i18n（D9/D10/D11）

### 7.1 manifest 本地化契约（D9）

```jsonc
{
  "id": "recut.vox-broll",
  "name": "AI 短片",
  "description": "把资料研究、导演风格与镜头生产收束成可审阅、可复用的 AI 短片。",
  "localized": {
    "en": {
      "name": "AI Short Films",
      "description": "Research, direct, and produce reviewable, reusable AI short films.",
      "onboarding": [
        { "id": "start-short-film", "title": "Start from a short-film topic", "description": "…", "prompt": "…" }
      ]
    }
  },
  "onboarding": [ /* zh 原样，作为 default */ ]
}
```

- 顶层字段 = 回退语言（作者主语言，现有 App 为中文，不绑定站点 default）；`localized[locale]` 可选覆盖 `name`/`description`/`onboarding`。
- 平台 `catalog.go`/`onboarding.go` 输出时按请求语言合并：`localized[locale] ?? 顶层`。
- 向后兼容：既有 App 无 `localized` 时行为不变。

### 7.2 background.js：`ctx.locale`（D10）

`runtime.go` 在 Goja 注入 `ctx.locale`（字符串），取值来自 App API 请求的 `Accept-Language`（经 `?locale=` → 宿主桥转发，或工作台直接带头的 fetch）。App background 的 operation 实现、错误信息、生成的资源标题可据此本地化；平台不解释 App 内部文案。

### 7.3 App UI：iframe 语言注入与宿主桥（D11）

- 工作台构造 iframe src 时附加 `?locale=<currentLocale>`；宿主桥现有 `page.context` 消息扩展 `locale` 字段，iframe App 在初始化时读取。
- App UI 语言判定顺序：宿主桥 `page.context.locale` → `?locale=` → `navigator.language`（兜底）。
- `apps/*/ui/src/recut-sdk.ts`（现有 SDK）增加 `useRecutLocale()`/`getRecutLocale()` 约定；`index.html` 的 `<html lang>` 由 App 在运行时按结果更新。
- 平台不注入脚本、不修改 App 构建；只提供「语言从何而来」的稳定通道。App 的 UI 与 background 之间经 App API 自行传递（App 内部事务）。

## 8. 数据与接口契约汇总

| 契约 | 位置 | 语义 |
|---|---|---|
| `Locale` 枚举 | `web/lib/i18n/locales.ts` ↔ `service/locale.go` | 唯一语言类型，跨层一致 |
| `Accept-Language` 头 | 工作台 fetch 包装 → 全部 `/v1` | service 侧语言真相 |
| `GET/PUT /v1/preferences` | service `user_settings` 表 | 用户语言偏好持久化 |
| `manifest.localized` | App manifest（可选） | App 元数据/onboarding 逐语言 |
| `ctx.locale` | `runtime.go` Goja 注入 | App background 感知语言 |
| `?locale=` + `page.context.locale` | 工作台 iframe 宿主桥 | App UI 感知语言 |
| `{{.Locale}}` | `core-agents.md.tmpl` 渲染 | Agent guide/工作语言 |
| `localizeURL(path, locale)` | `web/lib/i18n/url.ts` | 官网 URL/canonical/hreflang 唯一派生 |

## 9. 迁移路径

**P0（官网多路由 + 字典底座）**

**P1（工作台 + Service 传递）**

## 10. 边界与开放问题

- **非目标**：不做 `zh-TW`/日韩等多语言；不做翻译记忆/机器翻译流水线；不重写 App 内部数据模型；不把语言做进媒体素材本身（素材语言是内容语义，与 UI 语言正交，`recut.media.create_reference.language` 保留原义）。
- **已定 A（默认语言与跳转）**：`defaultLocale = "en"`，无前缀 `/` 恒为英文 canonical；中文固定 `/zh/`；中文浏览器经 `recut_locale` cookie + `Accept-Language` 302 到 `/zh/`。爬虫不带中文 `Accept-Language`，会稳定落在英文 `/`。
- **开放问题 B（Blog 双语言工作量）**：14 篇文章双语言是内容成本；`en` 为 default 面必须补全，迁移期允许 `zh` 缺失并自动 404/不出 sitemap，不阻塞机制上线。
- **开放问题 C（App 语言归属）**：App 是独立 Git 仓库，其语言文案属于 App 自身资产；平台只保证「语言信号可靠送达」，不保证 App 必须显示对。接受评审确认。
- **开放问题 D（Agent guide 语言）**：guide 语言直接影响 Agent 输出语言；是否允许用户在设置里独立选择「Agent 工作语言」与「界面语言」，本期默认绑定，记录为后续增强。
