# Part A · 对 v0.1 草稿的评审

## A.1 总评

v0.1 是一份合格的「差距盘点 + 能力构想清单」，但还不是一份可直接开发的设计方案：

- **缺三样**：① 用户任务流（用户做 X 时，画布上发生什么、状态如何迁移、什么反馈）；② 屏幕级状态机（卡片/面板/对话框/错误态各有什么状态、如何进出）；③ 可验证的验收（里程碑验收停留在「能走通」，不可测试）。
- **两处失衡**：过设计（4 层 Link 谱系、媒体三态、宿主卡+面包屑+路径三处导航、5 处 AI 能力）与欠设计（空状态、就地编辑、错误态、写后闪烁、只读态、"验证 AI 记住什么"的角色）。
- **产品定义修订**：v0.1 的「语义优先的二维创作画布」是架构陈述。v2 定义见 B.1。

保留 v0.1 的核心资产：双持久化分层（Canon 产 revision / 布局不产）、entity type 目录、递归容器语义、Promote 概念、里程碑大方向。

## A.3 UX 与设计问题

1. **4 层 Link（R/A/M/F）超出用户心智预算。** 用户能区分的只有：「事物之间什么关系」（实线+标签）、「素材挂在哪个事物上」（虚线）、「随手画的箭头」（细线）。M 层（作品引用/producer 记录）在 v1 没有任何 UI 入口。→ v2：v1 只做 **R 语义关系 + A 挂接虚线**，草稿箭头沿用；M 层移 P2。（D5）
2. **三种"草稿/状态"并存**（provisional 实体 / 画布自由元素 / 独立材料），用户无法建立一致心智。→ v2 统一为两根正交轴：**设定（草稿/正式）× 素材（独立/已挂接）**（B.5）。（D2）
3. **撤销设计是反模式**：「Cmd+Z 跨语义 op 弹二段确认」——撤销弹对话框会让用户直接放弃撤销；且「回滚整个语义版本」来撤一次建关系，会连带冲掉其他改动，爆炸半径过大。RFC 本意是视觉 undo 与语义 revision 分离。→ v2：Cmd+Z 只撤销布局；语义操作靠「最近变更」列表逐项撤销（P1）；版本回滚是独立的低频动作。（D4）
4. **导航三处冗余**：面包屑（已有）+ 宿主卡（§7.1）+ 路径行。→ 只保留顶栏面包屑，画布上不画宿主卡。（D6）
5. **命名态没有完整状态机**：Enter 空标题怎么办、Esc 时实体已写库如何回滚、blur 行为、光标/焦点、新卡落点——均未定义。→ B.7 给出完整状态表。
6. **空状态完全未设计**：现状空世界 = 画布上一个孤立 World 节点。前 5 分钟体验决定产品生死。→ B.5 空状态 + 首访引导。
7. **错误/异常态零定义**：写失败（notice 截断一行）、冲突（静默）、断网、只读模式（store 有 `readOnly` 但无产品定义）。→ B.4 错误映射表 + B.3 只读态。
8. **缺「验证」角色**：2026-08-14 RFC 的产品承诺是「让 AI 记住你正在创造什么，也让你一眼知道它记住了什么」。v0.1 没有任何屏幕承载后半句。→ World 态面板加「世界快照 + 待关注」列表（成本低、产品价值高）。
9. **「添加字段」没区分类型级 vs 实例级**：字段加到 type schema 会作用于该类型所有实体，只加到本实体的 content 则是私有字段。v0.1 的 §5.2 `custom_fields/aliases/notes` 没讲清这个区别，用户会困惑。→ v1 只做**类型级**字段 + UI 明示「该字段会出现在所有『人物』设定上」；实例级自由字段 P1。
10. **AI 铺得太开**：5 处能力（建实体/连线建议/补字段/生成媒体/Chat 承接），M2 一次做 4 个。→ v1（P1）只做「文字描述→候选实体」一个；其余 P2。（Q4）
11. **里程碑依赖纠缠**：M1 的「A 层 Link」依赖 M2 的媒体链；M2 的「快照面板」依赖未排期的后端。→ 按用户闭环重排，每里程碑独立可交付（Part C）。
12. **闭环表述误导**：§1.3「物品↔一张证据图连起来」——证据是**挂接**（evidence.entityId），不是画线。照 v0.1 闭环操作的会去拖线。→ B.12 明确两种形态。
13. **只读模式无定义**：他人世界/PGC 场景 `readOnly=true`，画布应禁用哪些交互、显示什么提示，v0.1 未提。
14. **视图切换状态丢失未定义**：切到设定视图画布 unmount，pomelo editor 销毁 → zoom/pan 丢失（context/selection 在 store 里能保留）。→ P1 持久化视口状态。

## A.4 后端能力缺口（v0.1 假设存在、实际没有）

| 能力 | 现状 | v2 归属 |
| --- | --- | --- |
| `entities.delete`（级联清理子实体/关系/证据） | 无端点（仅 world archive） | **M0 新增**（T2） |
| 便签 promote 的 title/summary 拆分 + 产出草稿 | 现状全文截 120 当 title、产出正式实体 | **M0 小改**（T3，~半天） |
| `entities.list` 批量带全量 content（消除 N+1） | list 只回 summary，前端逐个 get | P1 可选（T1 客户端合并不依赖它） |
| `relations.update`（改类型/换方向） | 只有 create/remove | P1（T16；换方向 v1 可用删+建兜底但不做 UI） |
| revisions 列表 / diff / 回滚 | 无 | P1（T12） |
| AI 候选实体端点 | 无 | P1（T13，契约先行） |
| 反向引用查询（谁引用了它） | 无 | P2 |
| 画布元素回收站（删除可恢复） | 无 | P1 可选（T12 附带） |

**已具备、v0.1 低估其价值的能力**（v2 直接利用）：`entities.upsert/children` 支持 `isProvisional` + `summary`；`entities.promote` 端点；evidence 全套（attach/update purpose+status/archive，含 modality/purpose/collection/segment）；`entityTypes.upsert/list`（type 目录 + 字段 schema）；`canvas.promote`；关系锚点几何持久化（`persistRelationGeometry` → `shape:rel-<id>` 元素，README 说「不持久化」已过时）。

## A.5 里程碑问题

- M0–M3 的**能力维度**切分（面板/Link/容器/媒体/AI）导致跨里程碑依赖（A.3 #11），且 M2 混入了依赖后端的快照面板。
- 估时未含：闪烁修复（T1）、`entities.delete`、错误体系、空状态。
- v2 按「用户闭环」重排：**M0 能录入 → M1 能连线能深入 → M2 能挂素材 → M3 能引导能兜底**，每级独立可用（Part C）。

# Part B · 细化设计方案 v2

## B.1 产品定义与设计原则

**v2 一句话定义**

> World Canvas 是一个**世界工作台**：创作者用「放下 / 写下 / 挂上 / 连上 / 深入」五个动作，把脑中的世界和散落素材组织成结构化设定；同时一眼看到「AI 已经记住了什么」。画布同时是 Canon 的**录入界面**和**验证界面**；AI 消费（CreationContext）是终点，但 v1 不做消费链路。

核心任务链（所有设计围绕它检验）：

```
开始（空世界/已有世界）
  → 放下：建实体（人物/地点/物件…）
  → 写下：填字段（外貌/性格/描述…）
  → 挂上：附素材（图/音/视频 作为证据）
  → 连上：建关系（位于/拥有/出现在…）
  → 深入：进入实体内部（容器）
  → 收尾：整理、看快照、确认草稿为正式
  →（P2）消费：作为 CreationContext 进入创作
```

**六条设计原则**

1. **画布是为组织心智，不是画图。** 一切自由表达（便签/媒体）都服务于「变成设定」。
2. **用户概念封顶三个：实体 / 关系 / 证据。** 不向用户暴露 revision、canon、hash、scope、provisional —— 对应用户语言「设定 / 草稿 / 局部（仅在此设定内可见）」。
3. **画布管空间，面板管内容。** 选中即面板，编辑不弹窗（确认类除外）。
4. **零摩擦创建。** 放置实体 ≤2 次交互；命名就地；无内容不阻塞放置。
5. **布局免费，语义有成本感。** 布局操作自动保存、零反馈；语义操作轻反馈（toast / 行内「已保存」）。
6. **删除必须可解释。** 语义删除展示影响范围；画布元素删除直接进行。

## B.2 用户语言（用户可见的唯一术语集）

| 用户语言 | 内部概念 | 说明 |
| --- | --- | --- |
| 设定 | entity（正式） | 卡片、面板统称 |
| 草稿 | entity（is_provisional=1） | 虚线框 + 「草稿」徽标；不进 Canon |
| 确认设定 | entities.promote | 草稿→正式的动作（按钮文案） |
| 关系 | relation | 受控词表 + 自定义 |
| 参考素材 | evidence | 挂在设定上的图/音/视频/文 |
| 挂接 | evidence attach | 拖文件到卡 / 面板添加 |
| 进入内部 | setContext | 双击卡 |
| 全局画布 | context='' | 面包屑文案（沿用现状） |
| 世界快照 | World 态统计 | 「3 个人物 · 2 个地点 · 5 条关系 · 8 份素材 · 1 个草稿」 |

- 类型标签一律取自 type 目录的 `name`（如「人物」）；`entityKindLabels`（「角色」等）仅作目录缺失时的兜底，并统一两套文案（T11）。
- 面板/文案中禁止出现 `revision`、`canonical`、`scope`、`provisional`、英文 error message。

**错误映射表**（服务端码 → 用户语言，T10 落地为集中函数）：

| 场景 | 用户语言 | 附带动作 |
| --- | --- | --- |
| `WORLD_REVISION_CONFLICT`（重试后仍失败） | 「设定已被其他窗口更新，已加载最新版本，请重试」 | 自动 load |

| 其他 | 保留原文（内部可见）+ 前缀「操作失败」 | — |

## B.5 草稿与正式：设定的状态（v2 核心修订，D2）

**规则：一切新出现在画布上的设定都是草稿。**（手动创建 / 便签 promote / AI 候选 一律 `is_provisional=1`）

- 草稿特性：虚线卡框 + 「草稿」徽标；**不进 Canon**（现成机制）；不计入 readiness（现成机制）；**编辑草稿不产生 revision**（现成机制：provisional upsert 不 commitRevision —— 草稿是免费草稿区）；出现在 World 面板「待关注」列表。
- 转正（= 产 1 条 revision + toast「已确认设定「林小满」」）：
  1. **自动**：标题 ≠ 默认名（「新人物」等）且 summary 非空 → 客户端在字段保存后检查并调 `entities.promote`（无后端改动）。
  2. **手动**：面板草稿徽标旁的 [确认设定]（`entities.promote` 现成端点）。
- 已正式实体不可降级回草稿（v1）。
- 配套小改（后端 ~半天）：
  - `promoteNoteToEntity`：改为 `IsProvisional: true`；文本拆分为 第一行→title、其余→summary（保留 `content.body` 全文）。
  - canvas-store `createEntity/createChildEntity`：传 `isProvisional: true`（client 类型已支持）。

> 产品叙事收益：「草稿」不再是 v0.1 里与「便签草稿/属性徽标」混在一起的第三个概念，而是**所有设定的统一起点**；「确认设定」成为用户"我认真了"的明确时刻，AI 候选实体也天然走同一确认门禁（符合 2026-08-14 RFC 的「提议→确认→写入」）。

**命名态状态机**（完整定义，v0.1 缺失部分）：

| 当前态 | 事件 | 行为 |
| --- | --- | --- |
| 正常 | 创建动作 | 立即写库（默认标题「新人物」等 + `isProvisional: true`）→ 卡出现在落点，进入命名态：标题位渲染 DOM 输入框（预填默认名、全选、autofocus） |
| 命名态 | 输入 | 本地预览（不写库） |
| 命名态 | Enter / blur | 非空 → 重命名（1 次 upsert；草稿不产 revision）；空 → 保持默认标题 | 然后退出命名态；若此时 summary 也非空 → 触发自动确认设定（B.5） |
| 命名态 | Esc / 点击空白 | 放弃重命名（恢复默认标题），退出命名态，**卡保留** |
| 命名态 | 再次双击该卡 | 退出命名态并进入容器 |

- 写库时机说明：创建即写库（而非本地幽灵卡）保证语义单一来源；草稿免费（不产 revision）使「先建后想」无成本，Esc 不需要回滚库——最坏情况留一张「新人物」草稿，可一键删。
- 创建后：卡高亮脉冲 1s + 视口自动平移使新卡入视（出屏时）。
- 结构性 toast：「已创建 人物「新人物」（草稿）」。

**新建设定类型**（RFC 5.4「随手建」的产品化，T3）：

- 菜单 [＋ 新建设定类型…] → 小对话框：名称（必填）/ 图标（emoji 选择，可选，默认 ◍）/ 颜色（自动分配，v1 不手选）→ `entityTypes.upsert`，字段 schema = 最小 `[描述 textarea]`（RFC：name+description 起步，按需生长）。
- 创建后问一句「现在创建第一个？」→ 是 = 用该类型落一张草稿卡。
- 新类型进入 `+` 菜单自定义区（最近 3 个）。

**AI 创建（P1，T13）**：菜单项 [✨ 用描述添加设定…]（v1 不显示）；流程见 B.16。

## B.11 容器导航（进入实体内部）

- **双击任何实体 = 进入**（T6 放开 children>0 限制）。心智统一：双击永远是"进去"。
- 进入后：视口自动 fit 子内容（复用缩放菜单「适应项目」的 editor 能力）；清空 selection/relating（现成）。
- 空容器（无子设定）：画布中央引导区「『林小满』下还没有子设定」+ [添加子设定]（创建菜单，context=该实体）。
- 返回：顶栏面包屑（现有「全局画布」按钮 + context chip，T6 升级为多级 `全局画布 ▸ 林小满 ▸ 项链`，>3 级折叠「…」）；**Cmd+/Ctrl+[ = 上一层**（新键位，T6）；面板 [在画布定位] 回外层。
- Esc 语义保持：取消选中/取消引导（与「上一层」分离，避免歧义）。
- 不画宿主卡（D6）；面包屑是唯一导航真相。
- 容器内实体卡显示其在本 context 的相对位置（现成机制）；证据媒体元素按**操作时所在 context** 落位（根视图挂的图在根视图，容器内挂的在容器内）——卡上相册/面板证据区是**语义视图**（永远可见），画布媒体元素是**空间表达**（按 context 落位）。两者不冲突。

## B.12 媒体元素与挂接（T8）

**数据**：新 `kind='media'`（`world_canvas` 开放结构，RFC 明确新 kind 无需迁移），props：`{ modality: image|video|audio, assetId?, url?, caption? }`。现有 `kind='attr'+props.media` 占位元素仅 demo 数据，直接弃用（不做迁移）。

**媒体的两种形态**（v0.1「三态」收敛）：

| 形态 | 语义 | 画布表现 |
| --- | --- | --- |
| 独立媒体 | 未挂接的自由素材 | media 元素卡（可拖移/可挂接/可删） |
| 已挂接证据 | 归属某实体的 evidence | 元素保留为投影 + A 虚线到实体 + 卡角「参考素材」角标；**同时**出现在实体卡相册与面板证据区（语义视图） |

（v0.1 的「作品引用/producer」态 = P2，T-。生成媒体的 `producer` 记录随 P2 AI 媒体生成一起做。）

**素材来源浮层**（统一所有「加媒体」入口，T8）：

```
┌ 添加素材 ────────────────┐
│ [＋ 上传文件]（拖入/选择；处理中=卡片 loading 态） │
│ [素材库]  缩略图网格 + 搜索（/v1/media/assets）   │
│ [URL]  输入 + 图片即时预览                        │
│ （AI 生成：P2 才出现）                            │
└──────────────────────────┘
```

- 上传复用现有 media 资产导入链（表单视图 ObjectEvidencePanel 的上传组件抽公共）。
- 挂接目标由入口决定：面板证据区 [＋添加] → 该实体；拖到卡上 → 该卡；拖到空白 → 独立元素（不挂接）。

**显示与预览**：

- 图片：cover-fit 缩略（220×140 默认）；hover 动作 [查看][替换][挂接…][删除]
- 视频：首帧/占位 + 时长 + ▶；音频：图标 + 时长 + ▶
- 预览浮层 `MediaPreviewDialog`：图片 lightbox（复用表单视图）/ `<video controls>` / `<audio controls>`；面板证据区与画布共用。
- v1 不做波形/裁切/滤镜。

**拖放矩阵**：

| 拖什么 | 落到哪 | 结果 |
| --- | --- | --- |
| 文件 | 空白 | 上传 → 独立 media 元素（落点处） |
| 文件 | 实体卡 | 上传 → **直接挂接**为 evidence（purpose 按模态默认），不建画布元素（最常用路径，画布最干净） |
| media 元素 | 实体卡 | 挂接：evidence attach + 元素保留 + A 虚线 + 卡角角标 |
| media 元素（已挂接） | 另一实体卡 | 换挂：确认「把这份素材从「A」移到「B」？」→ 归档旧 evidence + 挂新 |
| 素材库项 | 画布 | 同「文件→空白」（引用 asset，不复制） |

- 挂接成功 toast + 卡片相册/封面即时更新（增量投影，T1）。

## B.14 持久化、撤销与冲突（修订 v0.1 §10，D4）

- **布局**（移动/缩放/锚点）：本地先行 + 400ms 去抖（现成）；零反馈；中断不丢。
- **语义**：即时写；成功反馈按 B.4 分级；每次产 revision（草稿除外）。
- **撤销**：
  - Cmd+Z / Cmd+Shift+Z = **布局 only**（pomelo editor 视觉层，现成）；**永不弹确认**、**永不跨语义层**（RFC：视觉 undo 不撤销语义）。
  - 语义撤销 = P1「最近变更」列表（顶栏 ⏱ 下拉，最近 10 条语义操作：建/删实体、建/删关系、改字段、挂接/归档素材、确认设定；逐条 [撤销]：字段=回写旧值、关系=删、实体=删、素材=归档/恢复）。v1 不做语义撤销——删除有确认、编辑有行内反馈，可接受。
- **版本回滚**：P1（T12），需后端 revisions 列表 API；回滚 = 新建 revert 版本（非破坏），对话框展示两版本关键字段 diff。
- **冲突**：静默重试一次（现成）；仍失败 → 错误 toast（B.4）+ 自动 load。
- **视口状态**：切视图/刷新后 zoom/pan 丢失 → P1（T12）存 localStorage 恢复。

## B.15 增量投影（T1 设计——v0.1 遗漏的最高优先级）

**问题**（A.2 #1）：每次语义写 → `load(true)`（list + N 个 get 的 N+1 请求）→ `dataVersion++` → pomelo 文档全量重建（`buildPomeloRecords`）→ 所有封面纹理重新 `loadPixiTexture` → 闪烁 + 重复图片请求 + 50 实体时 ~50 次串行/并发 get。

**目标设计**（分层，允许分两步落地）：

1. **快速止血（T1-a，0.5d）**：写后不再 `load(true)`，改为按 API 返回对象**合并**进 store（`entities.upsert` 返回完整 entity → 替换 store 内同 id；`relations.create` 让服务端顺带返回 relation 对象（1 行）或客户端据 from/to 本地拼；promote 返回 entity/relation）；`dataVersion` 仅在有元素增删时 ++（纯属性更新走 block attrs 原地更新，不重建文档）。
2. **纹理缓存（T1-b，0.5d）**：模块级 `Map<url, PIXI.Texture>`（LRU ~200），`loadPixiTexture` 改查缓存；文档重建不再触发重复网络请求。
3. **文档 diff（T1-c，1d）**：`buildPomeloRecords` 从「全量重建」改为「按 block id diff：新增 addRecord / 删除 removeRecord / 属性变化 updateRecord」；`canvas-pomelo.tsx` 的 sync 层改造。
4. **全量 load 保留场景**：首次挂载、进入/离开容器、冲突后刷新。
5. **服务端批量（P1 可选）**：`entities.list` 支持 `includeContent` 一次带回全量，彻底消除 N+1（不阻塞 T1）。

**验收**：50 实体画布上创建卡/便签/关系：DevTools 无重复图片请求、无 N+1 get、选中与视口不跳、操作体感 <200ms。
