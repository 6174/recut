# World Canvas 产品 PRD（迭代规划）

> 状态：draft v0.1（初稿历史；评审与细化设计见 `world-canvas-prd-v2.md`，任务拆分以 v2 Part C 为准）
> 范围：Recut World 的「画布（Canvas）」产品体验 —— 从当前 demo 走向可真实使用的一版
> 关联实现：`web/app/worlds/[worldID]/canvas/`、`web/lib/pomelo/world-canvas/`、`service/worlds_canvas.go`
> 关联 RFC：`rfc/2026-09-07-recursive-world-canvas.md`（数据模型权威）、`rfc/2026-09-07-recursive-world-canvas-plan.md`

## 0. 一句话产品定义

World Canvas 是一个「**语义优先的二维创作画布**」：用户在画布上摆放**实体（Entity）**、用**关系连线（Relation/Link）**与**媒体元素（Media Element）**组织一个世界观的完整事实，画布上的一切都能下沉为可消费、可版本化的 Canon 语义数据（`world_entities` / `world_relations` / `world_canvas`）。

- 对「世界观文档」而言：画布是比表单更直觉的**录入与浏览界面**；
- 对「后续创作（视频/图片/配音）」而言：画布是把事实组织成**可用上下文**的工作台，最后经 `CreationContext` 消费。

本 PRD 面向的目标是：**把当前只能浏览/摆放 demo 数据的画布，升级为用户可以真实录入、编辑、整理自己世界观的一等公民产品。**

## 1. 现状与目标（现状盘点 → 差距 → 目标）

### 1.1 现状（已实现）

| 能力 | 现状 |
| --- | --- |
| 渲染 | Pomelo/Pixi 宿主，Grid/Viewport/Selection 等插件，EntityCard/Note/WorldNode/RelationArrow/FreeElement Block（`canvas-pomelo.tsx`） |
| 实体 | `EntityKind` 六类（character/location/story/style/rule/reference），从 `world_entities` 读，卡片含 cover + 照片网格 |
| 关系 | 受控词表 23 项关系类型；Link 工具 + "+" 手柄 → `RelateDialog`；箭头 + 中点标签；anchor/bend 几何 |
| 容器 | `setContext` 进入实体子图，面包屑在顶栏；双击卡进入 |
| 详情面板 | 右侧 320px 只读面板：World/Entity/Relation/Canvas-draft 四态 |
| 画布元素 | note、text/shape、attr（media 徽标）、world 核心节点；`+` 手柄拉出 attr 创建菜单 |
| 语义 | 实体/关系写入产 revision；画布元素写入不产 revision；conflict 重试一次 |
| 表单视图 | `world-detail-client.tsx` 存在 form/canvas 切换，但 canvas 目前无字段编辑 |

### 1.2 差距（本次要补）

1. **实体无法在画布上创建字段内容**（详情面板只读，字段编辑只能在 EntityDetailDialog 中做——体验割裂）。
2. **创建实体/媒体/关系靠弹窗+关键词，缺「所见即所得」的引导**（拖拽创建、就地输入、AI 提示实体尚未成链）。
3. **无法进入实体「内部」真正编辑**（容器视图=子实体列表，缺少把实体当容器+作品页双重语义的叙事）。
4. **Link 只是实体↔实体的语义边**；实体属性（字段值、图片/视频/文本证据、子元素）与「作品产出」的引用关系没有可视化表达。
5. **基础元素（text/image/video）体验最弱**：只能插入占位徽标，无真实素材、无上传、无 AI 生成、无就地编辑。
6. **预设类型偏少且无法“开箱即建”**：toolbar `+` 只弹「类型下拉 + 标题」，没有预设模板、快捷创建与字段引导。
7. 多个 demo 痕迹（`demo-store` 命名、`MediaNodeBlock` 占位、`扩展（即将推出）` 按钮）。
8. 无 AI Agent 参与创建（不能“把这段描述/这篇资料变成实体”）。

### 1.3 目标（T0 验收基线，最简可用闭环）

用户能完成一个真实任务闭环，且全程不需要打开表单视图：

> **“我想新建一个世界 → 用一句话或空白开始 → 在画布上添加「人物/地点/物件」几个实体 → 双击进入某个人物内部，补充他外观/性格/证据图片 → 用 Link 把人物↔地点、人物↔关键物品、物品↔一张证据图连起来 → 随时能撤销/保存/看到这个世界的 Canon 快照。”**

## 2. 全局交互模型

所有画布对象统一遵循四种“身份”和两套“持久化语义”：

- **Canon 对象（产 revision）**：实体 `world_entities`、关系 `world_relations`。它们是语义事实。
- **布局对象（不产 revision）**：画布元素 `world_canvas`（实体卡=实体投影、自由元素、箭头、媒体元素）。它们是投影/表达。

交互原则：

1. **画布即真相**：可编辑的尽量在画布内完成（详情面板/就地编辑），不强迫跳表单。
2. **一切皆可投影、可反推**：每个实体卡、每个媒体元素都可以从语义倒推（谁引用了它），右键“查看引用”。
3. **重力锚定**：实体卡 = 不可变形的主体；媒体/便签/文字 = 自由元素；箭头 = 绑定端点不脱落。
4. **任何创建都允许“先画后填”**：创建即占位（draft），随后补内容；未补全内容不阻塞画布组织。
5. **多入口收敛**：同一动作在 顶部+ / 画布右键 / 卡片手柄 / 详情面板 都存在，但都落到同一 store action。

## 3. Node：实体节点设计（问题 1、5）

### 3.1 节点类型总表

| 节点 | 画布语义 | 后端 | 可否进入内部 | 产 revision |
| --- | --- | --- | --- | --- |
| **Entity 卡**（六类预设 + 自定义） | 一个语义对象 | `world_entities` | ✅ 容器 | ✅ |
| **World 节点** | 当前 World 根，全局画布常驻 | — | 点 = 回到根 | — |
| **Note 便签** | 自由想法/待办/暂存文字 | `world_canvas` (note) | ❌ | ❌ |
| **Text 文本** | 自由文字块（跟便签的区别：无“待提升”属性，中性排版） | `world_canvas` (text) | ❌ | ❌ |
| **Image / Video / Audio** | 媒体证据或作品的引用 | `world_canvas` (attr/media) + `world_evidence`（如用户选择收录） | ❌ | 收录时产 revision |
| **Shape 图形** | 分组框/标注框/强调框 | `world_canvas` (shape) | ❌ | ❌ |
| **Attr 字段徽标** | 实体字段值在画布上的展开（如“性格=冷静”） | `world_canvas` (attr) | ❌ | ❌ |

> 复用现有 `ElementKind`/`FreeElementBlock` 的渲染层级即可，不必新增 Block；差异在「props 语义 + 进入内部 + 引用链路」。

### 3.2 实体卡的外观与信息层级

实体卡 = **封面区 + 信息区 + 动作区**，是画布主视觉单位：

```
┌───────────────────────────┐
│  ▓▓▓▓▓ 封面 ▓▓▓▓▓▓▓▓▓▓▓▓ │  <- cover（来自首张 identity/appearance 证据或自定义上传）
│ ───────────────────────── │
│  图标 ● 人物              │  <- kind 图标 + 类型标签（typeColors）
│  林小满                   │  <- title（就地可编辑）
│  一个擅长用声音的电台主播   │  <- summary 两行截断
│  · 草稿                   │  <- isProvisional 提示
│ ───────────────────────── │
│ [外貌][性格] [声音]        │  <- 已填字段 chip（点击展开/聚焦到该字段）
│ ───────────────────────── │
│  ❚❚❚❚ 相册(3)  ▤ 关系(2)  │  <- 数据徽标
└───────────────────────────┘
       └── 底部 / 右侧 “+” 手柄：拖出连线或媒体
```

关键规则：

- **卡片默认 264×328**，可被“展开模式”拉大显示更多字段与照片（对应 `entity-card-block` 的 3×N photo 网格上限 9）。
- **封面与相册图片来源优先级**：`identity/appearance/wardrobe/visual_style` 等 purpose 的 primary evidence → 用户手动置顶 → 无则 emoji 兜底（现逻辑）。
- 字段 chip 只显示「已填的非空 primitive 字段」；空字段不显示，避免卡片噪音（编辑时由详情面板引导）。
- 实体被多处引用（如“林小满”同时出现在多个世界/故事）不在此画布表达；那是 World 外的引用问题。

### 3.3 如何创建实体（问题 1 “如何方便的创建”）

按“从哪来”分 4 条路径，均收敛到同一 `createEntity` action：

| 路径 | 触发 | 交互 |
| --- | --- | --- |
| **A. 顶部工具栏 `+` → 实体** | 点按 | 弹出**创建菜单**（见 3.4），选类型即落卡，卡片立即处于“命名态”（就地输入标题，回车提交） |
| **B. 画布空白处双击 / 右键新建** | 双击空白 | 在光标处直接落一张“最近用类型”或所选类型的卡并进入命名态（按 alt=选类型） |
| **C. 便签提升（Promote）** | 便签卡右键 → “转为实体” | 现有 Promote 流程；保留：便签文字成为 `title` 或 `summary` 的预填 |
| **D. AI 生成** | 详情/创建菜单里“用 AI 描述” | 输入一段描述 → 生成 1..N 个候选实体（title+summary+kind+建议字段值）→ 用户勾选落盘（见 §8） |
| **E. 从已有内容派生** | 选中文本/媒体 → 右键“据此创建实体” | 文本→summary 预填；图片→成为该实体首张 evidence（identity）；来自全局素材库的媒体 asset 亦可 |

每类实体创建的“最小提交集”：`title`（必填）+ `kind`（自动从所选模板带出）。

> **增量交互反馈**：以上任一路径创建后，画布不整页刷新（已是如此），新卡带短暂高亮 + 自动滚入视口。

### 3.4 顶部工具栏 `+` 的创建菜单设计

`+` 菜单改成分组弹出（替代现有仅“类型下拉+标题”的 `CreateEntityDialog`）：

```
＋
├─ 实体（预设，快捷建）
│   ├─ 人物 👤    ├─ 地点 📍
│   ├─ 物件/物品 📦   ├─ 故事 📖
│   ├─ 风格 🎨   ├─ 规则 ⚖️
│   └─ 参考/设定 📎   └─ ⚙ 更多类型…（自定义类型目录）
├─ 便签 📝        ├─ 文本 Ｔ
├─ 图片 🖼 视频🎬 音频🎙   （素材来源见 §7）
├─ 分组框 ▭
└─ ✨ 让 AI 帮我加实体…   （自由文本描述 → 候选实体，§8）
```

- 顶部放的**预设类型 = “常用类型快捷项”**（不固定死六类，默认六类 + 用户最近创建的 3 个自定义类型）。对应问题 5：**预设类型要能一键创建**。
- “更多类型…”进自定义类型目录（见 §5），可多选一次建多个。
- 创建即落到视口中心（或点击处），卡片进入**命名态**（title 就地可编辑 + 黄色高亮虚线框）→ Enter 提交，Esc 收起为空卡。

### 3.5 卡片操作手势（完整）

| 手势 | 行为 |
| --- | --- |
| 单击 | 选中 → 右侧详情面板显示该实体 |
| 双击卡片体 | 进入实体容器（若为容器实体） |
| 拖动卡片体 | 移动卡（几何持久化，已实现） |
| 拖动四角 | 缩放卡（已实现，4 角；建议限制缩放范围且文字随之缩放保持可读） |
| 右下 / 右侧 `+` 手柄拖出 | 松手在实体上=建关系；松手在空白=建媒体元素/字段徽标并连线（已实现，完善见 §6） |
| 右键 | 上下文菜单：编辑标题/进入内部/建立关系/设为封面/展开字段/删除/查看 Canon 版本 |
| Del | 删除（实体删除需二次确认：会级联删除其容器子图与连线，提示影响范围） |

**删除的语义（重点）**：删除实体卡 ≠ 删除实体。给出二次确认：“删除会同时移除该实体的子图（N 个实体、M 条关系、K 个媒体元素）。画面删除 / 彻底删除？” —— 默认“画面删除”（仅移除卡，语义仍在，可从资料库/表单找回）；“彻底删除”需输实体名确认。

## 4. Link / Relation 设计（问题 2）

### 4.1 Link 的完整类型谱系

在现有“实体↔实体语义边（`world_relations`）”之上，Link 统一为画布上“任何两个锚点之间的有向连线”，共 4 层：

| 层级 | 语义 | 两端 | 落库 | 产 revision |
| --- | --- | --- | --- | --- |
| **R. 实体关系 Relation** | 语义关系（朋友/位于/出现在/引用…） | 实体↔实体 | `world_relations` | ✅ |
| **A. 属性绑定 Attribute** | 实体字段值的外部化 / 证据挂载 | 实体↔媒体元素 / 实体↔文本 | `world_canvas`（edge）+ 可选 `world_evidence` | 收录时 ✅ |
| **M. 媒体-作品引用 Media ref** | 素材与“生成的成片/图片/声音”的引用 | 媒体元素↔实体（如“这个设定图由它生成”） | `world_canvas` edge | ❌（或可选用 evidence） |
| **F. 自由连线 Free arrow** | 纯版式标注（不表达语义），分组/说明用 | 任意 block | `world_canvas` (arrow) | ❌ |

视觉上：
- **R 层**用**实线 + 关系标签**（中点 pill，现有实现），线的颜色可按关系分组着色（people=玫红 / world=青 / story=橙 / video=紫，可配置），当前灰色为降级方案，建议按分组上色以便扫读。
- **A 层**用**虚线 + 小圆点**（表示“这条线指向的字段/证据”），颜色取实体类型色。
- **M 层**用**点线**。
- **F 层**无标签细灰线。

这样在画布上一眼可区分“语义事实”“字段证据”“作品痕迹”“版式标注”。

### 4.2 Link 的建立方式（多条路径）

1. **工具栏 Link 工具**：点起点实体 → 点终点实体，自动弹 `RelateDialog`（选关系类型），支持**连续连多条**（Esc/点空白退出），支持把同一条关系反选方向。
2. **`+` 手柄拖到另一个实体**：松手即 `RelateDialog`（现有路径）。
3. **右键 → “从此实体建立关系…”**：终点用“实体选择器”（可搜索最近/同层/全部）。
4. **终点双击语义化创建**：从“林小满”的 `+` 拖到空白，若附近有新建的“北京”卡且它是 location，自动建议 `located_in`/`appears_in` 等最相关类型（按类型组合排序候选，如 character→location 优先 located_in / appears_in / visited）。
5. **关系标签直接改**：点关系标签 pill → 可就地切换到其它类型（等于改关系类型，写 `world_relations`）。
6. **双向展示**：关系默认单向箭头；`relate` 性质对称的关系（如 spouse/friend）显示双箭头或用户可切换箭头样式。

**关系类型候选排序规则**：根据 from kind → to kind 的组合给出 Top-4（如 character→character：friend/partner/spouse/father…；character→location：located_in/appears_in/owns…；character→story：appears_in/created_by…），用户仍可展开完整词表（23+ 项 + 自定义）。

### 4.3 连线几何与维护

- 锚点：实体卡边缘吸附点（上/下/左/右 + 可按需求 8 向）；已有 anchor/bend 几何持久化机制复用。
- 拖动端点可重新绑定到另一实体（改绑 = 先删旧边再建新边，或支持“重新连接”手势）。
- 被连的实体被删除/画面移除 → 该边自动悬空/级联处理（见 3.5）。
- 同对实体允许 0..N 条不同 type 的边；同 type 去重（现有逻辑）。
- 标签过多重叠：关系标签支持“精简模式”（汇聚成实体角上的关系计数徽标，hover 展开列表）。

### 4.4 关系类型词表演进

- 现有 23 项受控词表保留，按组展示（people/world/video/story）。
- 支持自定义关系类型（现有 `relationType` 允许自定义字符串）：新建入口在 RelateDialog 底部 “＋ 新关系类型…”。
- 词表按需补充高频“物件/财物”“位置成员”语义（在 RFC 基础上扩充到约 30 项即可，不追求全量本体论）。

## 5. 预设 Entity 类型与可扩展字段（问题 5）

### 5.1 预设类型的字段契约（默认给一套“够用且通用”的属性）

现有 server preset schema（`service/worlds_canvas.go`）已定义雏形，产品化时对齐并补全为一套**稳定默认属性**。每个预设 = 「确定属性（内置 schema）+ 通用可扩展属性（自定义字段）」。

| 类型 | 稳定默认字段（确定属性） | 说明 |
| --- | --- | --- |
| **人物 character** | 外貌 appearance / 性格 personality / 声音 voice / 职业 / 背景 / 口头禅 | invariant 不变项作为特殊子集 |
| **地点 location** | 描述 description / 氛围 atmosphere / 年代 / 关键细节 | |
| **物件 object**（新增 preset） | 描述 / 材质 / 来历 / 用途 / 重要时刻 | 现 reference 预设替代，见下 |
| **故事 story** | 前提 premise / 关键时刻 moment / 情绪 emotion / 梗概 | |
| **风格 style** | 视觉 visual / 指引 guidance / 避免 avoid | 供后续 AI 生成消费 |
| **规则 rule** | 规则正文 text / 适用范围 / 违者结果 | |
| **参考 reference** | 一句话描述 + 1..N 条证据/链接 | 保留，作为“临时材料箱” |

> 注：`character/location/story/style/rule` 六个 preset 的**类型标识**保留（避免数据迁移）；“物件”建议新增 `object` 或暂时用 `reference` + `baseKind` 表达，二选一见开放问题 Q1。

### 5.2 通用可扩展属性（所有类型通用）

在每个类型的确定属性之上，追加一套**与类型无关的通用属性**，任何实体都可用：

- `custom_fields`：键值对（key=中文标签 + value + valueType: text/number/boolean/date/media/select）。
- `aliases` 别名（同名异写）。
- `tags` 标签。
- `notes` 自由备注。
- 实体级 `media_attachments`：可挂任意数量图片/视频/音频，每个带 purpose + 是否 primary。

字段类型沿用 `EntityTypeField.type`（text/textarea/number/boolean/select/multi/media/invariant），保持与 `entityTypes` 契约一致。

### 5.3 如何在画布上管理字段值

- 详情面板是字段编辑主场（见 §6）。
- 卡片上的字段 chip 可被选中聚焦到详情面板对应字段并高亮。
- 拖「字段行」出来可**外化为画布上的 attr 徽标/媒体元素**（见 §6），形成字段↔证据 Link。
- 字段值支持来自 AI 生成/补全（见 §8）：在字段输入框旁提供 “✨ 智能补全”。

### 5.4 自定义类型（用户自定义目录）

- 用户可在“更多类型…”里创建自定义类型（复制预设或从零定义字段集合），等同 `entityTypeTypes.upsert`（现有能力，需 UI）。
- 顶部 `+` 会把用户最近常用 / 最近创建的自定义类型提升为快捷项（3.4）。

## 6. 详情 Panel 设计（问题 3）

### 6.1 整体结构

右侧 320px 固定面板，**先读后写**：未选中时显示上下文总览（World 卡）；选中后分层展示。Panel 顶部的选中对象名可随时就地改名。

```
┌──────────────────────────┐
│ 林小满            [编辑] ✕ │   <- 标题 + 打开表单视图入口 + 关闭
│ 👤 人物 · 容器(3)  修订 abc │   <- 类型 / 子项数 / Canon 版本徽标
│ ┌──────────────────────┐ │
│ │ 摘要 summary      [✎] │ │   <- 展开两行可编辑
│ │  · 草稿              │ │
│ ├─ 字段 FIELDS ────────┤ │
│ │ 外貌      关键词…   [✎]│ │   <- 每行：label + 值摘要 + 就地编辑 + 外化+ 
│ │ 性格      …          │ │
│ │ ＋ 添加字段（选类型）  │ │
│ ├─ 证据 / 图库 ────────┤ │
│ │ [缩略图 ×n]   [＋添加] │ │   <- 添加媒体：上传 / 素材库 / AI 生成 / 已有元素
│ ├─ 子实体 (容器) ───────┤ │
│ │ 关系对象们…    [进入]  │ │
│ ├─ 关系 ──────────────┤ │
│ │ 林小满 → 北京 [located_in] │ │
│ └─ 事件时间线?─────────┘ │
│ [进入内部] [在画布定位]    │   <- 底部动作
└──────────────────────────┘
```

### 6.2 四态内容（继承现有四种 body 并补齐可编辑性）

| 选中 | 展示 | 可编辑 |
| --- | --- | --- |
| **World**（空选/根） | 类型/描述/Canon 状态/实体统计 | 描述、世界级快捷动作 |
| **Entity** | 见 6.1 | 标题、摘要、字段、添加字段、添加证据、进入容器、建立关系 |
| **Relation** | 类型/方向/scope/两端实体 | 改类型、换方向、换 scope、删除 |
| **Canvas 元素**（便签/文本/媒体/图形/attr） | kind、内容、连向实体 | 便签/文本正文就地编辑；媒体重新选择素材；attr 解除外化（还原为字段值）；删除 |

### 6.3 编辑状态的交互细节

- **就地编辑 vs 弹层**：单行字段（标题、职业）就地编辑；textarea（摘要、性格、描述）在 panel 内展开编辑区；**不跳出表单视图**（除非点右上“打开表单视图”才切到 `world-detail-client` 的 form）。
- **每处编辑 = 一次 revision**：字段级保存（保存按钮 / Cmd+Enter / 失焦防抖）后写 `world_entities`，版本徽标变化可见。
- **外化按钮 `⇥`（每字段行尾）**：把该字段做成画布上的 attr 元素并自动连 A 层 Link，用于把关键设定“钉”到画布叙事位。同样可把字段中的一段文本/图外化为普通 Text/Image 元素。
- **空字段引导**：面板内“＋ 添加字段（选类型）”支持从实体类型的字段 schema 选取，也支持自定义字段。
- **图片区**：点缩略图放大预览；拖到画布即外化为 Image 元素（A 层 Link 到该实体的对应 evidence purpose）；设定主封面（identity primary）；更换来源（素材库/URL/生成）。

### 6.4 关联信息入口

- 列表里的每个关系都可点选 → 面板切到 Relation body；点对端实体名 → 跳到该实体 body。
- “子实体”区点击 = 进入容器（等价双击卡）。
- “在画布定位”：若该实体有卡但被移出视口，点击后画布平移缩放定位高亮。

## 7. 进入 Entity 内部的体验（问题 4）

### 7.1 容器语义（两种模式）

实体 = **容器（容器子图）+ 身份卡（全局卡）**。进入实体后有**两种心智**，UI 要同时满足：

1. **组织结构**：像文件夹 —— 我看到“林小满”的**子实体**（她的物品、她的圈子、她的关键台词本）。
2. **编辑作品**：像页面 —— 我看到她的**属性、证据与关系**。

设计：进入容器后，画布切换为该实体的**局部子图上下文**（`contextId=entity`，已有机制），并：

- **顶部保持一张“宿主卡”**（画布左上角固定，像“锚点”）：显示当前容器实体名与类型、summary 一行、封面；点它 = 回到该实体卡所在的外层并定位。它允许你随时知道“我在谁的内部”。（不参与连线，仅导航，可收起。）
- **子实体与嵌套**：容器内的子实体拥有相对位置；它们仍属于该实体（`parent_id`），语义进入 Canon。
- **证据/媒体也放进容器**：该实体的 identity/appearance/voice 等 evidence、媒体元素默认一起展示（A 层 Link 在这里最自然）。
- **徽章与导航**：面包屑 `World → 林小满` 可见（已有顶栏）；深链路 `World → 林小满 → 项链` 逐级进入。

### 7.2 嵌套深度与去迷失

- 限制建议：**默认视觉深度 1 层**（进入后只见直接子实体），深层靠双击逐级下钻 + 面包屑逐级返回。
- 视觉锚点：宿主卡 + 面包屑 + 画布顶部一行“路径”。加“⬆ 返回上一层”快捷键（Esc 有歧义，用 Cmd+[ 或左上）。
- “跨容器引用”在容器内不展开（子图是局部的）；要用外层的实体请到根视图连线，或把外层实体的投影拖进容器作为“引用投影”（可选 v2）。

### 7.3 进入/退出的动作入口统一

| 入口 | 行为 |
| --- | --- |
| 双击实体卡 | 进入容器（卡有子项） |
| 详情面板「进入容器」 | 同上（仅容器实体显示该按钮） |
| 面包屑 | 返回任意上层 |
| 宿主卡点击 | 跳回实体卡所在外层并定位 |
| 键盘 `Cmd+[` / 按钮 ⬆ | 上一层 |

### 7.4 “根视图 = 世界的总览”

- 根画布（`context=""`）展示 World 核心节点 + 顶层实体（parent_id 为空的）。
- 顶部一个**结构开关/大纲侧栏（可选 v1.5）**：左侧大纲树（缩进层级：实体/子实体/媒体）点击=定位/进入，方便跳深。列在 Roadmap 而非 P0。

## 8. 基础元素（文本 / 图片 / 视频 / 音频）体验（问题 7）

### 8.1 元素类型与“三态”地位

基础元素在画布上是**自由元素**，可三种地位并存：

| 地位 | 语义 | 例子 |
| --- | --- | --- |
| **独立材料** | 未绑定实体的自由资料 | 一段灵感文本、一张参考图 |
| **证据（evidence）** | 已收录为某实体证据，带 purpose/status | 林小满的参考照片（identity, primary） |
| **作品引用** | AI/平台产出的图/视频/声音，标注来源 | “这张氛围图是我用 XX 生成的” |

落地：
- 未收录 = `world_canvas` 元素（不产 revision）。
- 收录 = 元素 + 链接到实体 + 写 `world_evidence`（产 revision）→ 细节见 §6.3 外化/收录逻辑。
- 作品引用 = 元素 props 记录 `producer: {app, jobId, prompt}` + M 层 Link。

### 8.2 添加方式（多渠道）

| 渠道 | 交互 |
| --- | --- |
| 顶栏 `+` | 菜单里选 图片/视频/音频/文本（8.3） |
| 拖拽文件进画布 | 整块投放；放在实体卡上=直接作为该实体 evidence 收录（快捷！） |
| 拖拽素材库 Asset 进画布 | 从右侧素材库/资源面板拖入（素材库集成，见 §8.5） |
| 从 `+` 手柄（实体） | “为此实体添加 [图片/音频/文本]” → 落元素 + A 层 Link |
| URL 粘贴 | 粘贴一个图片 URL → 询问“作为自由素材 / 作为某实体 evidence / 作为 reference” |
| AI 生成 | `+` 菜单“✨ 生成图片 / 生成视频 / 配一段旁白…”，产物落成媒体元素（见 §8.4） |
| 已有元素复制 | 复制/克隆自由元素及其引用 |

### 8.3 文本元素

- **添加**：`+`→文本；或在实体 `+` 手柄拖出选“文本”→ 元素带 A 层 Link。
- **显示**：普通文本块（自由换行、可设字号/色/高亮、可折叠长文）。区别于便签（便签=随手待办、默认黄、可 Promote）；文本更“正式”、中性。
- **就地编辑**：双击进入编辑，Cmd+Enter 保存。这是实现空缺之一（README 承认 inline text 缺失），但建议文本正文双击就地编辑，字段值则走详情面板。
- **格式**：markdown 子集（加粗、列表、链接），不引入富文本引擎。
- 文本可被提升为实体（Promote：title=首行）。

### 8.4 图片 / 视频 / 音频媒体元素

- **显示**：图片=等比缩略（可设 cover/fit/contain），视频/音频=占位卡（播放图标 + 时长 + 波形或首帧），支持点击预览浮层（播放器）。
- **就地基础操作**：替换素材 / 裁切对齐方式 / 置为实体封面 / 收录为证据 / 作为 AI 生成参考。
- **文件落位**：画布元素引用的是素材库 Asset（assetId）或 URL；**本地/粘贴文件先入素材库**（复用 `media.import_*`），再落元素，不搞画布私有二进制。

### 8.5 AI 生成交互

在媒体元素卡右键或 `+` 菜单提供“✨ 生成”入口：

| 生成 | 输入 | 产出 |
| --- | --- | --- |
| 图片 | 一句话描述 +（可选）参考图 = 已有 evidence/风格 | 候选 2~4 张 → 选一张落卡，并记录 producer |
| 视频 | 提示词 + 时长 + 参考 | 同左（占位直到后台完成，进度态展示） |
| 音频/旁白 | 文案 + 可选音色（复用 Voice 库/本地 TTS） | 落音频元素，可试听 |
| 文本续写/扩写 | 对文本卡“继续写” | 追加段落或给出候选 |

原则：**生成产物默认作为自由媒体元素（不自动进 Canon）**；用户选择“收录为该实体证据”才写 `world_evidence`，避免污染事实库（呼应现有“不得自动将生成结果写入”约束）。

### 8.6 素材来源分层（图片/视频/音频共同的资产层）

- 顶层 `+`→媒体 → 弹**素材来源浮层**：上传文件 / 从素材库选 / 从 URL 粘贴 / AI 生成 / 从该 World 已有 reference/evidence 复用。这统一所有“加媒体”入口，替代现在散落的占位。
- 该浮层 = 8.2 的收口 UI。

## 9. AI 参与（贯穿，非独立模块）

1. **AI 建实体**：描述一段文本 → 结构化为多个候选实体（含 kind、title、summary、字段预填）。
2. **AI 连线建议**：画布上有孤立实体时，被动提示“可能的关系”（依据 kind 组合 + 字段语义），一键确认建边。
3. **AI 补字段**：字段行 “✨ 智能补全”，基于 summary/证据上下文生成候选值。
4. **AI 生成媒体**：§8.5。
5. **AI 承接对话**：在 World 的 Chat 里引用画布对象（未来与 recut Chat/World 集成，列出作为后续 v2，不阻塞本 PRD）。

约束：AI 的一切“写入语义”建议均需用户确认；生成媒体默认不进 Canon（§8.5）；草稿实体/关系可一键整体降级为便签或删除。

## 10. 撤销 / 持久化 / 冲突（产品行为定义）

- **画布布局**（移动/缩放/几何）连续高频写入 `world_canvas`，不产 revision；异常中断不丢失（现有 debounce 机制保留）。
- **语义写入**（实体/关系/证据）每次产 revision；提供 **快照面板**：查看 Canon 历史版本、diff 关键字段、一键回滚到某版本（回滚=新建一条“revert”版本，不做破坏式重置）。
- **撤销栈**：Cmd+Z 先撤销布局 op；跨到语义 op 时弹“将回滚到上一语义版本?” 二段确认。避免当前“undo 只作用于内存投影”的落差。
- 冲突（他人/其他端已改语义）：沿用现有 `WORLD_REVISION_CONFLICT` → 冲突提示条，展示“我的版本 vs 服务器版本”摘要，让用户选择合并方式（保留我的 / 保留服务器 / 双份）。

## 11. 进入门槛：新建世界的引导（Onboarding）

在 World Onboarding 流程之上（现有 `world-onboarding.tsx`），给画布一个“空世界向导”：

1. **三种起点**：空白画布 / “一句话生成” / 从模板（如“古风言情”、“悬疑宇宙”结构模板：预设一批空的 人物×3、地点×2、物件、故事 卡 + 建议关系骨架）。
2. 若从素材/资料开始：先导资料 → “这些资料帮你提取了 N 个候选实体，是否加入画布？”
3. 首 3 次进入画布显示**悬浮引导气泡**（双击进入实体 / `+` 手柄连关系 / 拖文件加图片 三个手势），之后可关。

## 12. 迭代规划（分里程碑）

> 原则：每一里程碑结束都要**可用**；先做“单用户单画布”最稳闭环，再上多媒体与 AI 深链，最后做协同/复用。

### M0 · 打通“画布即编辑”（本周目标，≈2–3 天）
**目标：demo → 可真实录入的最小闭环。**
- [ ] 详情面板从只读 → **可编辑**（标题/摘要/字段/添加自定义字段），字段编辑写 `world_entities`。
- [ ] 顶部 `+` 改造为**分组创建菜单**，预设类型一键建（快捷实体卡 + 命名态）。
- [ ] 卡片标题/便签/自由文本**就地编辑**（双击进入、Cmd+Enter 保存）。
- [ ] 删除二次确认（画面删除 vs 彻底删除 + 影响范围提示）。
- [ ] 清理 demo 痕迹命名（`demo-store` 分离 viewport 状态）；移除“扩展（即将推出）”占位。
- 验收：§1.3 闭环去掉“媒体/AI”部分可走通；全程不开表单视图即可建立世界 + 编辑人物地点。

### M1 · Link 与容器（≈4–5 天）
- [ ] Relation 类型**候选排序**（kind 组合 Top-4）；关系标签就地改类型。
- [ ] **A 层属性/证据绑定 Link**：详情面板字段外化 + 拖放建 A 层边；图片拖到实体=evidence 收录。
- [ ] **进入实体内部**完善：宿主卡 + 面包屑导航闭环 + 容器内子实体相对布局 + 返回入口。
- [ ] 关系标签重叠优化 / 汇聚计数徽标。
- [ ] 预设类型**字段默认补齐**（§5.1 表格），object preset 决策（Q1）。
- 验收：能建立 人物→地点/人物→物件/物件→证据图 三层关系；进入“林小满”内部看到其物件子图并可返回。

### M2 · 媒体真实可用 + AI 创建（≈5–6 天）
- [ ] 媒体元素真实素材链：素材库/URL/拖文件/播放预览；8.2/8.6 收口。
- [ ] 媒体→实体 evidence 收录闭环（含 purpose/status 选择器 UI）。
- [ ] AI 建实体（自由文本→候选卡）+ AI 连线建议 + AI 字段补全。
- [ ] AI 生成媒体落元素（图/视频/音频，含进度态与 producer 记录）。
- [ ] 快照/回滚面板（§10）。
- 验收：从一段文字描述 1 分钟得到一组实体+关系建议并一键采纳；上传/生成媒体并作为证据收录。

### M3 · 打磨与深度导航（≈4–5 天）
- [ ] 大纲侧栏（结构树，跳深定位）。
- [ ] 线色/分组视觉体系落地（§4.1）；自定义关系类型 UI。
- [ ] 键盘与无障碍、缩放性能（大量元素时流畅）、空状态插图与引导气泡。
- [ ] 跨端/多标签冲突合并 UI（§10 二段确认）。
- [ ] 整体走查：撤销栈语义、命名态、悬空边处理、性能回归。
- 验收：500+ 元素画布 60fps 平移缩放；全键盘可操作；冲突处理可用。

### M4 · 高级（非 P0，排期另行）
- [ ] 引用投影/跨容器视图；World 级“素材复用”进入其它创作 App（Recut Editor / Remotion / Voice）**作为 CreationContext 工作台**。
- [ ] 协同（多人实时编辑、光标在场感）—— 需要把 yjs/CRDT 从画布投影扩展到语义层，开放问题 Q4。
- [ ] Chat 内直接 @ 画布对象并双向定位。
- [ ] 本体模板市场（行业模板：人物小传、IP 设定、短剧角色卡）。

## 13. 非目标（本 PRD 明确不做）

## 14. 开放问题（Q）

- **Q1 物件类型**：`object` 作为第 7 个 preset 类型（推荐），还是复用 `reference` + `baseKind` 表达？影响预设 schema、色卡与关系候选。倾向：新 preset `object`，向后兼容旧数据。
- **Q2 实体卡缩放**：允许自由缩放会破坏排版一致性，是否限制为 2~3 档预设尺寸？倾向档位制。
- **Q3 “进入内部 vs 编辑作品”**：容器页是否默认同时展开宿主的 evidence/字段？倾向默认折叠、可展开（M1）。
- **Q4 协同时机**：语义层 CRDT 是否 M4 前投入？倾向先用“版本 + 冲突解决”撑到用户规模信号出现。
- **Q5 删除默认值**：“画面删除”默认可恢复期多长？倾向：语义对象不物理删除（可归档），画面元素可恢复 7 天。
- **Q6 跨 World 引用**：是否需要把“林小满出现在另一个 World”做成画布元素？倾向 v2，根视图暂不表达。

### 15.2 词表（本 PRD 内术语）
