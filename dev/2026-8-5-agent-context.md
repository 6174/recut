# 现状

当前的 Agent 会话是有上下文的，有放在首页的 General 会话，有具体项目内的项目级别会话，也有直接使用的应用级别的会话

为什么会有这样的区分：

- App 本质是一个技能，比如生成 Vox-broll 类的视频，它就是参考一个 skill 来设计的。
- App 本身运行后提供很多 api 接口来互通，这就需要做 MCP 配置 

所以一个 App 或者一个项目本质就是 工具 + skill 的集合，对 AI 来说至少是这样

# 问题

- 如果是在单个应用内或者项目内这样设计是没有问题的，但是现实的场景是，需要将多个 App 互相结合来做设计，这就产生了问题。
- 比如首页的 Agent，它只能做的事情就是创建一个项目，项目内的需要跳转进去才能执行，这就产生了问题，对用户来说很不友好


# 思考

- 所以我在想，是不是不应该把应用或者项目设计成 agents.md 的形式，而是设计为 skill 的形式，它们放在 app 安装包中，无论在哪个场景下都可以获取任意 app 的 skills 
- mcp 是动态注册的，可以获取某个 app 或者项目的 api，不依赖某个具体的项目
- 当然如果是在某个项目右侧打开，它也能获取 getCurrentWorkspaceContext 获取当前在什么位置
- 当然需要考虑 background.js 是在什么时机运行的，因为它是实际对接 mcp api 的
