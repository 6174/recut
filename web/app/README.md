# web/app/

成员清单
工作台数据规则: 项目、App、安装状态、项目详情与独立 App scope 由 `lib/workspace-store` 跨路由缓存；App、项目与已安装 App 的读取结果不可互相污染，安装列表成功返回空数组就是未安装，失败必须保留服务端原因；Provider、Credential 摘要与用途 Route 由 `lib/media-configuration-store` 缓存；首次读取及写操作成功后显式刷新，绝不使用 5 秒轮询。工作台 i18n: 语言偏好是工作台/Service/App 的单一真相，前端真相在 `lib/i18n/locale-store`（localStorage 兜底 + navigator 首启探测），service 持久化经 `GET/PUT /v1/preferences`（`lib/i18n/preferences`）；全部 /v1 请求经 `lib/service-endpoint` 的 `fetchRecutJSON`/`recutHeaders` 附加 `Accept-Language`，服务端错误原因保留由客户端本地化；文案字典在 `lib/i18n/workspace-dict.ts`，组件用 `useI18n()`、非组件用 `useLocaleStore.getState()` + `t()`。
layout.tsx: 工作台 HTML 外壳、全局元数据与品牌图标声明；`<html lang="en">` 保留为工作台默认语言（defaultLocale），`og:locale` 为 `en_US`；body 内挂载 `locale-effect.tsx`，挂载时按 `navigator.language` 探测并初始化语言偏好，随后订阅变化写 `document.documentElement.lang`；`title` 模板为 `%s | Recut`，description 为本地优先 AI 视频工作台，`robots` 默认 `noindex,nofollow`（官网四个 Marketing 页面各自显式开启索引），声明 canonical、og/twitter 默认值、`/manifest.webmanifest`、`icon.png` / `apple-touch-icon.png` 与 `theme-color`；根布局唯一挂载全局工作台壳 `agent-panel-host.tsx`，整体结构为顶部固定 64px Header 横贯全宽、其下 Body 左侧从 Header 下沿向下铺满的全局 Agent 对话栏、右侧内容区（用 `--side-panel-width` 预留左侧空间），页面只经 `lib/agent-panel-context` 声明素材上下文与草稿；官网 Host 会让全局壳移除该对话栏。
路由协议: `recut.video` / `www.recut.video` 是公开官网，内容收敛在 `marketing/[locale]/` 多路由：无语言前缀的 `/` 恒为英文（default，SEO canonical 稳定），中文固定 `/zh/` 前缀；Worker（`web/worker.ts`）与本地 `server.cjs` 按「显式 `/zh/` 前缀 → `recut_locale` cookie（语言切换器写入）→ `Accept-Language`」判定语言，判定中文的无前缀路径 302 到 `/zh/<同路径>/`（302 而非 301，避免改变爬虫对 canonical 的理解），再把 en/zh 路径统一补尾斜杠映射到 `/marketing/<locale>/...` 静态壳；`app.recut.video` 是工作台 Host。开发时 `localhost:3000` 根路径渲染官网，`app.localhost:3000` 渲染工作台；官网永不读取 service，工作台不承载官网内容。`lib/i18n` 提供 Locality 枚举、`localizeURL`（default 无前缀 / zh 加 `/zh/`）与 `t()` 字典；`marketing-dict` 是官网文案字典，`marketing-posts/apps` 是双语言数据源。SEO：`marketing/[locale]/` 各页面导出 `generateMetadata`（title/description/robots/canonical/hreflang 三元组 en/zh/x-default/openGraph `og:locale` 与 `og:locale:alternate`/twitter 逐语言），并在页面外层挂载 `marketing-jsonld`（`inLanguage` 逐语言）；`www.recut.video` 由 Worker 301 到裸域、`/marketing` 别名 404、未知路径 404。`app/robots.ts`、`app/sitemap.ts`、`app/manifest.ts` 在 `output: export` 下生成 robots.txt / 逐语言 sitemap.xml / manifest.webmanifest。
marketing/[locale]/: 官网逐语言多路由；`layout.tsx` 的 `generateStaticParams` 枚举 `["zh", "en"]` 并经 client 的 `MarketingLocaleProvider` 注入 locale、设置 `document.documentElement.lang`；`seo.ts` 是共享的非路由 metadata 构造模块；`page.tsx` 是 Landing，`apps/` 是应用市场目录与 `[appID]` SEO 落地页，`docs/` 是 Docs 入口，`blog/` 是文章列表与 `[slug]` 详情；由双语言数据源逐语言静态生成，安装/使用引导到工作台。
项目卡片约定: 从所属 App 的 manifest 派生图标与应用名称；不暴露内部 app ID，也不重复“继续编辑”操作文案。
page.tsx: 固定桌面双栏工作台；`/` 与 `/projects` 同渲染项目桌面，`/media`、`/community` 共同复用 Header 和各自可刷新状态的内容区，左侧 Agent 面板由根布局的 `agent-panel-host.tsx` 全局 Host 边界挂载为单一会话；该边界保证本组件只会在 `app.recut.video` / `app.localhost` 渲染，官网 Host 即使发生客户端路由也不会挂载本组件。顶部一级 Tab（项目 / 素材库 / 社区）在工作台内更新 URL 和内容，避免 Cloudflare 静态导出环境将切换降级为整页导航；创作台（Studio）暂时隐藏、默认进入项目——`/` 与 `/projects` 都渲染项目桌面，Studio 组件（`webgl-studio-hero.tsx` 分层动态视频背景与按日期稳定的文本引导）代码保留但不再注册入口；内容区统一为单一外部滚动容器（`data-workspace-scroll` + `max-w-6xl`），项目页与素材页共用同一标题/筛选骨架；项目桌面顶部是面向用户需求层的创作场景卡片区（`components/scenario-gallery.tsx` + `lib/scenarios`）：对齐 video GTM 的几个需求场景（栏目复用 / 栏目内容 / IP 角色 / 复刻参考）平铺为卡片，点选后经 `components/scenario-dialog.tsx` 填写结构化表单，只把「场景提示词 + 创作需求」回填左侧创作框，用户可继续编辑且绝不自动提交；首页的 section 是无框的内容节奏层，所有标题、对象网格与空态沿同一内容边缘排列，只有项目、素材和应用能力等可进入实体保留卡片边界；「项目列表」取代“继续创作”，首张永远是和项目页共享、与项目卡同高的「新建」入口；点击后在居中模态框选择项目型 App，点选后直接弹出项目命名框，绝不在卡片下方展开菜单；首页最多展示 11 个最近项目，超出部分经“查看全部”进入完整项目页；首页与项目页共享同一项目卡及 1/2/4 列网格，统一封面比例、信息密度与 More 操作；项目和资源卡统一在右上角提供 More，菜单可重命名或经确认删除；页面同时展示紧凑的最近项目（读取 owner App 设置的 image/video `cover`）与最近 Assets 外显。Projects 独立承载新建项目与完整项目列表（用户自己的 World 与项目混排）；Assets 是原生媒体库；Community 统一承载可扩展分区——PGC Worlds 与 Apps 目录（已安装扩展 + 可添加市场），世界/应用详情路由 `/worlds/[worldID]`、`/apps/[appID]` 保持不变。Agent 为跨路由的单一全局会话，不做按页面的会话过滤，页面只提供素材上传上下文。新建项目使用居中 App 选择模态框，只展示项目型 App，选择后紧接命名弹框创建项目；顶部提供“新建应用”AI Prompt 与“从 Git 安装”入口，后者把 GitHub 仓库交由 service 校验 manifest 并在成功后刷新目录；Git App 目录读取会检测远端更新，检查完成事件会刷新全局目录，详情和卡片可升级单项，远端更新与本地修改并存时明确显示“远端更新”与保护原因，存在可安全更新项时顶部才显示一键更新；素材库不进入 App Catalog、安装管理或 iframe；任何条目均可离线进入详情，service 仅提供安装状态、安装和 Git 更新；cloud mode 首次无法连接本机 service 时，主内容统一展示 ServiceGuide 落地页（由 `components/service-guide` 的 `ServiceGuide` 提供，采用官网首页「不要再靠抽卡做视频、开始经营一个世界」的单核心故事与扁平超大排版，安装 Recut 为唯一主操作，不再逐条罗列能力卡片）——项目 / 素材库 / 市场任一 Tab 都落到该落地页，市场不单独支持离线打开，必须先连上 service；Header 始终是工作区三 Tab（项目 / 素材库 / 市场），不再切换官网式导航，着陆时隐藏 service 状态与设置，设置面板改由落地页的「连接远程工作区」受控挂载；local mode 已与 service 同进程，断连时仍显示真实诊断，不伪装为安装引导；连接中主内容与 Agent 左栏均只显示骨架，连接失败后才显示对应状态；发现 service 更新时继续保留当前核心入口，由 Header 右侧的醒目操作入口触发升级；Header 右侧复用 service 状态与全局设置操作。工作台文案已迁移到 workspace 字典（Tab、项目、Community 目录、云端 Landing 等高频面；Studio 每日灵感与创作场景为内容面，场景入口与表单独立成 `scenario` 命名空间）。
media/: 原生 React Assets 能力；`page.tsx` 是 `/media` 独立入口壳，`media-library-panel.tsx` 为主工作台复用的内容组件；左侧按类型管理跨项目媒体资产，可主动批量上传图片、视频或音频，提交创建后由单条 Recut Asset SSE 原位呈现，活跃 Asset 显示实时用时、终态显示持久化耗时；创建弹框从 `media-configuration-store` 共享读取已连接 Provider 模型，在独立缩略图选择弹框中按需添加参考图，并引导添加缺失 Provider；桌面端左侧复用标准 Agent 会话。
worlds/: 原生 React Worlds 能力；`page.tsx` 是 `/worlds` 到社区世界分区的兼容深链壳，`[worldID]/` 承载单个世界的五个核心区域；用户自己的 World 与项目在 Projects 混排，平台/PGC World 只在社区展示；World 是系统级列表，不进入 App Catalog、安装管理或 iframe。
community/: 社区（Community）一级入口；`page.tsx` 是 `/community` 可扩展分区首页壳，`apps/` 是 `lib/community-sections` 注册的应用分区，`worlds/` 是世界分区；两个分区共用同一个 `Community` 容器与子导航，后续新增板块只需在注册表加一条；分区内容组件在 `web/components/community/`，只展示公共内容（PGC Worlds + Apps 目录），不承载用户资产。
appstore/: `/appstore` 到 `/community/apps` 的兼容深链；应用的主入口是 `/community/apps`（兼容 `/apps`），语义详情路由为 `/apps/[appID]`，身份来自云端市场 `lib/appstore`（`<site>/api/appstore.json`，双语言），只从 service 查询是否已安装并按状态提供安装或创建项目入口。
workspace-app/: 工作区型 App 的独立工作台路由；为 standaloneView 建立不显示在项目桌面的稳定 App scope，复用 iframe 宿主与根布局全局挂载的 Agent 面板，但没有项目创建或项目名称。
projects/: `/projects` 独立项目桌面与单个项目详情的路由边界。
projects/[id]/page.tsx: 项目详情的服务端路由壳；只导出静态站需要的占位参数并挂载客户端容器，不能使用浏览器 API，避免客户端组件导出 `generateStaticParams`。
projects/[id]/project-detail-client.tsx: 固定桌面项目详情客户端容器；从真实项目与 manifest 签发 Work Surface，iframe `focus.report` 只追加局部 Focus，绝不覆盖 projectId/appId；同时承载 App UI、项目事件、素材桥与草稿回填。
Agent 工作面: 顶级 Tab 签发 workspace/media-library Work Surface；项目、World 与 standalone App 子路由签发带稳定 ID 的工作面，当前选区作为独立 Focus 随本次 Turn 发送。
globals.css: 工作台与官网同源的暗色优先设计 token：深色画布、分层面板、明亮品牌绿操作，以及状态色、低圆角、阴影与基础排版；小屏下工作台退化为单栏，Agent 仅保留在桌面工作面。
