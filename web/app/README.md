# web/app/

> L2 | 父级: /web/README.md

成员清单
工作台数据规则: 项目、App、安装状态、项目详情与独立 App scope 由 `lib/workspace-store` 跨路由缓存；App、项目与已安装 App 的读取结果不可互相污染，安装列表成功返回空数组就是未安装，失败必须保留服务端原因；Provider、Credential 摘要与用途 Route 由 `lib/media-configuration-store` 缓存；首次读取及写操作成功后显式刷新，绝不使用 5 秒轮询。工作台 i18n: 语言偏好是工作台/Service/App 的单一真相，前端真相在 `lib/i18n/locale-store`（localStorage 兜底 + navigator 首启探测），service 持久化经 `GET/PUT /v1/preferences`（`lib/i18n/preferences`）；全部 /v1 请求经 `lib/service-endpoint` 的 `fetchRecutJSON`/`recutHeaders` 附加 `Accept-Language`，服务端错误原因保留由客户端本地化；文案字典在 `lib/i18n/workspace-dict.ts`，组件用 `useI18n()`、非组件用 `useLocaleStore.getState()` + `t()`。
layout.tsx: 工作台 HTML 外壳、全局元数据与品牌图标声明；`<html lang="en">` 保留为工作台默认语言（defaultLocale），`og:locale` 为 `en_US`；body 内挂载 `locale-effect.tsx`，挂载时按 `navigator.language` 探测并初始化语言偏好，随后订阅变化写 `document.documentElement.lang`；`title` 模板为 `%s | Recut`，description 为本地优先 AI 视频工作台，`robots` 默认 `noindex,nofollow`（官网四个 Marketing 页面各自显式开启索引），声明 canonical、og/twitter 默认值、`/manifest.webmanifest`、`icon.png` / `apple-touch-icon.png` 与 `theme-color`；根布局唯一挂载全局工作台壳 `agent-panel-host.tsx`，整体结构为顶部固定 64px Header 横贯全宽、其下 Body 左侧从 Header 下沿向下铺满的全局 Agent 对话栏、右侧内容区（用 `--side-panel-width` 预留左侧空间），页面只经 `lib/agent-panel-context` 声明素材上下文与草稿；官网 Host 会让全局壳移除该对话栏。
路由协议: `recut.video` / `www.recut.video` 是公开官网，内容收敛在 `marketing/[locale]/` 多路由：无语言前缀的 `/` 恒为英文（default，SEO canonical 稳定），中文固定 `/zh/` 前缀；Worker（`web/worker.ts`）与本地 `server.cjs` 按「显式 `/zh/` 前缀 → `recut_locale` cookie（语言切换器写入）→ `Accept-Language`」判定语言，判定中文的无前缀路径 302 到 `/zh/<同路径>/`（302 而非 301，避免改变爬虫对 canonical 的理解），再把 en/zh 路径统一补尾斜杠映射到 `/marketing/<locale>/...` 静态壳；`app.recut.video` 是工作台 Host。开发时 `localhost:3000` 根路径渲染官网，`app.localhost:3000` 渲染工作台；官网永不读取 service，工作台不承载官网内容。`lib/i18n` 提供 Locality 枚举、`localizeURL`（default 无前缀 / zh 加 `/zh/`）与 `t()` 字典；`marketing-dict` 是官网文案字典，`marketing-home/posts/apps` 是双语言数据源。SEO：`marketing/[locale]/` 各页面导出 `generateMetadata`（title/description/robots/canonical/hreflang 三元组 en/zh/x-default/openGraph `og:locale` 与 `og:locale:alternate`/twitter 逐语言），并在页面外层挂载 `marketing-jsonld`（`inLanguage` 逐语言）；`www.recut.video` 由 Worker 301 到裸域、`/marketing` 别名 404、未知路径 404。`app/robots.ts`、`app/sitemap.ts`、`app/manifest.ts` 在 `output: export` 下生成 robots.txt / 逐语言 sitemap.xml / manifest.webmanifest。
marketing/[locale]/: 官网逐语言多路由；`layout.tsx` 的 `generateStaticParams` 枚举 `["zh", "en"]` 并经 client 的 `MarketingLocaleProvider` 注入 locale、设置 `document.documentElement.lang`；`seo.ts` 是共享的非路由 metadata 构造模块；`page.tsx` 是 Landing，`apps/` 是应用市场目录与 `[appID]` SEO 落地页，`docs/` 是 Docs 入口，`blog/` 是文章列表与 `[slug]` 详情；由双语言数据源逐语言静态生成，安装/使用引导到工作台。
项目卡片约定: 从所属 App 的 manifest 派生图标与应用名称；不暴露内部 app ID，也不重复“继续编辑”操作文案。
page.tsx: 固定桌面双栏工作台；`/` Studio、`/worlds`、`/projects`、`/media`、`/apps` 共同复用 Header 和各自可刷新状态的内容区，左侧 Agent 面板由根布局的 `agent-panel-host.tsx` 全局 Host 边界挂载为单一会话；该边界保证本组件只会在 `app.recut.video` / `app.localhost` 渲染，官网 Host 即使发生客户端路由也不会挂载本组件。顶部五个一级 Tab 在工作台内更新 URL 和内容，避免 Cloudflare 静态导出环境将切换降级为整页导航；Studio 是默认创作入口，提供由 `webgl-studio-hero.tsx` 绘制的分层动态视频背景和由日期稳定选出的两条轻量文本引导；首访引导与普通创作模板共用同一随机池，不再单设区域。模板池覆盖完整视频、补充画面、Remotion 与剪纸风格等用户熟悉的表达，点击只将创作内容回填左侧创作框，用户可继续编辑且绝不自动提交；首页的 section 是无框的内容节奏层，所有标题、对象网格与空态沿同一内容边缘排列，只有项目、素材和应用能力等可进入实体保留卡片边界；「项目列表」取代“继续创作”，首张永远是和项目页共享、与项目卡同高的「新建」入口；点击后在居中模态框选择项目型 App，点选后直接弹出项目命名框，绝不在卡片下方展开菜单；首页最多展示 11 个最近项目，超出部分经“查看全部”进入完整项目页；首页与项目页共享同一项目卡及 1/2/4 列网格，统一封面比例、信息密度与 More 操作；项目和资源卡统一在右上角提供 More，菜单可重命名或经确认删除；「世界观」是创作应用列表中永远置首的原生能力卡，点击直接进入系统级 Worlds 管理，其后才是已安装 App；已安装 App 使用相同的横向能力卡，卡内并列品牌图标、名称、用途和进入箭头，点击直接打开独立 App 或发起项目创建，详情统一收束到 Apps 管理页；页面同时展示紧凑的最近项目（读取 owner App 设置的 image/video `cover`）与最近 Assets 外显。Projects 独立承载新建项目与完整项目列表；Worlds 是系统级语义列表；Assets 是原生媒体库；Apps 管理已安装扩展与可添加目录。Agent 为跨路由的单一全局会话，不做按页面的会话过滤，页面只提供素材上传上下文。新建项目使用居中 App 选择模态框，只展示项目型 App，选择后紧接命名弹框创建项目；顶部提供“新建应用”AI Prompt 与“从 Git 安装”入口，后者把 GitHub 仓库交由 service 校验 manifest 并在成功后刷新目录；Git App 目录读取会检测远端更新，检查完成事件会刷新全局目录，详情和卡片可升级单项，远端更新与本地修改并存时明确显示“远端更新”与保护原因，存在可安全更新项时顶部才显示一键更新；素材库不进入 App Catalog、安装管理或 iframe；任何条目均可离线进入详情，service 仅提供安装状态、安装和 Git 更新；cloud mode 首次无法连接本机 service 时，主内容展示本地优先的产品 Landing Page：安装 Recut 为唯一主操作，同时介绍开源、可扩展、视频剪辑、世界观与语音克隆能力；Header 同时切换为官网式导航，保留「工作台」(`/`) 返回入口及可离线浏览的「应用市场」(`/apps`)，不显示完整工作台 Tab、service 状态或设置；local mode 已与 service 同进程，断连时仍显示真实诊断，不伪装为安装引导；连接中主内容与 Agent 左栏均只显示骨架，连接失败后才显示对应状态；发现 service 更新时继续保留当前核心入口，由 Header 右侧的醒目操作入口触发升级；Header 右侧复用 service 状态与全局设置操作。工作台文案已迁移到 workspace 字典（Tab、项目、Apps 目录、云端 Landing 等高频面；Studio 每日灵感与提示模板为内容面，后续按语言拆组）。
media/: 原生 React Assets 能力；`page.tsx` 是 `/media` 独立入口壳，`media-library-panel.tsx` 为主工作台复用的内容组件；左侧按类型管理跨项目媒体资产，可主动批量上传图片、视频或音频，提交创建后由单条 Recut Asset SSE 原位呈现，活跃 Asset 显示实时用时、终态显示持久化耗时；创建弹框从 `media-configuration-store` 共享读取已连接 Provider 模型，在独立缩略图选择弹框中按需添加参考图，并引导添加缺失 Provider；桌面端左侧复用标准 Agent 会话。
worlds/: 原生 React Worlds 能力；`page.tsx` 是 `/worlds` 独立入口壳，`worlds-client.tsx` 为主工作台复用的内容组件，`[worldID]/` 承载单个世界的五个核心区域；World 是系统级列表，不进入 App Catalog、安装管理或 iframe。
appstore/: `/appstore` 到 `/apps` 的兼容深链；App 的主入口是 `/apps`，语义详情路由为 `/apps/[appID]`，身份来自云端市场 `lib/appstore`（`<site>/api/appstore.json`，双语言），只从 service 查询是否已安装并按状态提供安装或创建项目入口。
workspace-app/: 工作区型 App 的独立工作台路由；为 standaloneView 建立不显示在项目桌面的稳定 App scope，复用 iframe 宿主与根布局全局挂载的 Agent 面板，但没有项目创建或项目名称。
projects/: `/projects` 独立项目桌面与单个项目详情的路由边界。
projects/[id]/page.tsx: 项目详情的服务端路由壳；只导出静态站需要的占位参数并挂载客户端容器，不能使用浏览器 API，避免客户端组件导出 `generateStaticParams`。
projects/[id]/project-detail-client.tsx: 固定桌面项目详情客户端容器；从真实路径（兼容旧查询串）读取项目 ID，Header 右侧复用 service 状态、全局设置与项目 App 版本升级入口；右侧全高 iframe 承载 App UI，左侧的 Agent 对话栏由根布局全局挂载（可拖拽调宽、持久化宽度），本页只经 context 声明项目 scope、当前页面上下文与回填草稿，并转发项目事件与 iframe 请求；App 经 `page.context` 宿主消息上报更具体的当前编辑页上下文；App API 的结构化失败原因必须透传到 iframe。
globals.css: 工作台的全局设计 token：白色画布、黑色内容、明亮品牌绿操作，以及状态色、低圆角、阴影与基础排版；小屏下工作台退化为单栏，Agent 仅保留在桌面工作面。
