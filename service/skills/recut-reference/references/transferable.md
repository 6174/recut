# 可迁移 vs 不可复制

这支参考里，**什么值得保留、什么必须重做**。本页给判据；真正的「换成什么」由 `recut-director（references/remix）` 决策，本技能只负责把它建立在可核实的观察与参考分析之上。

## 1. 为什么需要这条线

复刻不是抄。抄画面/台词/肖像会侵权、也会水土不服；有价值的是**结构**——让原片有效的那套关系。写作 `ref.transferable` 时，把「结构」与「表面」分开说。

## 2. 可迁移（保留机制）

| 维度 | 判据 | 例子 |
|---|---|---|
| 钩子机制 | 前 3 秒靠什么抓人（断言/数字/悬念/冲突） | 「先抛结论再解释」 |
| 结构节拍 | 主张 → 证据 → 兑现 的推进与节奏 | 「逐项揭示 + 卡词揭示」 |
| 视觉系统的角色 | 某图形/版式在**什么时候、响应哪句话** | 榜单板随名词出现并保留 |
| 声音角色 | SFX/卡点/BGM 跟什么事件绑定 | 揭晓瞬间音效 |
| 情绪路径 | 观众每个节拍的心理状态怎么迁移 | 怀疑 → 惊讶 → 服气 |

## 3. 不可复制（必须重做）

- 源片**台词文案**、**字幕措辞**、**画面构图**、**人物肖像**、**品牌标识**。
- 依赖原片特定事实的笑点/梗（换主体后不成立）。
- 只在原片语境成立的承诺/悬念（无后续承接）。

## 4. 判据句式

写 `ref.transferable` 时用可定位的表达：

- **保留**：`第 2 拍：名词出现时图形入场，保留这一「词↔图形」绑定`
- **替换**：`榜单主体换成我的产品；揭示音效保留，来源换成我自己的 SFX`
- **失效**：`关于原主播外貌的笑点，换人后需重写或删除`

每条都要能指回源片时间（来自 `ref.beats` 的源时间记录）。

## 5. 与目标项目的分工

- 本页产出的 `ref.transferable` 是**参考属性**（可复用，写参考素材）。
- 「本目标具体换哪些、保留哪些」是**目标改造决策**，写目标项目的 `TREATMENT.md`（由 `recut-clone` 在 S2 依 `remix` 判断产出）。
- 不要把它们混写：素材上的是「这段片子的机制」，项目里的是「这次怎么改」。

## 6. 校验

换一个完全无关的话题，若你的「保留机制」仍然成立、而「不可复制」项确实失效，这条线就画对了。以「换话题后仍成立」为无效信号。
