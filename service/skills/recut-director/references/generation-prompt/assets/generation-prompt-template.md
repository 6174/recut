# 生成提示词模板（Generation Prompt Template）

> 本文件归 `references/generation-prompt` 所有，是产出自检的填写形态。规则与边界见同级 `SKILL.md`；`<reference>` 标签属性、role 词表与编号规则见 SKILL.md《参考锚点表达规则》。

## 填写顺序

固定七段，顺序不可调换：

1. `[CAMERA LOCK]`——AI 选定的机身/胶片、镜头焦段、光圈景深、稳定方式，全片一套、逐字复用；
2. `[STYLE LOCK]`——冻结风格全文，逐字复用；
3. `参考锚定表`——每条 `<reference>` + 角色声明；
4. `镜头基调`——全段镜头纪律，声明一次（允许的机位/运动、轴线与屏幕位置、一镜一主导运动）；
5. `声音设计`——全段底声声明一次 + 分镜局部声逐镜；
6. `镜头序列`——每镜一行，以片段时间轴累计区间 `[起~止s]` 领起；区间内写清景别/机位、单一主导运镜、主体唯一变化，以及画面内每个可见面的具体内容；**需要可读的画内文字逐字写死**；区间由内容定、连续相接，不每镜套同一常数；
7. `[负面约束]`——本片/本镜真实风险，约 4–6 类。

## 骨架

```text
[CAMERA LOCK]
<AI 选定并逐字复用：机身或胶片（ARRI Alexa / Sony FX3 / Kodak Portra 400）+ 镜头焦段（如 35mm 定焦）+ 光圈与景深 + 稳定方式（三脚架 / 滑轨 / 手持 / 机械臂）+ 镜头畸变与呼吸>

[STYLE LOCK]
<stock/胶片/LUT/颗粒/镜头/画幅/光比/调色/氛围/物理规则，逐字冻结>

参考锚定表
<reference id="__" kind="image" role="pov"        label="__" /> 作为 __ 视角锚定。
<reference id="__" kind="image" role="color-card" label="__" /> 作为整段画面色卡锚定，所有色彩严格按色卡执行。
<reference id="__" kind="image" role="environment" label="__" /> 作为环境视角锚定。
<reference id="__" kind="image" role="character"  label="__" /> 作为 __ 视觉锚定。
<reference id="__" kind="audio" role="voice"      label="__" /> 作为 __ 音色锚定。

镜头基调
<全段声明一次：允许的机位与运动（固定 / 慢推 / 慢拉 …）；轴线与主体的屏幕位置；一镜一主导运动；禁止手持抖动与无意义漂移。>

声音设计
<全段底声，声明一次：贯穿整个片段的持续环境底声 + 有无 BGM 与气质；无 BGM 时明确写出。>
<分镜局部声，逐镜：用与镜头序列一致的区间标出因果点动作声 / 局部环境变化 / 对白，如 [0~3s] <……>；[3~7s] <……>。>

[0~3s] <景别/机位（高度、相对位置）与单一主导运镜（方式/方向/速度/参照对象/落点景别）；主体的起始状态、唯一可见变化、结束状态；画面内每个可见面的具体内容（屏幕/界面/道具/材质/光源）；需要可读的画内文字用引号逐字写死，单条 ≤ 约 15 字并逐条给位置与层级>
[3~7s] HARD CUT。<承接上一镜结束状态；同上写全>

（区间连续相接、总和即片段长度，按内容定、不每镜套同一常数；默认一条多镜连续段；段内切换默认 HARD CUT）

[负面约束]
<具体对象 4–6 类；通用：签名/水印/角标/图标/电量/时间；「无文字/无字幕」仅在本镜不需要可读画内文字时才加，要了可读文字就别写它>
```

## 示例（时间区间 + 细节密度）

同一个「低头看手机」的场面，粗写与写足：

> 粗写：第 1 镜，约 4 秒。全景，缓慢推近。他在看手机。

> 写足：
>
> [0~4s] 客厅全景、平视，蓝色旧沙发压住画面下 1/3，画面右侧墙面留黑；机位在三脚架上从沙发正前方极缓慢推近到中景，只推尺度、无横向漂移。主体：圆头小人瘫坐沙发里低头看手机，呼吸极轻地起伏；手掌里握着手机，冷白屏光只照亮他的下颌与两根拇指。手机屏上是一条**白色细线构成的通讯录列表**，共四行，最上一行被一个更细的白框圈住，屏幕没有可读文字；屏幕亮度在第 3 秒轻微闪动一次。
>
> [4~7s] HARD CUT。手机屏幕近特写，画框里只有屏幕与拇指，冷白屏光是画面唯一光源。拇指沿列表**从下向上缓慢滑动约一行**，四行一起上移、最上一行滑出画框顶端；拇指停在第 3 行上，列表静止。

区间连续相接（0–4 + 4–7 = 7s），每镜都写满了可见面：屏幕上是几行、框在哪里、手指停在哪一行、光落在哪些面。

## 示例（画内文字要可读时）

上面那一镜是「不需要可读文字」的一支。当观众**必须读到**屏幕/招牌/包装上的字时，判支不同、写法也完全不同：文字载体只给「是什么界面」不给具体字，是最典型的糊字来源。

> ❌ 未完成：`手机屏幕上显示微信聊天界面，别人发来一条新消息。`
> 没给任何具体文字，模型只能自己编 → 出图是几行糊成一团的伪汉字（qc 的 F11）。

> ✅ 写死：
> `手机占满画面宽度，屏幕内是深色主题的微信聊天界面。顶部导航栏居中一行白色中文字「文件传输助手」；下方三个聊天气泡依次为：左对齐的浅灰色气泡内黑色中文字「明天的会议改到下午三点了」，右对齐的绿色气泡内白色中文字「收到，我把材料准备好」，左对齐的浅灰色气泡内黑色中文字「记得带上合同原件」；屏幕底部是输入栏，右侧一个绿色圆形发送按钮。`

四条都在：准确原文（引号）、一条一句且都短、逐条给了位置与层级、载体占满画幅宽度保证每字有足够像素。实测同模型/同画幅/同 seed，只改这一句——前者糊字，后者逐字正确。

改写后**记得同步负面词**：要求了可读文字就不能再写「无文字/无字幕」，换成「无乱码文字、无错别字、无重复文字」。

## 提交形态（resolver 输出）

正文里的 `<reference>` 在提交时被改写为组内编号别名：

```text
参考图1 作为执明视角锚定。
参考图2 作为整段画面色卡锚定，所有色彩严格按色卡执行。
参考图3 作为环境视角锚定。
参考图4 作为丹朱视觉锚定。
音频1 仅用于参考执明的音色特征。
```

同时提交 `referenceIds = [a1, a8, a2, a3, a6]`（image 段按编号顺序 + audio 段），顺序与别名编号严格一致。
