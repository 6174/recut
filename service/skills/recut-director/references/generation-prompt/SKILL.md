# Recut 全局生成提示词技能（references/generation-prompt）

本技能只回答一个决策问题：**一条交给图片/视频生成模型的生产级提示词怎么写？** 输入是已确认的镜头意图、场景/人物资产与参考素材，输出是一条可直接提交的提示词（含摄影机与镜头锁、固定风格块、参考锚点表、镜头基调、声音设计、多镜连续段与负面约束），以及机器可校验的参考绑定。

它是 `references/shot`（模型中性镜头意图）与各 App 模型方言之间的**落格层**：把「怎么拍」翻译成「模型读得懂的提示词形状」，但不写 provider 参数语法。

提示词是**一份交给摄影、灯光、声音与表演部门共同执行的导演说明书**，不是画面摘要：它必须同时说清「用什么拍、画面里谁在动、镜头怎么走、耳朵听到什么、这段时长怎么花」。其中**用什么拍（机身、镜头、胶片/质感、稳定方式）由 AI 主动选型并全片锁定**，见《摄影机与镜头选型》。只写画面、不选器材、不写镜头运动与声音，等于把导演决策交还给模型随机发挥。

## 边界声明

| 归属 | 内容 | 说明 |
|---|---|---|
| **本技能** | 生成提示词的形状与锚定 | [CAMERA LOCK] 摄影机与镜头锁定、STYLE LOCK、typed 参考锚点、片段时长预算与多镜连续段、镜头基调、声音设计、负面合同与提示词自检 |
| **references/shot** | 镜头意图 | 景别/角度/焦段/运动/调度/分镜连续性；本技能消费其结论，不重写镜头决策 |
| **references/story / hooks / editing / captions / sound / platform** | 故事、钩子、剪辑、字幕、声音、平台 | 各归其口；本技能只在提示词需要时引用其结论 |
| **各 App 适配层** | provider 方言 | `modeType`、负面词字段、`ratio/resolution` 传参、别名模板；本技能只写意图与引用，不写技术参数 |
| **references/qc** | 失败诊断与门禁 | 本技能产出自检；成片验收走 qc 的 F-code 与门禁 |

未验证的 provider 能力不冒充支持；本技能不出现任何 App 工具调用、时间线 op 或代码语法。

## 输入前置（缺一不写）

1. **已冻结的视觉风格**：来自立项模板 `styleTemplate.visualPrompt`、`LIGHT_INVARIANT` 或导演风格文件的稳定视觉语言。若没有，先回到立项/视觉设定阶段冻结，**不允许每镜临时重写风格**。
2. **场景的镜头意图**：景别、机位、主导运动、起止构图（来自 `references/shot` 的分镜表）。
3. **参考素材与角色**：每条引用有稳定 `id`、`kind`、`role`、`label`（见《参考锚点表达规则》）。**世界语境为硬前置**：先 `recut.worlds.get({ worldId })` 读 `references[]`；画面会出现主角色时必须带该角色参考图（`role="character"`），世界已有场景/风格/色卡锚点按 role 带入；**角色有台词/旁白时必须带声线参考（`role="voice"`，取实体 `voice_reference` 字段；`sfx`/`music` 按需）**，且对白/旁白必须用该声线，不静默换默认音色；只有明确不出现任何角色的纯空场景才可无参考。
   **克隆/仿拍的镜头语言必须真绑定**：迁移一支参考时，把它的帧/接触表/片段连成真实参考——`style-ref`（调色/质感/视觉语言）、`motion-ref`（运镜/动作时序，视频参考）、`storyboard`（构图/调度）；只在正文用「电影感/压迫感」等形容词描述，不构成可执行镜头语言，等于没迁移。
4. **声音资产**：对白逐字文本、音色参考 id、环境/SFX 清单。提示词的底声与局部声必须由它推出（见《声音设计规则》）。
5. **画幅与时长**：画幅与片段总时长由项目配置/宿主传参决定，**不写进提示词正文**；但**片段长度必须先在纸面按内容定**（落在模型单次上限内，见《片段时长预算与多镜连续段规则》），正文**按片段时间轴逐镜标出累计区间**（`[起~止s]`，如 `[0~3s]`、`[3~7s]`）。区间是这一条连续段内部的时间分配、连续相接，不是固定切片，也不在正文另写总长。

## 提示词固定结构

每条提示词按同一顺序构造，段落之间空行分隔：

```text
[CAMERA LOCK]
<AI 选定的拍摄器材与光学性格，逐字复用：机身/胶片 + 镜头焦段 + 光圈与景深 + 稳定方式（三脚架 / 滑轨 / 手持 / 机械臂）+ 镜头畸变与呼吸>

[STYLE LOCK]
<冻结的视觉风格全文，逐字复用，全片所有镜头一致>

参考锚定表
<每行一条：<reference id kind role label /> 作为 <role 中文名> 锚定>

镜头基调
<全段镜头纪律，声明一次：允许的机位与运动（固定 / 慢推 / 慢拉 …）；轴线与主体的屏幕位置；一镜一主导运动；禁止手持抖动与无意义漂移>

声音设计
<全段底声，声明一次：贯穿整个片段的持续环境底声 + 有无 BGM 与气质>
<分镜局部声，逐镜：用与镜头序列一致的时间区间标出该区间因果点上的动作声、局部环境变化与对白位置>

<镜头序列>
按片段时间轴逐镜写，每镜以累计区间领起，区间连续相接、总和即片段长度：
[0~3s] <这一区间的完整画面：景别/机位（含高度与相对位置）与单一主导运镜（方式/方向/速度/参照对象/落点景别）；主体的起始状态、唯一可见变化与结束状态；画面内每个可见面的具体内容（屏幕/界面/道具/材质/光源）>
[3~7s] HARD CUT。<同上写全，并承接上一镜结束状态>

[负面约束]
<本片/本镜真实可能出现的风险项，名字具体、数量约 4–6 类>
```

- 顺序不是装饰：先生成条件（器材、风格、参考）后创作纪律（镜头、声音）再内容（动作），负面最后；与 `keyframe-prompt-template` 的九槽位同源。
- **[CAMERA LOCK] 由 AI 选型并锁定**：机身/胶片、镜头焦段、光圈景深、稳定方式逐字复用，全片一套；放在 [STYLE LOCK] 之前，选型规则见《摄影机与镜头选型》。
- **镜头基调与声音设计各声明一次**，对整段生效；每镜只写自身变化，既不重复全局纪律，也不遗漏本镜的局部声。
- **每镜以时间区间领起、以完整画面内容写实**：行首是片段时间轴上的累计区间 `[起~止s]`（连续相接、无空档），区间内写清景别/机位、单一主导运镜的起点与落点景别、主体的唯一可见变化，以及画面内每个可见面的具体内容。只写「缓慢推近」而不写起点、方向与终点，或只写「他在看手机」而不写屏幕上是什么，均视为未完成。
- **一镜一主导运动**；复合运动必须写清阶段顺序与衔接点（见 `references/shot`）。
- 段落切换默认 HARD CUT；写清每镜结束状态 = 下一镜起始状态（首尾帧合同）。

## 摄影机与镜头选型（[CAMERA LOCK]）

提示词的器材与光学性格是 AI 的主动选择，不是留给模型的空白。选型写进 `[CAMERA LOCK]`、放在 `[STYLE LOCK]` 之前，全片逐字复用：

1. **AI 主动选型**：按题材、情绪、年代与媒介选定**一套**主配置——机身或胶片（ARRI Alexa / Sony FX3 / Kodak Portra 400）、镜头与焦段（如 35mm 定焦）、光圈与景深、稳定方式（三脚架固定 / 滑轨慢推 / 手持轻晃 / 机械臂）、镜头畸变与呼吸；质感（颗粒/光晕）与 STYLE LOCK 呼应。缺 shot 决策时按题材自选并给出理由，不空着。
2. **一套为主、克制**：全片一套器材与镜头性格，不堆三台机身或五个焦段；确需景别跳变时可增加焦段，并在《提示词固定结构》的镜头基调里说明。
3. **与 `references/shot` 分工**：景别/角度/每镜运动由 `references/shot` 决定；本块只锁「用什么拍」的器材与光学性格，不重写景别与调度。
4. **非写实媒介同样要写**：动画/手绘/3D 也能写等效的光学与质感（如 `35mm film, 50mm, f/2, subtle grain`），不必是真实机型，但必须写死、可复用。
5. **不进 provider 参数**：`ratio/resolution/时长` 是 App 适配层传参，不写进 [CAMERA LOCK]；器材与光学是创作语言。

## 画面细节密度（每个可见面都要有定义）

镜头序列写不细，根因通常不是镜头少，而是**画面里出现了没有被定义的可见面**。只要画面里有一块屏、一张纸、一面墙、一个包装、一件道具、一处光，它就必须被写出来；没写的部分由模型随机发挥，成片就会漂移。

「他在看手机」把整块屏幕交给模型瞎猜，是未完成；必须写清屏幕上是什么、手指停在哪一行、冷白屏光照亮了哪些面。**每一个可见面都要能回答「上面具体是什么」。**

- **一镜一格，逐面点名**：按前景—主体—背景清点这一镜所有可见面，逐面给出可观察内容；不写「等等」「杂乱的背景」这类省略。
- **屏幕/界面/文字载体必须给内容**：手机、电视、显示器、招牌、菜单、书页、包装、标签，写清上面是什么（图形、列表、图标、数字、留白、色块）。**先判「要不要可读文字」再落笔，按《画内文字》两支写法之一走**：需要观众读到就逐字写死；不需要才用**无字可画的视觉编码**（例如「白色细线列表 + 一条被细白框圈住的条目」）并声明屏幕无可读文字。两支都不写、只留一句「手机屏幕」，等于把整块屏交给模型瞎猜。
- **道具与材质给状态**：热气、烟灰、磨损、反光、干湿、新旧、持握手别与手指位置。
- **光给来源与落点**：唯一光源是什么、在世界的哪个方向、照到哪些面、哪些面落在暗部。
- **每句都要改变可见或可听结果**：删掉后不影响画面的形容词不写；把空泛质量词（「氛围感」「电影感」）换成具体的面、物、光、动作。

## 画内文字（要可读就逐字写死）

**核心事实：生成模型不会「自己想出合理的内容」，它只渲染你给它的字。** 画面里出现文字载体（屏幕、招牌、菜单、书页、包装、标签、聊天界面）而你只描述「显示了什么界面」、不给具体文字时，模型就自己编——编出来的通常是形似而不可读的伪字形，成片里就是一团糊字/乱码（对应 `references/qc` 的 F11）。**这是「提示词明明写得很足、出来还是糊」最常见的根因，和分辨率、步数都无关：把分辨率调高、步数加上去都救不回来。**

因此文字载体先判支、再落笔，两支必须选一支，不能都不选：

| 判定 | 写法 |
|---|---|
| **需要观众读到**（用户明确要求画内文字；叙事依赖屏幕/招牌/包装上的信息；目标模型具备文字渲染能力） | **逐字写死**（见下） |
| **不需要观众读到**（只是氛围与质感；模型文字能力弱；不愿承担文字漂移风险） | **无字视觉编码**：写清上面是什么形状、几行、框在哪、高亮在哪，并明确声明该载体没有可读文字 |

**逐字写死的五条**：

1. **给准确原文，用引号**：`「今天下午三点开会，别迟到」`，不是「一条新消息」。语言、简繁、标点都写清楚；改写一字＝错误。
2. **一条一句、宁短勿长**：单条 ≤ 约 15 字，需要多行就分行逐条列出。给一整段长文，模型会开始丢字、重复、或把同一句复读满屏。
3. **每条给位置与层级**：哪一条在哪个位置（顶部标题 / 左对齐气泡 / 右对齐气泡 / 底部按钮）、字号相对大小、颜色、对齐方式。同一个载体里有多条文字时逐条点名，不要让模型自己分配。
4. **载体要给足像素**：文字的**物理占比决定它能不能被读**。写清载体在画面中的尺寸与占比（如「手机占满画面宽度」），必要时推进景别让文字变大。载体只占画面一角、每个字只剩十几像素时，再强的渲染也糊——这是构图问题，不是模型问题。
5. **视频额外声明时间**：哪一镜出现、是否随动作变化、何时消失；跨镜出现同一块文字时，字与位置必须逐字一致。

**反例 / 正例（同一个「低头发微信」的场面）**

> ❌ 未完成：`手机屏幕上显示微信聊天界面，别人发来一条新消息。`
> 模型不知道要写什么字，只能自己编 → 成片是几行糊成一团的伪汉字。

> ✅ 写死：`手机占满画面宽度，屏幕内是深色主题的微信聊天界面。顶部导航栏居中一行白色中文字「文件传输助手」；下方三个聊天气泡依次为：左对齐的浅灰色气泡内黑色中文字「明天的会议改到下午三点了」，右对齐的绿色气泡内白色中文字「收到，我把材料准备好」，左对齐的浅灰色气泡内黑色中文字「记得带上合同原件」；屏幕底部是输入栏，右侧一个绿色圆形发送按钮。`

实测对照：同一模型、同一画幅、同一步数、同一 seed，只改这两句写法——前者出糊字，后者三段中文逐字正确。

- 文字载体不止「屏幕」：招牌、横幅、菜单、价签、书页、包装、车牌、球衣号码、仪表读数、便利贴、涂鸦墙同样适用。
- **画内文字 ≠ 字幕**：后期烧入的 caption 归 `references/captions`，不写进生成提示词；本节指的是物理存在于场景里、会被摄影机拍到的字。
- 与项目级生成锁的优先级：项目若已锁定「全程不生成任何字幕/屏幕文字」（见 `references/modes/*/video-prompt-guide.md`），则该锁优先，此时按上表的「无字视觉编码」支写，并且**不得**再在镜头里要求任何可读文字。

## 参考锚点表达规则

引用一律用统一的 `<reference>` 标签（属性、role 词表与提交编号规则见本节）：

```xml
<reference id="asset_a1" kind="image" role="pov"        label="执明视角" />
<reference id="asset_a8" kind="image" role="color-card" label="整段色卡" />
<reference id="asset_a6" kind="audio" role="voice"      label="执明音色" />
```

规则：

1. **role 受控**：`pov / color-card / environment / character / prop / style-ref / storyboard / motion-ref / voice / sfx / music`。生成链路每条引用必须有 role。**本表是 AI 侧唯一权威**；运行期镜像在 `canvas-proposal.ts` 的 `PROPOSAL_ROLES`，`recut.worlds.get.references[].role` 也用它，三处必须同步。
2. **格式与提交分离**：正文用 `<reference id …>`（身份、可由 Agent 校验）；提交给模型时由 resolver 改写为**组内编号别名**（`参考图1..N`、`音频1..N`，可配 `{{Mixed n}}`），并把同序 `referenceIds` 一并提交。
3. **id 不进模型串**：模型不是 Agent，看不到也不该看到 assetId；它只看到别名 + 按顺序附着的媒体。
4. **一图一 role**：需要一图多义时用 `label` 说明，不叠 role。
5. **role↔kind 必须匹配**：`voice/sfx/music` 只能 audio，`color-card` 只能 image。
6. **每个 role 在正文有且只有一次声明**；后续镜头以「同参考图{n}」提及，不重复声明。
7. **禁止幻觉锚点**：正文出现的每个 token 必须有真实绑定；未绑定即拒绝提交，不做静默丢弃。
8. 只引用本片段真实需要的参考，不为「可能有帮助」堆料。

## 片段时长预算与多镜连续段规则

1. **一个片段 = 一次生成请求，时长由内容定**：先把整段当成一个连续单元，让模型自己导演连续动作；片段长度按内容与模型能力定，落在模型单次上限之内（常见区间约 5–15 秒，具体上限由 App 适配层传参，不写进正文）。**不要每镜套同一个固定秒数（尤其不默认每镜 5 秒），也不按固定秒数机械切片**——多长是结果，不是预设；每镜的实际区间用 `[起~止s]` 明确标出。
2. **优先用模型自身的导演能力保连续**：一段连续动作优先一次生成，靠模型内部的时间分配与运镜保持连续，而不是人为切块；只有命中拆分条件才拆。
3. **拆分条件（只有命中才拆请求）**：模型单次时长上限小于需求；命中 Red 风险镜需拆分预案（见 `references/shot` 的可生成性预算）；叙事确需跨时空/跨场景且必须独立重生成。拆出的每段仍是完整连续段，首尾状态自洽，不留半截动作。
4. **时长预算按信息量给**：每镜给足完成其变化所需的区间（情绪停留/长镜头给长，密蒙太奇给短），不每镜套同一个常数；区间连续相接、无空档，总和即片段长度。
5. **连续段优先于切碎**：慢节奏、情绪/氛围/长镜头类内容允许整段一镜到底（单一主导运动贯穿全段，如一次极缓慢推近），不为「凑多镜」而硬切；多镜只在确有一个新信息或新机位时增加。
6. **一镜一信息变化**：镜头变长时增加镜头，不拉长单镜。
7. **首尾帧即合同**：每镜写清起始状态 → 单一可见变化 → 结束状态；下一镜起始 = 上一镜结束。
8. **HARD CUT 显式标注**；跨镜的人物/道具/光位/环境用同一世界状态推导，不重建房间。
9. **方向与屏幕位置不混写**：人物自身左/右与画面左/右分开描述；跨镜保持世界坐标一致。
10. **运镜克制、物理路径明确**：不做无意义漂移或随机抖动；每镜在区间内写清机位起点、运动方式与方向、落点景别；手持/机械臂等质感与人物状态形成对照时说明。
11. **可生成性预算**：高风险镜（多人交手、快速位移、复杂复合运镜）在纸面先给拆分预案。
12. **每镜写满可见面**：区间内出现的每个可见面（屏幕/界面/道具/材质/光源）都要给出具体内容，不留「看手机」「背景很干净」这类空概括；密度按《画面细节密度》逐面点名。

## 一图分镜表锚定（storyboard）

当分镜先以**一张 N 宫格分镜表**（storyboard sheet，见 `references/shot` 的宫格压缩法）压缩生成时：

1. **默认整张 sheet 作一张 image 直接作 `role="storyboard"` 参考**，与 `character`/`environment`/`style-ref`/`voice` 并列提交，由模型据此展开分镜；**参考数量有限，整张只占一个名额，不逐格占用**。它承载整段的构图与调度连续性，不是成片帧。
2. **仅当命中升级条件**（模型吃 storyboard 参考弱或分辨率明显不足、需精确首尾帧端点、代表镜 proof 不过）才切格细化：`recut.media.gridSlice` 切出单格作 `role="storyboard"`，**只锚定该格**的构图/动作/调度；再叠 `character`（角色身份）/`environment`（场景）/`style-ref`（风格）。
3. 切格细化时提示词要求「去掉宫格边框与坐标编号、提升分辨率、保持角色/服装/道具/光位与相邻格一致」；**不放大草图**，成片关键帧必须重生成。
4. 一格里已冻结的起止状态即该镜的首尾帧合同；相邻格用世界状态推导，不重建房间。

## 声音设计规则

声音写成两层（归口见 `references/sound`），两层都不可省，缺一即视为提示词未完成：

1. **全段底声（声明一次，贯穿整段）**：贯穿整个片段的持续环境底声（房间 / 夜风 / 街道 / 雨 / 地铁），以及有无 BGM 与气质；无 BGM 时明确写出。底声不因切镜重置，是听觉连续性的锚。
2. **分镜局部声（逐镜写，用同一区间锚定）**：每镜把**因果点**上的声音写清——接触先于位移、受力先于反应、实体声源先于环境反馈；局部环境随场景改写（进店 / 开窗 / 雨停），不沿用上一镜。声音的时间位置与镜头序列的 `[起~止s]` 对齐。
3. **对白逐字保留**，位于声音前景、清晰可懂；用引号标明，不改写、不节选。对白超量时增加片段或减词，不加速朗读。
4. **音色引用**只说明「仅用于参考音色」；当前台词语义只由本片文本决定，不带入参考样本原台词。
5. 声音约束只写用户/项目明确要求的，不堆叠冗长负面词。

## 负面约束写法

- 名字具体、不用类别：写「无现代塑料制品、无腕表」，不写「无现代物品」。
- 数量约 4–6 类，随片/随镜裁剪，不整墙复制。
- 通用固定项：签名/水印/角标/图标/电量/时间/与叙事无关的额外 UI 元素。
- **「无文字 / 无字幕」是有条件项，不是默认项**：只有本镜确实不需要可读画内文字（即《画内文字》的「无字视觉编码」支）时才写。
- **要求了可读文字，就不得再把「无文字 / 无字幕」列进负面词**：两者互相抵消，模型会在「该写字」与「不该写字」之间摇摆，结果就是糊字。此时把负面换成针对文字质量的风险项：无乱码文字、无伪字形、无错别字、无重复文字、无多余文字、无文字溢出载体。
- 本镜自身风险项（当镜特有的漂移风险）优先占位。

## 常见误用

- **每镜重写风格**：STYLE LOCK 必须逐字复用；改一个形容词就是另一部片子。
- **把 id 写进提交串**：模型无法解析，等于噪声，还会挤掉描述预算。
- **只有顺序没有 role**：`referenceIds` 是数组，模型不知道第几张负责什么。
- **世界语境不带参考图**：不先读 `references[]` 就纯文本直出，主角色会漂、场景/风格会串；画面可能出现主角色却无 `role="character"` 引用时不得提交，只有明确无角色的纯空场景才可省略。
- **克隆时只描述镜头语言、不连参考帧/片段**：把参考的画面语言写成形容词（「镜头感像参考」）而不连 `style-ref`/`motion-ref`/`storyboard` 锚点，模型无从继承其景别/运镜/调色；迁移参考必须真绑定。
- **一图多 role 或 role 冲突**：无法校验，生成时语义互相打架。
- **用形容词代替可执行描述**：「压迫感」「电影感」不可执行，应写为可观察的动作、光位与材质。
- **每镜重选相机/镜头**：器材与光学性格全片一套、锁定在 [CAMERA LOCK] 逐字复用；每镜换机身/焦段会读成拼盘。
- **把器材写成空泛质量词**：「电影感镜头」不可执行，应写机身/胶片、焦段、光圈、稳定方式。
- **把片段切成等长小块**：按固定秒数（如每镜 5 秒）机械切请求，丢了连续段的同一世界状态与长镜头，也浪费了模型自身的连续导演能力；多长由内容定，除非命中拆分条件，整段应一条连续段一次生成。
- **用「第 N 镜，约 X 秒」的散文代替时间区间**：镜头序列以片段时间轴上的累计区间 `[起~止s]` 领起，读者一眼能看出每镜占多久、彼此是否相接；用「约 X 秒」和对「起始机位→结束机位」的抽象叙述，模型落不到具体时点。
- **镜头只有形容词没有路径**：「压迫感推近」不可执行，应写清机位起点、运动方向与落点景别。
- **画面里有一个没被定义的可见面**：「他低头看手机」把整块屏幕交给模型瞎猜，应写出屏幕上是什么、手指停在哪一行、屏光照亮哪些面（见《画面细节密度》）。
- **文字载体只给「是什么界面」、不给具体字**：「手机上显示微信聊天界面」是最典型的糊字来源——模型只会渲染你给它的字，没给就自己编。要可读就逐字写死（见《画内文字》）；不需要可读才走无字视觉编码，并明确声明无可读文字。
- **要求了可读文字，负面词里却还写着「无文字 / 无字幕」**：自相矛盾、互相抵消，结果仍是糊字；见《负面约束写法》。
- **文字载体在画面里给得太小**：载体只占画面一角、每字只剩十几像素，再强的文字渲染也读不出；此时要么写清载体占比、要么推进景别，别指望靠提高分辨率补救（见《画内文字》第 4 条）。
- **只写画面不写声音**：底声与局部声缺一，等于把耳朵交给模型瞎猜。
- **把 `ratio/resolution/时长` 写进正文**：这是 App 适配层传参，写进正文会诱发内部黑边或语义漂移。
- **重播已完成的动作**：相邻镜头提供新信息，不重启上一镜的推近/抬头/开门。
