# Output Style

Use this before finalizing `story_analysis.md`.

## Final Report Shape

Keep the report specific to the video. Recommended sections:

1. 基础信息
2. 一句话总结
3. 标题 / 标签 / 人群分析
4. 前 3 秒 / 前 5 秒钩子
5. 剧情节拍
6. 关键画面分析
7. 冲突点
8. 反转设计
9. 梗点 / 笑点 / 金句
10. 配音 / 台词 / 声音节奏
11. 为什么容易火
12. 评论区洞察 / 底层心法
13. 可迁移结构
14. 不建议照搬的风险

## Comment Insight

When comments are collected, analyze:

- top-liked comments and what emotion they represent
- repeated phrases or repeated audience stance
- why viewers comment: self-projection, protection, anger, joke continuation, correction, disagreement, rescue fantasy, identity signaling
- what the creator can learn: stronger hook, more protective character, better conflict, fatigue risk, clearer payoff

Do not paste raw comment dumps as the final analysis. Summarize the mechanism.

## Generic Migration Rule

Do not force the output into any specific account, IP, industry, or creator persona unless the user explicitly requests that mapping.

Write “可迁移到你的账号 / 项目” in generic runs. If the user provides a target account, write to that account.

## Quality Bar

- Replace script placeholders before final delivery.
- Name speaker roles when possible instead of leaving `说话人A/B/C`.
- Describe keyframes by filename when useful.
- Distinguish “can borrow” from “should not copy”.
- Call out fatigue risks when the comment area shows resistance.
