# Recut 生产计划技能（references/plan）

本技能只回答一个决策问题：**这部片子怎么排产？** 输入是已确认的世界（角色/场景/风格/声线）与脚本（`script`），输出一份**生产计划**：作品/脚本 → 视频段（一次生成单位）→ 每段用料与参数 + 成本预估。

**它不写提示词**（归 `references/generation-prompt`），**不决定单个镜头怎么拍**（归 `references/shot`），**不落轨**（归 timeline-editor）。

## 边界

| 归属 | 内容 |
|---|---|
| **本技能** | 排产：备锚点 → 拆视频段 → 定用料 → 定参数与成本 → 落生产计划 |
| `references/assets` | 把参考锚点真的做出来（角色卡/场景图/道具图/色卡/声线）——**本技能的前置** |
| `references/shot` | 单个镜头/一段怎么拍（景别/角度/焦段/运动/调度/连续性） |
| `references/generation-prompt` | 一条提示词怎么写（CAMERA LOCK / STYLE LOCK / 参考锚定 / 多镜连续段 / 声音两层 / 画内文字） |

## 一、先备锚点（缺一不排产）

生成要有锚点：主角色参考图、场景图、道具图（关键道具）、风格锚点、声线参考（**不含分镜表——storyboard 不是生成参考**）。
- 世界已有 → 直接引用（`recut.worlds.get` 的 `references[]`，按 role：`character` / `environment` / `prop` / `style-ref` / `voice`）。
- 世界没有 → **先做**（见 `references/assets`），不要"纯文本直出"。

> 判断依据：**这是"世界生图/生视频不带参考图"这条最严重误用的根因**——不是 Agent 不听话，是链里根本没有"先备锚点"这一步。

## 二、把它排成作品与脚本，再拆成视频段（本技能主体）

一部片子 = **作品(`work`) → 视频脚本(`script`)**；脚本的内容再拆成**一段段视频段**，每段就是一个画布上的**视频节点**（媒体元素，一次生成的单位）：

- **作品 `work` = 交付单位 + 内容本体**：**正文 `detail` 先把该作品的完整内容一次写全**（电影 = 小说式完整故事；广告 = 完整广告故事/创意；**不压缩、不跳步**）；一个作品可挂多个脚本＝多集；
- **视频脚本 `script` = 一集的可生成规格**（**一集一个 script**）：**前置是 `work.detail` 已写全**——**故事/内容没写全不拆集、不压缩时间表达**；每集 `script.detail` 写本集结构 + 旁白/台词 + 场景初步规划 + **每个视频段的拍摄设计**，一次写全；
- **视频段 = 一次视频生成的单位**：一段连续动作一次生成（**时长 ≤ 模型单次上限，默认 ≈15s**）；**排产与生成的粒度都在这里，不逐镜生成**；
- **段内镜头**：镜头序列写进脚本正文（文本），供关键帧 / 预览；**不是每镜一次生成，也不再是一类实体**。

**结构靠 link `has_script`（作品→脚本），不是 `parentId`**——`parentId` 只是通用归属（文件夹），改它不断链；建脚本时服务端会自动补这条链。类型目录的 `childTypes` 是这件事的机器可读声明（`work.childTypes=[script]`，script 是叶子，advisory）。

**每个视频段写清五件：**

1. **内容（= 真正拍摄的逻辑，不是剧情梗概）**：本段拍摄设计 → 写进所属 `script.detail`，**至少含**：空间与美术 / 表演与调度（blocking）/ 摄影（CAMERA LOCK + 每镜机位景别）/ 灯光 / 镜头序列（`[起~止s]`）/ **声音设计两层**（底声 + 局部声）/ **旁白·台词（逐字，不能空）** / 画内文字 / 连续性锚点 / 参考 role（骨架见 `recut-worlds` 的 `references/content-templates.md`）。**只写剧情梗概不合格**——这段正文是生成提示词的料场，漏了空间/表演/摄影/灯光/声音，提示词就长不出来。
2. **时长**：本段总时长——**一个视频段 = 一次生成，必须 ≤ 模型单次上限（默认 ≈15s）**；内容更长就**多拆几段**，不把单段拉长；
3. **镜头序列（文本）**：把本段逐镜写进正文（`[起~止s]` + 景别/机位/动作/声音）；**分镜表不作生成输入**（仅排产/预览）；
4. **用料**：带哪些 role 的锚点（角色 / 场景 / 道具 / 风格 / 声线）；
5. **产物**：本段要出什么（默认一段一条**视频片段** → 画布视频节点；需要时追加关键帧/配音）。

> **产物不设固定槽位**：生成关系至少三类（参考驱动 / 首尾帧 / 文生），实测绝大多数是参考驱动（liblib《阿猫阿雀》90 镜里 89 个 `mixed2video`）。计划里写"要出什么 + 什么关系"，具体提示词由 `references/generation-prompt` 决定。

**成本预估**：按"**视频段**数 ×（模型单价 × 段时长）"粗算；贵的（视频）标注**待用户确认**。

## 三、落地（工具）

1. `recut.worlds.entity` 建 `work` / `script`（脚本创建时自动写 `has_script`）；脚本正文写完整内容，**每个视频段的拍摄设计写进 `script.detail`**。
2. **逐段生成**：走 `recut.video.generate`（**视频待用户确认**）——**一次视频生成 = 一个视频段**，用**资产（角色/场景/道具/声线，按 role）+ `script.detail` 的该段设计**驱动（**分镜表不进生成**）；返回的 `assetId` 落到作品层的**视频节点**（`kind:"media"`, `props.modality:"video"`）；预览/测试关键帧与配音按需走 `recut.image/speech.generate` 并写回相关实体的 **media 属性**（`label` 标角色）。
3. 用户在画布上确认生成（确认权只在用户）。

## 四、纪律

- **建结构不收钱、生成才花钱**：`recut.worlds.entity` 只落结构，不提交任何生成；花钱的闸门只在下游生成（媒体提案门）。
- **结构 = `has_script` 链，不是 `parentId`**：`has_script` 表达作品→脚本归属（单源、可环）；`parentId` 只是文件夹；`followed_by`/`precedes` 表达段落顺序；别混。
- **产物挂在任一层**：视频片段（画布视频节点）、关键帧/配音（相关实体的 media 属性）、作品成片；上层是下层的聚合（作品成片 = liblib 图外的 `finalOutput`）。
- **生成才要人确认**：结构直接落；视频走生成提案门（不是实体转正）。
- **改了锚点要重跑下游**：换角色卡 → 用到它的视频段标记过期 → 重跑（见 `references/qc`）。
- **一段 = 一次生成、时长 ≤ 单次上限（默认 ≈15s）**：超长就**拆成多段**，不拉长单段；段内镜头不改变粒度。
- **画布排成思维导图树**：`work → script / 视频节点` 在作品层**分层**摆（同层同列、子节点在父节点右侧一列并纵向居中），树线用 `has_script` 关系投影，别堆成一坨（见 `recut-worlds` 的 `references/canvas-hierarchy.md`）。
- **可生成性预算**：高风险段（多人交手、复杂运镜）先写拆分预案（见 `references/shot`）。

## 使用时机

用户要"把这部片子排出来 / 拆成可生产的视频段 / 排个计划"时加载。单镜优化用 `references/shot`，不加载本技能。
