# Recut 全局故事与编排技能（references/story）

本技能回答两个绑在一起的问题：**讲什么、怎么编排**（谁要什么、为何现在行动、因果怎么闭环、对话如何推动关系、节拍如何分布），以及 **剧情类怎么编排生产**（把故事意图编成可检验、可传递、可回写的控制合同链再交付生成）。输入是选题、人物与约束，输出是可被拍摄/剪辑的结构 + 可执行的编排合同。

## 边界与归属

| 归属 | 内容 |
|---|---|
| **本技能** | 故事因果、人物行动链、对话目的与潜台词、结构与节拍、场景交易；剧情类的六种生产合同（节拍/资产库/调度图/布光图/动作账本/草图转镜头）与固定生产顺序 |
| `references/editing` | 0–3 秒钩子与留存机制（本技能定 hook 的结构占位，hooks 定三层执行与话术） |
| `references/shot` | 镜头怎么拍、分镜与连续性（本技能的节拍落在那张分镜表里） |
| `references/generation-prompt` | 把结论落成生成提示词 |
| `references/editing` / `motion`(并入 shot) / `sound` / `qc` | 剪辑节奏、动效、声音、诊断门禁 |

## 一、核心决策规则

### 1. 因果链五问（故事是否成立的唯一标尺）

每一场、每一节拍、每一句关键对白落格前必答；任一问答不出即回上游重写，不以视听装饰掩盖：

1. **谁要什么？** 当前想要的是否可被看见/拍摄（要钱、要钥匙、要一句道歉，而非"要成长"）。
2. **为何现在行动？** 什么压力/时限/代价/机会迫使此刻不动不行？能等的事不是戏。
3. **什么阻碍？** 人/制度/环境/自身恐惧中，哪一个在当下可被对手感知并抵抗？无阻碍即无场景。
4. **做了什么导致什么？** 以 `先决条件 → 人物行动/有意拒绝 → 直接结果 → 状态改变 → 迫使/封堵下一步` 闭环；仅用"然后"连接的为伪因果。
5. **为何不选更安全的替代？** 若存在更便宜/安全/直接的路径却未被尝试，即为作者便利；须让该路径不可用、代价更高或已尝试失败。

五问穿透三层：情节层（事件链与转折）、人物层（目标/策略/权力位移）、观众层（何时感到压力、释放与代价）。

### 2. 人物行动与对话即行为

- **行动先于情绪标签**：不写"愤怒地"，写可被摄影机捕捉的动词（逼问、包庇、试探、拖延、羞辱、撤退）；情绪由行为与倾听对象推导。
- **策略必有触发**：改变战术必须由新刺激/失败/代价变化/选项集改变触发；无触发的转变为断裂。
- **对话是战术**：每句有目的（索取/隐瞒/测试/安抚/要挟/暴露/撤回），有听者反应与权力/信息差变化；两句同一战术无升级即删一或升级。
- **潜台词与可说性**：表面话与真实目的可分离；允许打断、重复、误听、沉默、未完句，但必须有可追踪的听者效应。遮住说话人标签仍可区分声音，否则重写。
- **去生成腔**：拒绝金句、主题直述、每物必有回响的整洁闭环；保留与情境共生的摩擦、迟滞与无用行为。

### 3. 结构节拍

- **三幕/短片压缩**：长结构 = 建置 → 转折 → 兑现（后果落在可视代价与新状态）；短片（<3 分钟）= 一地、一核心冲突、一重大转折，迟进早出，道具与场所当下做功，背景故事仅当改变当下选择时出现。
- **五段式 hook–pain–turn–value–cta**：本技能负责在全片结构中**定位**五段的占位、节拍功能与因果衔接（每段必须有状态改变，否则可删）；`references/editing` 负责 hook 段（0–3 秒）的三层执行与话术。
- **节拍纪律**：每节拍一功能（want/resistance/discovery/cost/image）、一情绪转向、一可视锚点；跨节拍状态（事实、知情、关系、权力、道具位置与持有者）必须继承，不重置。成功也必须改变后续条件，否则为装饰性节拍。符号/母题仅当改变选择、权力或物理可能性时才算兑现。

### 4. 验证即交付

- **无声行动脊**：遮住对白，场景是否仍有一条可复述的行动与状态改变链。
- **状态引擎**：事实单源、知识继承、沉默行动脊、对话回应链、道具/信息生命周期，五层自检不过不交付。
- **独立 cold-read**：fresh reader 只给生文本与锁定约束，能复述"谁做了什么、为何这么做、每句关键话在让对方做什么"，否则回到最早断裂层重修。

## 二、剧情类生产编排：六种可控性合同

> 每一项都是"把不可控变成可检验"的账；缺一项，对应环节就无法回答"这场戏到底变了什么/外观能否复现/空间是否一致"。字段与 JSON 模板以各合同的完整说明为准（见本文件末尾「完整合同模板」路由）。

1. **剧本节拍合同** — 管"故事是否可被画面执行"。把钩子、want/obstacle/strategy_shift/power_turn/cost/cliffhanger 写成画面或台词可观察的事实，并记录观众信息差、人物进出状态差、情绪曲线与视觉概念引用。写"反转很强"不计数，能拍出"掌权者伸手索要证据却看到自己罪证"才计数。
2. **资产库合同** — 管"外观是否可复现"。是已批准 Cxx/Sxx/Pxx 的索引账：asset_id、版本、状态、参考图、锁定特征、可变状态、来源镜头、最后审阅日期；版本以 `C01b` 后缀演进，绝不覆盖已批准版本；后续只引用已审资产，不以"再抽一次视频"替代。
3. **场面调度图** — 管"空间是否可画在同一张纸上"。固定画面朝向、左/中/右与前/中/后锚点、位置与面向、道具初末位、行动路径、进出画与遮挡、摄影机位与朝向、180°轴及权力几何；移动用 `T0→T1→T2` 阶段编号。**调度先于机位**：先让走位与物件关系承担变化，再选摄影机怎么看。
4. **布光图** — 管"光是否有来源、是否服务叙事"。每镜列主光/补光/轮廓·背景光的画内来源、方向、色温、强度或光比及照亮区域，记录开镜/尾帧是否连续。资产图以可读性标准光为准，剧情镜以叙事光为准；禁止无来源泛光、死黑或滤镜替代布光。
5. **动作账本** — 管"打戏/追逐/抢夺是否可生成"。按交换单元拆为 `起势→位移→接触/落空→反应→定格尾帧`，每单元写清发力主体、起点/路径/终点与受力反应，武器·手脚与镜头方向同写正/负约束。动作密度由"因果环节数×持续时间×人物数×镜头运动"判定，超预算即拆镜或改画外暗示；默认每镜只装 1–2 个可读因果节拍。
6. **草图转镜头** — 管"草图是继承关系而非复刻外观"。只锁构图与关系（构图/地平线/机位/人物占比/视线/主光方向），脸、服装纹理与成片风格由资产/类型补齐；先标可继承与须回填项再生成关键帧，防止"草图脸"覆盖批准资产。分镜可先压成**一张 N 宫格分镜表**（见 `references/shot` 的「一图分镜表」）：默认整张直接作 `storyboard` 参考，需逐格细化时按格坐标展开，每格即本合同的单元，格清单坐标与镜号是唯一外键。

## 三、固定生产顺序（线性闸门）

前一步未通过不进入下一步；回炉按归属定向返回，禁止"再生成一次"绕过。

1. **剧本三层读法**：先完成剧本理解→调度→镜头句的镜头设计，再落为可检验的开场钩子、目标/阻力、策略或权力转折、结尾钩子。
2. **资产库**：建 Cxx/Sxx/Pxx，**先人工审核**，再进入分镜；不以视频抽卡替代资产。
3. **调度**：对每镜建立调度图，人物/道具/摄影机与轴线必须能在同一平面图上互证。
4. **类型参数**：给镜头、色彩、材质参数；类型只供参数，不改已审核外观。
5. **专项合同**：仅在需要时叠加草图转镜头、布光、动作。
6. **装配**：把所有合同装进提示词模块，单段只含一个连续机位与一个主导运动（提示词形状归 `references/generation-prompt`）。
7. **QC 门禁**：核验实际画面与合同一致性，失败按归属回炉，不以"漂亮单帧"当通过（门禁归 `references/qc`）。

## 四、与 Recut Creation Worlds 的对接（映射说明，非工具调用）

| 本技能合同 | Recut 实体 | 约束 |
|---|---|---|
| `Cxx` 角色资产 | `character`（**角色**，含人物/动物/生物） | 外观锁定特征、状态变体与审查版本对应 `appearance` 等字段；核心参考图写 `character_reference`（角色卡，role=character）；`C01b` 版本演进对应 World revision |
| `Sxx` 场景资产 | `location`（场景/地点）；剧情「场次」是 `scene`（生产实体，另一层） | 世界位置、通道、门窗、家具、光源方位对应 `description` / `atmosphere`；核心参考图写 `location_reference`（场景卡，role=environment） |
| `Pxx` 道具资产 | `prop`（**道具**，默认预设锚点） | 持有人、位置、状态与来源镜头对应 `description` / `appearance` / 道具卡（`prop_reference`，role=prop） |
| 分镜表/格清单 | `script`（视频脚本） | 节拍、口播、时长、画幅与「分镜表」媒体属性（一张 N 宫格）对应 `beats / vo / durationSec / aspectRatio / storyboard` |
| 调度图世界坐标 | 世界地图 | 人物/道具/摄影机的世界位置与轴线复用同一世界坐标系 |
| 布光图实体光源 | 世界的光源锚点 | 光源的世界位置/方向/色温需能在世界里找到实体依据 |

## 五、常见误用

- 以视听/音乐/金句掩盖断裂的因果：先修五问，再谈视听。
- 把形容词当节拍（"情绪很燃、反转炸裂"不计数）；把调度写成散文（"两人走近对峙"不可检验）。
- 用视频抽卡替代资产库，导致全片脸/衣/场景漂移；草图脸覆盖资产脸。
- 无来源泛光；动作密度超限不拆镜。
- 每场都让人物做主题陈述：主题必须落在行动、物件、空间或沉默上。
- 把 hook 话术当结构：本技能定 hook 的位置，hooks 定话术，二者不互替。

## 产出自检（交付前）

- [ ] 因果五问可答；叙事钩子/目标/阻力/结尾钩子均可画面观察，不含空泛形容词
- [ ] 跨节拍状态（事实/知情/关系/权力/道具位置）已继承，无重置
- [ ] 无声行动脊成立；cold-read 可复述
- [ ] （剧情类）全部 Cxx/Sxx/Pxx 存在、版本一致且已人工审核；调度图/布光图/动作账本可互证；草图仅继承允许字段

## 完整合同模板

六种合同的 JSON 模板、字段字典、生产顺序与 QC 对照，以及剧本/分镜的深化方法，作为搬运原文保留在 **`.executor-tasks/sources/ai-film-skills-full/`**（Apache-2.0）。本技能为介质中性的决策层，不再内联深树；需要字段级或方法级深化时，按任务直接读该源目录对应文件（`.executor-tasks/sources/ai-film-skills-full/ai-short-drama-production/references/control-contracts.md`、`.executor-tasks/sources/ai-film-skills-full/ai-storyboard-director/SKILL.md`、`.executor-tasks/sources/ai-film-skills-full/director-agent/references/screenplay-writing-core.md` 等）。

## 介质中性声明

本技能不出现任何 App 工具调用、时间线 op、代码或模型控制面语法；决策以可观察的人物行动、状态改变与可复述因果表达，由各 App 适配层再译为各自实现。
