# Recut 全局导演技能：失败诊断与验收门禁（references/qc）

本技能是 Recut 平台 App 无关的全局导演技能，**只回答一个问题：哪里坏了、怎么修**。适用范围为一切视频/短片成片——实拍口播、AI 生成片段、图文动效混排、字幕与声音成片。所有关于画面是否可交付、是否需要重做、重做哪一段的判断，以本技能为准。

> 介质中性：本文件仅给出“看什么、判什么、修什么”的导演决策，不包含任何 App 工具调用、时间线操作或代码语法。各 App 的适配层自行将本技能的配方映射为自身操作。

## 边界声明

- **本技能是失败诊断与验收门禁的唯一来源；各创作技能里的自检清单只做轻量提示并指向本技能。** 任何创作流程在声称“可交付”之前，必须通过本技能的门禁；自检未通过不得进入下一环节。
- **唯一性**：本技能只回答“哪里坏了、怎么修”。以下交界处的决策归属其它技能——
  - 讲什么、怎么编排故事 → `references/story`
  - 一个镜头怎么拍（机位/调度/构图） → `references/shot`
  - 元素怎么动、动效嗓音 → `references/shot`
  - 画面该放什么素材、怎么摆（B-roll/安全区/cover vs contain） → `references/shot`
  - 片子怎么剪到一起、节奏与转场 → `references/editing`
  - 字怎么上屏、字幕版式与可读性 → `references/editing`
  - 耳朵听到什么（旁白/BGM/SFX） → `references/sound`
  - 发给谁、什么规格、什么雷区 → `references/platform`
- 各创作技能如需质量判定，仅以“详见 references/qc 的 F-code / 门禁编号”作引用，不另立判定标准。

## 一、诊断总则

1. **按症状计数，按机制归因**：一句抱怨可能含多个机制（如“脸变了、衣服也变了”属同一机制“主体漂移”计 1 个；“像 PPT 且人物中途消失”计 2 个）。每个症状独立诊断，全部归因后再读修法。
3. **多症状必追共同上游**：同一镜头出现 2 个及以上失败，必为策划过载（时长过长、动作过多、画面信息过密、遮挡过多）；修症状前先修上游——缩短、推近、简化、拆分镜头。3 个及以上视为“不是一个镜头，是三个镜头”，重做分镜。
4. **三次同设计失败即换设计**：同一镜头设计连续 3 次失败，不再改文案措辞，直接换设计（缩短/推近/简化/拆分/换起点画面/换机位/用剪辑承接）。第四次同文案重试成本等同第一次，不产生新信息。

## 三、各环节验收门禁清单（摘要）



- [ ] 故事与交付物已锁定：时长、画幅、信息目标、不可妥协红线（品牌色/标志/人物身份）已书面确认
- [ ] 每镜具备“起点状态→单一动作→终态定格”三要素，时长按动作真实耗时配比
- [ ] 每镜仅一种镜头行为、一种主体动作；多动作/多运镜已拆镜
- [ ] 起点画面已按交付画幅构图，主体占比/留白/手部入画/文字规避已确认
- [ ] 光源已命名（方位/性质/强度对比）并将贯穿全场；时代与禁忌物清单已落实到画面
- [ ] 需全程存续的道具已登记（颜色/材质/边角特征），并明确“全程不遮挡不出画”或“遮挡落在切点”
- [ ] 需对口型的台词已压至短句短镜，否则已改走画外声/反应镜头；不可硬拼的失败已改写


- [ ] 选片已按“表演/身份/动作/连续性/构图/可剪性”择优
- [ ] 连续性：手持物/服饰/光位/视线/机位轴线跨镜一致；不匹配处已安排插入镜头消化
- [ ] 构图：主体未出安全区、未误裁头手、画幅一致；字幕区与主体区无重叠
- [ ] 技术瑕疵筛查：无熔融/多指/多肢、非预期多物/多人、乱码文字/水印、光色跳变、对象消失
- [ ] 节奏预检：切点均有信息/权力/动作/反应动机；单镜 2–5 秒为主
- [ ] 声音预检：台词归属清晰，画内对口型仅短句；环境声与可见空间匹配


- [ ] 全片通看已完成：正常速度至少两遍（第一遍看故事与节奏，第二遍看连续性与瑕疵）
- [ ] 硬门禁全绿：无 slideshow 感、无主体/换脸漂移、无熔融穿帮、无动作未完成、无镜头失控、无凭空多物/乱码文字、无光色跳变、无对象消失、无口型严重错位
- [ ] 节奏与信息：无冗长平段，切点有动机；信息密度与情绪起伏可被观众感知
- [ ] 声音与字幕终检：对白可懂、声场贴合空间；字幕安全区内、高对比、无溢出遮挡、断行合语义、移动端可读
- [ ] 残留风险已书面告知；若全片通看或任一硬门禁未完成，交付状态为“未完成/待验证”，不得声称为合格成片

## 四、QC 修复循环

```
诊断 → 定位最早上游问题 → 修复 → 复核
```

1. **诊断**：按第二章将观众可见症状逐条译为 F-code，记录“症状—原因—修法”与时间点，不合并不同机制。单症状按本 SKILL.md 的 Symptom-to-code quick index 单次定位；多症状按 60-second triage tree 逐症状独立取码，全部归因后再读修法。
2. **定位最早上游问题**：在策划链路上回溯至最早可拦截该失败的环节（交付物定义→分镜→起点画面→生成→选片→剪辑→调色→字幕→混音），同镜多症状取其共同上游（通常为时长/景别/动作复杂度）。
3. **修复**：按本 SKILL.md 的成本阶梯 L1–L7 从低到高执行—— L1 文案收紧与终态补全 → L2 时长/运动强度等参数下调 → L3 同设计重试（预算 2 次）→ L4 重做起点画面 → L5 重做分镜（缩短/推近/简化/拆分）→ L6 剪辑承接（修剪/插入/遮盖/调色统一）→ L7 删镜头；每步仅动一处变量。同设计累计 3 次未过即升格为重策划。
4. **复核**：修复后回到第三章对应门禁重检，并全片通看验证是否引入新断裂；修复记录按条留痕（例：“镜头 07 — F1 主体漂移，二次生成；原因：8 秒单镜含转头与遮挡；修法：拆为 3 镜各 3–4 秒，起点画面推近”），便于同类失败被上游拦截。
