# 验收门禁清单（改写自 ai-film-skills 的 QC 契约）

> 本文件将 `62656456/ai-film-skills` 的 `SKILL.md` 中与 QC、验收门禁、合格成片判定相关的段落改写为中文清单。原文为英文，本清单保留其判定逻辑与门槛语义，仅做语言转换与清单化；深化诊断仍以 `failure-modes.md` 的 F-code 为准，量化评分与逐帧检查仍以 `assets/qc-checklist.md` 的三道闸门为准。

## 使用位置

- 仅在声称“可交付”之前运行本清单；任一项不通过即打回，不进入交付。
- 与 `failure-modes.md` 配合：本清单判定“是否通过”，该文件回答“哪里坏了、怎么修”。
- 与 `assets/qc-checklist.md` 配合：该资产文件给出 PRE / POST / SEQUENCE 三道闸门的权重与阈值，本清单给出与 `produce-ai-video` 工作流对齐的阶段门禁与诚实交付口径。

## 门禁总则

1. 以成片为准，不以中间物为准：故事板、提示词、已生成片段、工程文件、QC 报表均为中间产物，不可替代可播放的最终视频。
2. 以全片通看为准，不以文件齐全为准：未以正常速度完整通看成片，不得声称合格。
3. 以硬门禁为准，不以单项高分为准：任一硬门禁不通过即不交付，即使总分达标。
4. 诚实分级交付：按实际验证状态标注 `合格成片 / 候选成片 / 未完成·待验证`，不夸大。

## 门禁一 —— 源与验收锁定（对应原文步骤 1 与步骤 10–11 的前置）

- [ ] 已锁定本次创作的唯一项目、当前剧本版本、已批准资产、已固定决策、交付规格（时长/画幅/格式）、权限与成本边界。
- [ ] 已书面定义“合格成片”：观众可理解发生了什么、付出了什么代价；硬门禁清单已确认且可执行。
- [ ] 已区分已验证事实 / 未知 / 假设 / 惯例；假设已显式标注，不冒充事实进入门禁。

## 门禁二 —— 生成与选片纪律（对应原文步骤 6–8）

- [ ] 未让模型最大时长重定义戏剧时长；分镜时长按动作真实耗时设计，必要时以多镜剪辑达成段落，而非拉长单镜。
- [ ] 已生成真实动态素材；已拒绝以静态帧位移、关键帧幻灯片或技术预览冒充成片。
- [ ] 选片按“表演/身份/动作/连续性/构图/可剪性”择优，而非“有文件即过”；单镜择优结果可追溯。

## 门禁三 —— 装配与声音（对应原文步骤 8–9）

- [ ] 切点均有动机（递进信息、转移权力、澄清动作、揭示反应、交接下一拍），非等时长拼接；单镜时长以 2–5 秒为主，已留呼吸感。
- [ ] 声音承载空间、动作、节奏与连续性，而非粘贴感；对白、呼吸、环境、效果、静默与音乐（如授权使用）已按可见空间重建。

## 门禁四 —— 全片通看与硬门禁（对应原文步骤 10 Enforce hard rules）

> 本门禁为硬门槛：任一项不通过即打回，不进入交付。创作技能中的自检清单仅作轻量提示，完整判定以本技能与 `assets/qc-checklist.md` 为准。

- [ ] 已完成至少两遍正常速度全片通看：第一遍看故事与节奏，第二遍看连续性与瑕疵；未以“文件齐全/时长相符/单镜抽检通过”替代。
- [ ] 已修复首个观众可感知的缺陷并重看验证，直至 `assets/qc-checklist.md` 的硬门禁全绿（见下）。
- [ ] 硬门禁全绿（任一不通过即不交付）：
  - 无 slideshow 感或关键动作未发生/未完成（F2/F4/F5）
  - 无主体/换脸漂移或服饰/锚点消失（F1）
  - 无熔融穿帮或多指/多肢（F3/F10）
  - 无镜头失控或无端推拉（F6/F17）
  - 无凭空多物/多人闯入或乱码文字/水印（F9/F11）
  - 无光色跳变或风格断层未被调色统一（F12/F16）
  - 无对象消失或跨镜连续性断裂（F19/F7）
  - 无口型严重错位或声画空间不符（F15）
- [ ] 未以“已生成/已导出/提示词完整”作为成功依据；未交付由独立单镜演示拼凑而成的“伪成片”。

## 门禁五 —— 诚实交付与三态标注（对应原文 Output Contract）

> 完成时必须以可播放视频为先导，并显式标注以下三态之一；不得以故事板、提示词文档、静帧画廊、测试片段或 QC 报表替代最终视频。

- [ ] `合格成片`：全片通看已完成，且全部硬门禁通过。
- [ ] `候选成片`：可播放，但一项或多项可见质量判断仍待人工复核（需在交付说明中列明位置与可见度）。
- [ ] `未完成·待验证`：生成、装配、全片通看或任一硬门禁未完成；此状态下不得声称为合格成片。
- [ ] 若全片通看或任一硬门禁未完成，交付说明已如实标注残留风险与观众可见度，不隐瞒。

## 门禁未通过时的修复纪律

1. 回到 `references/failure-modes.md` 按症状译码（F1–F19），按成本阶梯 L1–L7 从低到高尝试，不跳级。
2. 同一设计累计 3 次同因失败即换设计（缩短/推近/简化/拆分/换起点画面/用剪辑承接），不再原地重试。
3. 修复后回到本清单对应门禁重检，并全片通看验证是否引入新断裂。

## 与其它文件的分工

- 本清单回答“是否可交付”；`references/failure-modes.md` 回答“哪里坏了、怎么修、修到哪一层成本”；`assets/qc-checklist.md` 回答“按什么权重与阈值打分、阻塞项如何一票否决”。
- 三者的判定口径一致，重复条目以本清单的中文表述为准，机制解释以 `failure-modes.md` 为准，量化阈值以 `qc-checklist.md` 为准。
