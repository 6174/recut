# 记忆（Memory）：记住用户的习惯

> `recut-worlds` 的二级参考。定义 memory 是什么、什么时候写、三种 op 与压缩预算（入口只给概览）。

## 是什么

**记忆 = 这个用户在这个世界里的工作习惯**，由 Agent 维护的自由 markdown，随每次 `recut.worlds.get` 一起返回（字段 `memory`）。

它**不是**：

- **不是 Canon**：不产 revision、不进 `world_entities` / 历史版本、不参与 `expectedRevisionId`。写记忆不会和别人争并发锁。
- **不是内容**：作品的顶层设想、脚本、设定正文属于实体 `detail`；把长文塞进 memory 是错的，会挤爆预算也找不到位置。
- **不是世界技能**：`skillMd`（world.md）是这个世界的内容 / 生产工作流，全球共享；`memory` 是**这台用户此刻的偏好**，因人而异。

**一句话判据**：**换个用户就不成立**的，写 memory；**换个用户也成立**的，写 `detail` / `skillMd`。

## 什么时候写（核心）

**用户给出反馈 / 纠正 / 偏好时，主动记下**——这是 memory 存在的主要理由。典型触发：

| 用户说 | 记什么 |
|---|---|
| "以后都用竖屏 / 横屏" | 画幅偏好 |
| "不要自动生成视频 / 先问我" | 审批 / 确认习惯 |
| "分镜别太多 / 一段一个长镜" | 生产手法偏好 |
| "旁白用男声 / 更口语一点" | 风格偏好 |
| "上次不是这样" | 先看 memory，**改掉**那条错的 |

**不要**在纯内容编辑（改一句台词、挪一张卡）时写记忆；**只有在用户表达了"以后怎么做事"的意图时才写**。宁少勿滥：一条精准的偏好胜过十条流水账。

## 怎么写（三种 op）

工具：`recut.worlds.memory.update`，必填 `worldId` / `op` / `content`。

| op | 语义 | 什么时候用 |
|---|---|---|
| `append` | 末尾追加一段（自动补换行） | 新增一条偏好 / 反馈，最常用 |
| `replaceLine` | 替换第 `line` 行（1 起，`content` 可多行；**为空即删除该行**） | 修正某条、删除过时项 |
| `replace` | 整体重写全文 | **压缩**，或大改结构 |

返回 `{memory, lines, bytes}`——写完即可看到新尺寸。

```jsonc
// 新增偏好
{ "worldId": "<id>", "op": "append", "content": "偏好：竖屏 9:16；每段先给参考图再生成" }

// 改掉第 3 行（记错 / 用户改主意）
{ "worldId": "<id>", "op": "replaceLine", "line": 3, "content": "偏好：横屏 16:9（已从竖屏改）" }

// 删掉第 2 行（不再适用）
{ "worldId": "<id>", "op": "replaceLine", "line": 2, "content": "" }

// 压缩：把散记忆收敛成短清单
{ "worldId": "<id>", "op": "replace", "content": "- 画幅：竖屏 9:16\n- 分镜：少而精\n- 视频：只提交、待用户确认" }
```

**行号从哪来**：`world.get` 返回的 `memory` 是纯文本，第 1 行就是第一行。改之前先看一眼，避免改错行。

## 压缩（尺寸纪律）

memory 有预算，`world.get` 会返回 `memoryBytes`：

- **软上限（约 6000 字节）**：超过就尽快用 `op=replace` 压成更短的等价文本——**去重、合并同类项、删被推翻 / 过时的条目**。压缩是常规动作，不是异常。
- **硬上限（约 16000 字节）**：超过这个尺寸的写入会被直接拒绝，返回提示让你先压缩。所以当 `append` 开始报"over the limit"时，先 `replace` 收敛，再追加。

压缩时要**保住结论、删掉过程**：留下"用什么"，删掉"为什么当初讨论过"。

## 边界

- **非 local 世界只读**：`WORLD_READ_ONLY` 时不要试图写记忆（记忆随世界，不随副本用户）——需要就 `recut.worlds.fork` 后在新副本上记。
- **不写敏感信息**：memory 会随世界导出 / 迁移，别记凭据、隐私或一次性 token。
- **只写这个世界相关的习惯**：跨世界通用的偏好应交给上层（用户级设置），不要在每个世界里复制。
