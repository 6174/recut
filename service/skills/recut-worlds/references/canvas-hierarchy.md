# 画布层级纪律：无限画布 ≠ 文件夹

> `recut-worlds` 的二级参考。建任何实体前先读。生产结构见 `production-layer.md`；建作品流程见 `SKILL.md`《四、基础操作 B》。

**画布树不是文件夹**：相关联的内容尽量放**同一张画布**——一个作品的 `work → script / 视频节点` 全铺在**作品层这张画布**，别逐级分层；内层画布只在内容确实是独立子世界时才用。每多一层就多下钻一次，丢掉无限画布「一眼看全」的价值。

两条硬约束：

1. **锚点实体放世界根层**：`character` / `location` / `prop` / `work`——即"谁 / 在哪 / 拿什么 / 交付什么"——直接建在**根画布**（`contextId: ""`），**归属留空**（不给 `parentId`）。世界级锚点是全库共享的，不要为"归类"另造中间容器实体（如「作品 - 1」「竖屏版」这类空目录）。
2. **生产实体与视频节点在作品层平铺**：`script` 建在**作品的内层画布**（`contextId: <workId>`），**归属也停在作品**（`parentId: <workId>`）；视频节点（媒体元素）也放同一层。不要把脚本再套内层画布、逐级下钻。

```text
✗ 太深：把画布当文件夹                ✓ 平铺：相关内容同一张画布
世界                                  世界
└ 作品 - 1                            ├ 角色 · 阿蛋
  └ 画中哑女                           ├ 道具 · 铜镜
    └ 画中哑女·竖屏3分半版              └ 画中哑女（work）
      └ 临河观音堂·雨夜                    ├ 脚本 · 竖屏3分半版
        └ #15 画褪 …                       ├ 视频节点 · 临河观音堂·雨夜
                                           └ 视频节点 · #15 画褪 …
```

**结构不靠层级、靠关系**：`work → script` 由 `has_script` 结构链单源表达，`parentId` 只是"摆在哪个文件夹"。把卡片摊到作品层**不会断链**。

## 作品层怎么摆（思维导图式）

`work → script`（+ 视频节点）是有向父子关系，**别把卡片堆成一坨**；按**分层列**摆，让 `has_script` 的投影连线自然连成树：

- **分层列**：`work` 在最左（或最上），`script` 一列、视频节点再一列；`x` 逐层递增 ≈ 360px。
- **同层等距**：同一父节点的子节点**同列、等距纵向排列**（行距 ≈ 380px；实体卡 264×328，留 ~50px 间隙），并对齐到父节点**纵向居中**（父节点 `y` ≈ 子节点 `y` 的中位数）。
- **先读后放**：放卡前用 `recut.worlds.doc {contextId: <workId>}` 读已有 `geometry`，找空位、避免重叠；不传 `x/y` 时服务端只会贴到已有内容右侧兜底，必乱。
- **树线即关系**：树线只用 `has_script` 链的投影（`arrow:<relationId>`），**不要手写箭头**。
- **规模控制**：同层超过约 5 个子节点就换列或收紧行距；视频节点很多时按脚本 / 段落分簇、簇间留更大间距。
- **微调**：树形美观用 `recut.worlds.docs` + `recut.worlds.doc.update` 的 `update` op 改 `geometry`（不产 revision）。

## 唯一的加深例外

一个作品**确实有多个脚本**、且需要按脚本归组时，才把该脚本放进这个脚本自己的一层（再深一层）；其余一律平铺在作品层。判断依据：`parentId` 的语义是通用归属，不是生产结构。
