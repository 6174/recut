# Vox B-roll 创作指南

> 这是创作契约，不是平台或工具说明。项目当前状态、可用能力和保存方式由宿主提供。

## 目标

把一个主题做成可审阅、可继续制作的 Vox 风格 B-roll 方案：论点清楚，画面有统一的纸质拼贴语言，每个镜头都服务叙事。

## 媒体执行边界

本 App 的图片、旁白和场景视频必须通过 Recut MCP 媒体 API 生成。场景视频的唯一执行路径是 `recut.video.generate_async → resource.create`：提交会立刻返回稳定的 Recut `assetId`，该 Asset 先处于 `queued`；常驻 Daemon 将其提交给 Atlas 后，同一 ID 原位变为 `running`，最终为 `completed` 或 `failed`。`recut.media.get_job` 只用于读取和汇报状态，不能阻塞 Scene 引用的创建；关键画面使用 `recut.image.generate`，旁白使用 `recut.speech.generate_async`。

这是 Provider 调用，不是本地视频创作任务。禁止以 HyperFrames、ffmpeg、浏览器自动化、终端脚本或本地渲染替代上述生成调用；即使通用视频 Skill 被自动建议，也不得选择或读取它。除非用户明确要求制作 HyperFrames 合成，否则不要读取、安装、调用或解释 HyperFrames；它不是 Scenes 阶段的实现方式。

## Vox 提示词与导演语言

每条提示词先区分两个职责：关键画面决定拼贴语言，场景视频只让已分层的拼贴以克制、可剪辑的方式运动。不要把一张海报描述和一整段剪辑时间线塞进同一次生成。

**关键画面：五段提示词结构**

1. **固定风格块**：混合媒介手工剪纸拼贴、编辑杂志感、撕纸或剪刀边缘、胶带、网点印刷、报纸剪贴、纸模板、真实纸张投影、印刷颗粒；平面 2D，非 CGI、非 3D、非写实。
2. **分层场景**：把主体、道具、装饰碎片和信息区域分别描述为边缘清晰、各自带投影的纸质剪贴层；不要要求一团融合的绘画。
3. **背景与构图**：每个 Beat 选一个醒目的纯色纸背景，保持强负空间、明确视觉焦点和前中后层次；全片固定纸张纹理语言，色彩可随叙事推进。
4. **印刷质感**：根据主题选择有限 2–3 色、双色或单色加强调色，以及 risograph、丝网印、复印机、活字、木刻、旧报纸、牛皮纸、油墨套印偏移等一种主质感；不能混成脏灰渐变。
5. **技术约束**：16:9、清晰边缘、平视扫描或平铺俯视光线、保留纸张瑕疵和投影。当前产品禁止让模型生成可读文字、数字、Logo 或水印；标题区必须留白，文字交给后续可控图层。

同一支片的固定风格块必须逐字复用。每个 Beat 只改变场景、单一背景色、情绪和动作，不要每一段都换媒介、年代或纹理。需要提供多个 Look 时，优先在时代/版式、色板、印刷质感、字体气质和情绪这五个维度做真实差异，而不是只替换形容词。

**场景视频：六段提示词结构**

1. **目标**：把参考关键画面变成平面剪纸拼贴动画，保持原有布局、材质和比例。
2. **镜头**：一段只选一个连续镜头运动，例如极慢推进、横向纸层视差或缓慢上移；默认平视、镜头平行于海报。
3. **元素运动**：描述纸层可实现的动作：漂移、轻摆、滑入、刚性旋转、轻微浮动、网点呼吸、胶带或撕纸边缘轻颤、落位；可让多层纸片共同运动，但必须围绕同一个信息变化，保持刚性纸片，禁止 morph、融化和有机变形。
4. **质感与颜色**：保留撕纸、胶带、网点、报纸、纸模板和粗颗粒；说清本 Beat 的情绪、色板和运动强度。低振幅、缓慢、连续、ease-in-out 是默认。
5. **稳定锚点**：纸层保持刚性平面、只做纸层视差；画面布局、人物剪影、标题安全区和关键物体不重绘、不变形、不漂移。若有用户提供的人脸、产品或标签，必须声明它是冻结的摄影贴纸，只能重构周围纸张世界。
6. **镜头收束**：单一连续镜头、无内部跳切、无突然缩放；非循环镜头必须说明最后如何稳定落位。复杂节奏用多个短 Scene 之间剪辑，不要塞进一个视频。

**导演节奏：从结构到镜头**

先按主题选择叙事弧：单一观点优先“钩子→铺垫→建立→回报→收束”；产品/痛点用“问题→放大→解决→证明”；机制解释用“钩子→它是什么→2–3 步→收益→行动”；历史演进用“起点→事件→转折→当下→启示”；辟谣用“先给事实→指出误解→拆解→正确结论”。用户先确认 Beats，才进入 Look 和 Keyframes。

首个 Beat 必须在三秒内给出结果承诺、反常识、直接问题、痛点或警示，绝不从背景介绍开场。30 秒一般 6–8 个 Beat、每段约 4–5 秒；60 秒一般 10–12 个 Beat、每段约 5–6 秒。每 3–5 秒改变一次画面信息；回报点可使用静态或近静态镜头，让运动突然收束以强调结论。

镜头景别沿信息推进变化：先用全景建立关系，中景解释主体，近景或细节镜头落在论点、证据或结果；相邻 Beat 不要重复同一种镜头运动。默认只从 `static`、`push_in`、`pull_out`、`pan`、`tilt`、`parallax`、`element` 中选择：缩放、平移和纸层视差安全；旋转、轨道、dolly-zoom、手持、甩镜和快速变焦会破坏平面纸艺与文字稳定性，除非用户明确要求实验性风格。

对 Gemini、Veo、Runway 等正向提示模型，用“保持稳定、平面、连续”表达约束；对 Seedance 可同时写清禁止的失真结果。无论模型如何，动作不能靠大幅镜头甩动、爆炸、变形或 morph 来制造冲击。

## 七个阶段

`Brief → Beats → Look → Keyframes → Audio → Scenes → Delivery`

**Brief｜创作简报**

回答：讲给谁、核心观点是什么、观众为什么现在要看、整支片的张力来自哪里。

请求目标：把一个题目收敛为后续所有创作共享的单一论点，不写成泛泛的选题介绍。输入只有用户主题与明确约束；交付应说明目标观众、可被验证的核心观点、开场冲突、因果推进方向和预期时长。完成标准：后续 Beats 能直接据此拆出 6–8 段，每一段都能回答“这段为什么值得看”。没有 Brief 时不能靠猜测先做画面。

**Beats｜叙事节拍**

把观点排成能看完的短片结构。先用三秒内的冲突或反常识抓人，再用 6–8 个短节拍推进因果；每个节拍都要说明观众看见什么、理解什么。

请求目标：将 Brief 变成可执行的叙事骨架，而不是一组并列的提纲。每个节拍要有稳定的 `id`、标题、旁白要点、画面证据、叙事目的和时长；前一段提出的问题必须由后续段落回应。完成标准：开头三秒有明确钩子，中段每一节只推进一个信息变化，结尾回收核心论点；未确认 Beats 不能进入 Look 或 Keyframes。

**Look｜视觉风格**

一张风格参考图定义整支片的视觉语言，不是装饰海报。它应同时呈现视频里会反复出现的元素：纸张层次、信息卡、人物或物件的处理、色彩、标题区域、纹理与情绪。给出 3 个明显不同、都贴合主题的候选；每个候选必须有自己的参考图和原始画面描述。

请求目标：为同一叙事提出三种可比较的整片视觉系统，每个候选都必须先生成一张 16:9 图片。每张图必须保存自己的 `media.assetId` 与原始提示词，并覆盖纸张材料、色板、信息卡、标题安全区、主体处理和纹理；候选之间要在色彩、材料或信息密度上真实不同，不能只换形容词。完成标准：用户选择一个 Look 后，Keyframes 可以把它的图片作为 `image.imageAssetIds` 风格输入；未选定 Look 不得生成 Keyframes。

**Keyframes｜关键画面**

把每个节拍变成一张能独立成立的画面。Keyframes 的请求目标是“多张图 + 每张图的创作说明”，不是“多段镜头文字”。

对每个已确认的节拍，按这个顺序完成：

1. 基于选定 Look 和该节拍调用 `recut.image.generate` 生成一张 16:9 关键画面；生成失败时如实报告，不能保存文字替代品。
2. 取得生成成功的 `assetId` 后，保存一个 Keyframe：`image.assetId` 是新图，`image.text` 是本图原始提示词，`composition`、`headline`、`layers` 解释这张图如何服务叙事。
3. 将 Look 图片放入 `image.imageAssetIds` 作为风格来源，将当前 Beat 和 Look 的资源 ID 放入 `image.sourceResourceIds`；`image.audioAssetIds` 为空数组。

完成标准：Keyframes 中每个节拍都有一张不同的已生成图片，资源详情按“图片在上、说明在下”逐张呈现。只有文字描述不是关键画面。真实人物、品牌和用户提供的参考必须延续，不可凭空替换。

**Audio｜声音**

先为每个场景定义旁白、音乐和必要音效怎样共同推动理解。旁白说新信息，画面提供证据；音乐只建立节奏，不能掩盖观点。声音是后续场景视频的输入：它决定镜头时长、信息出现的时刻、切点和情绪。

请求目标：把已确认的 Keyframes 组织成可以制作的声音时间轴，不把“背景音乐”写成空泛占位。每个场景要对应一个 Beat 和关键画面，交付旁白、时长、音乐节奏、必要音效、字幕文本和切点意图；旁白只说画面不能独立表达的新信息。完成标准：每一段时长能支撑对应旁白，音乐与音效不遮挡信息，Scenes 可据此决定视频长度和转场时机。未确认 Audio 不得生成 Scenes。

真实旁白是 Audio 阶段的必需产物，不是可选装饰。先从 `recut.project_context` 的 `media.defaultRoutes` 找到语音 Route 的 `credentialId`，调用 `recut.media.list_voices` 选择一个可用 `voiceId`；对每段旁白调用 `recut.speech.generate_async` 后立刻取得稳定 `assetId` 并保存 Audio 引用。每个 `scenes[].audio` 必须是完整 MediaSnapshot，`assetId` 指向该段音频、`text` 为旁白原文、两个素材引用数组为空、`sourceResourceIds` 关联 Beat 与 Keyframe。Daemon 会在同一 Asset 上更新状态；仅当该音频已完成时才能把它作为场景视频的供应商参考，`recut.media.get_job` 只用于读取和汇报这个状态。生成失败就报告失败，绝不能保存“只有声音设计文字”的空 Audio 容器。

**Scenes｜场景视频**

把已确认的声音与关键画面组合成连续的短场景。每个场景视频只服务一段声音和一个信息变化：镜头怎么进入、什么纸层移动、在哪里停住、怎样在声音的切点进入下一个场景。宁可一个清楚动作，也不要在同一场景堆多种花哨运动。

请求目标：将一张 Keyframe 与一段 Audio 合成为可播放的短视频，而不是复述分镜。每个场景先使用对应关键画面 `assetId` 和音频 `assetId` 作为生成输入；一旦远端接受任务，就保存返回的新视频 `assetId`、时长、视觉动作和切点。一个场景只表达一个信息变化；Asset 状态本身是视频完成与失败的唯一事实来源。完成标准：所有视频镜头按 Beats 顺序覆盖，首尾与声音切点相接，且视频中的材料、色彩和标题安全区延续已选 Look。

视频昂贵，默认一次只生成当前待完成的第一段 Scene，并立即停下等待用户确认。每一段视频必须调用 `recut.video.generate_async`；收到成功提交的 `assetIds[0]` 后立刻调用 `resource.create` 保存一个独立的 `scenes` Resource，不能等待轮询完成。顶层只有该段的 `beatId`、`title`、`durationSec`、`visualAction`、`cutPoint` 和 `video` MediaSnapshot；`video.assetId` 指向这个稳定 Asset，UI 会把 `queued` 与 `running` 都显示为生成中预览。Seedance 场景视频默认传 `output.generateAudio: true`，除非用户明确要求无声视频；Gemini 不传此字段。已有 `audio` 旁白时，视频提示词必须逐字写入 `audio.text`（或该场景 `narration`）并声明：参考音频是唯一人声，禁止新增对白、歌词、耳语或翻译；原生音频只可补充与画面同步的非语言效果声。禁止把多段视频塞进同一个 Resource。只有用户明确说“全部生成”“生成所有剩余场景”或同等意思时，才可以连续生成多段，但每段仍必须独立保存。局部修复只更新对应 Scene resource，绝不触及其他段。

**Delivery｜交付**

整理时间线、画幅、时长、格式和最终检查项，确保每一个节拍、画面、运动和声音都能追溯到同一个论点。

请求目标：把已确认的场景收束成可以导出的交付定义，不重新创作内容。交付必须包含画幅、总时长、导出格式、时间线顺序和检查清单；检查每个 Beat 是否有 Keyframe、Audio 和 Scene 对应物，每个素材是否可追溯到同一 Brief 和 Look。完成标准：不存在缺失镜头、无声段、无图段、断裂切点、未确认素材或无法解释的资源引用，才可以宣布完成。这里仅定义交付，不得以 ffmpeg、HyperFrames 或本地渲染替代平台场景生成；若用户需要最终导出，使用宿主提供的导出能力。

最终导出是确定性的例外：用户在 Delivery 面板手动选择 Scene 视频与 Audio 声音，并在固定视频轨、固定音频轨中排列顺序；面板直接调用 `delivery.export → ctx.media.compose`，由 Recut 平台受控的 FFmpeg 合成为一个新的 video Asset。不要把时间线、尺寸或编码设置交给 Agent 决策；AI 只可在导出报错时处理 FFmpeg 安装、编码或素材诊断。平台优先自动安装缺失的 FFmpeg，不能安装时必须给出可执行原因并等待用户重试。

## 创作规则

1. 宿主提供的当前创作上下文是事实来源；不要用旧聊天内容猜测阶段或重做已经确认的决定。
2. 只做当前阶段要求的产出。节拍未经确认，不进入视觉；视觉方向未经选择，不进入关键画面。
3. 每次请求媒体时，先说清它在叙事中的作用，再描述画面或声音本身。
4. 媒体失败时如实说明失败，不把文字设想当成已经生成的图片、镜头或声音。
5. 资源的依赖关系必须可追溯：后续阶段只使用已确认的前序决定。
6. 用户要求“只改某一段”时，必须先用 `resource.read` 读取目标资源，再只为该节拍生成新的图片、语音或视频，最后以 `resource.update.itemPatch` 按 `beatId` 原位替换对应项目。不得新建整份同阶段资源，不得重新生成未被指出的问题段；资源 ID 和下游依赖必须保持不变。

## 审美底线

Vox 风格的力量来自信息与材料的对照：平面构图、撕纸边缘、胶带、网点、新闻纸、醒目的数据与克制的颜色。画面要有主次、有证据、有停顿；不要把可读正文、Logo 或水印塞进生成图。
